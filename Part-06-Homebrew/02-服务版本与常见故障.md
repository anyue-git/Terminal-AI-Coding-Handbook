# 02 服务、版本与常见故障

Homebrew 还会影响后台服务、多版本软件和项目运行环境。最常见的问题不是“没装上”，而是服务重复、PATH 指向错误版本，或者升级后项目突然不兼容。

---

## 1. Formula、Cask 与 Service

```text
Formula
→ 命令行工具和库

Cask
→ 图形应用和大型软件包

Service
→ 需要长期在后台运行的程序
```

查看：

```bash
brew info PACKAGE
brew list --formula
brew list --cask
```

Finder 中有没有图标，不能判断命令行工具或后台服务是否正常。

---

## 2. `brew services` 管理什么

查看服务：

```bash
brew services list
```

常见操作：

```bash
brew services start SERVICE
brew services stop SERVICE
brew services restart SERVICE
```

服务模式通常会通过 macOS `launchd` 注册后台任务，并可能在登录后自动启动。

它适合本地数据库、Redis 或需要持续监听端口的组件，不适合临时脚本和 GPU 训练。

---

## 3. 服务启动前先问是否真的需要常驻

适合长期服务：

- 本地数据库；
- 缓存服务；
- 明确需要持续监听的开发组件。

不适合：

- 临时开发服务器；
- 一次性脚本；
- 偶尔使用的项目工具；
- 机器学习训练任务。

临时服务可以在项目终端中运行；远程长任务使用 tmux、systemd 或调度器。

---

## 4. 服务故障按状态、日志、端口排查

```bash
brew services list
brew info SERVICE
lsof -nP -iTCP -sTCP:LISTEN
```

检查指定端口：

```bash
lsof -nP -iTCP:PORT -sTCP:LISTEN
```

服务显示 started 但端口没有监听，通常说明程序启动后立即失败。继续检查：

- 服务日志；
- 配置语法；
- 数据目录权限；
- 端口冲突；
- 是否已有手工启动实例；
- 升级后是否需要迁移数据。

不要先删除数据目录，也不要只反复 restart。

---

## 5. 用户级服务与管理员级服务

普通：

```bash
brew services start SERVICE
```

通常以当前用户运行。

不要因为启动失败就改用 sudo。管理员级运行可能造成：

- root 所有的数据文件；
- 普通用户无法更新；
- 同一服务启动两份；
- 端口冲突；
- 卸载后仍有残留任务。

先看日志和文件所有权，再判断是否真的需要系统级服务。

---

## 6. 全量升级可能改变项目基础环境

```bash
brew outdated
brew update
brew upgrade
```

全量升级可能改变：

- Python 和 Node 版本；
- 数据库主版本；
- 动态库路径；
- 编译工具链；
- AI CLI 的运行依赖。

重要项目期间推荐：

```text
先看 outdated
→ 识别相关软件
→ 阅读主版本变化
→ 单个升级
→ 运行项目测试
→ 再继续
```

Homebrew 更新成功，不代表项目一定兼容。

---

## 7. 多版本与 `keg-only`

Homebrew 可能同时提供：

```text
python@3.x
node@xx
postgresql@xx
```

`keg-only` 表示某个 Formula 不会默认链接到通用 bin 目录，以避免覆盖系统或其他版本。

查看：

```bash
brew info FORMULA
type -a COMMAND
printf '%s\n' "$PATH" | tr ':' '\n'
```

不要因为命令找不到就随意创建全局软链接。项目可通过虚拟环境、版本管理器或明确路径选择版本时，通常比频繁改变全局链接更稳。

---

## 8. `brew link`、`unlink` 和 `pin`

```bash
brew unlink FORMULA
brew link FORMULA
```

它们会改变通用命令名指向哪个版本。执行前检查：

```bash
brew info FORMULA
type -a COMMAND
```

短期阻止升级：

```bash
brew pin FORMULA
brew list --pinned
brew unpin FORMULA
```

Pin 只是短期稳定措施，不是项目环境复现方案。项目仍要记录运行时版本、依赖文件和测试结果。

---

## 9. 卸载前检查依赖关系

```bash
brew uses --installed FORMULA
brew deps FORMULA
```

然后再考虑：

```bash
brew uninstall FORMULA
```

清理前预览：

```bash
brew cleanup -n
```

不要手工删除 Cellar 中的随机目录。

---

## 10. 命令安装了但找不到

```bash
brew list FORMULA
brew info FORMULA
brew --prefix
type -a COMMAND
command -v COMMAND
printf '%s\n' "$PATH" | tr ':' '\n'
```

Apple Silicon 还要检查是否混入 `/usr/local` 下的 Intel/Rosetta Homebrew。

```bash
uname -m
type -a brew
file "$(command -v COMMAND)"
```

同一命令在不同终端表现不同，通常与架构、PATH 或 Shell 配置加载方式有关。

---

## 11. AI CLI 的 Homebrew 排错约束

```text
先只读检查 brew 前缀、PATH、命令来源、已安装版本和服务状态。
不要执行全量 upgrade、cleanup、link、unlink、卸载或服务重启。
说明最小修改方案、影响范围、验证方式和回滚步骤。
不要使用 sudo brew，也不要递归修改 Homebrew 目录权限。
```

审批前要求 Agent 回答：

1. 当前 Homebrew 前缀是什么；
2. 当前命令实际来自哪里；
3. 是否有多个版本或架构；
4. 服务是否真的需要自启动；
5. 升级是否跨主版本；
6. 是否涉及数据目录和迁移。

---

## 12. 固定排错清单

```bash
brew --version
brew --prefix
brew doctor
brew outdated
brew services list
type -a brew python3 node
uname -m
```

遇到服务问题再加：

```bash
brew info SERVICE
lsof -nP -iTCP -sTCP:LISTEN
```
