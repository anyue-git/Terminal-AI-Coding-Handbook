# 05 文件系统、目录与路径

终端中的文件操作依赖路径。Finder 通过窗口和图标告诉你当前打开了哪个文件夹，Shell 则维护一个“当前工作目录”。运行 `python3 app.py`、`git status`、`claude` 或 `codex` 时，程序通常从当前目录开始寻找文件和项目配置，因此路径不是命令旁边的次要信息，而是决定操作实际落在哪里的边界。

先运行：

```bash
pwd
```

若输出 `/Users/NAME/Projects/demo`，这就是当前工作目录，后续相对路径、隐藏配置、Git 仓库和 AI CLI 启动范围都从这里解释。

## 1. 用一棵小文件树理解路径

建立练习目录：

```bash
mkdir -p ~/terminal-practice/paths-demo/src
mkdir -p ~/terminal-practice/paths-demo/docs
cd ~/terminal-practice/paths-demo
touch README.md src/app.py docs/notes.md
find . -print
```

结果可能是：

```text
.
./README.md
./docs
./docs/notes.md
./src
./src/app.py
```

可以把目录理解成一棵树：`paths-demo` 是这一段树的起点，下面有两个目录和一个文件；`src/app.py` 表示先进入 `src`，再找到 `app.py`。系统中可以同时存在多个 `README.md`，文件名不能唯一确定位置，完整路径才可以。

几个常用符号是：

```text
/     文件系统根目录
~     当前用户主目录
.     当前目录
..    上一级目录
-     在 cd 中表示上一次所在目录
```

在练习目录中可以依次运行 `cd src`、`cd ..`、`cd ~` 和 `cd -`，并在每次切换后用 `pwd` 观察变化。`.` 常用于明确“从当前目录开始”，例如 `find . -print`。

## 2. 绝对路径与相对路径解决不同问题

绝对路径从文件系统根目录 `/` 开始，例如：

```text
/Users/NAME/terminal-practice/paths-demo/src/app.py
```

无论当前位于哪里，它都指向同一位置。Mac 用户主目录通常在 `/Users/NAME`，Ubuntu 用户通常在 `/home/NAME`，所以一台机器上的绝对路径不应直接写死到另一台机器；跨设备项目更适合使用 `$HOME`、项目相对路径或本地配置。

相对路径从当前目录计算。站在 `paths-demo` 根目录时，`src/app.py` 指向源码文件；进入 `docs` 后，原来的写法就不再正确，需要使用 `../src/app.py`。相对路径较短，也更适合项目内部，但依赖上下文。复制命令前先看 `pwd`，能避免大量“文件明明存在却找不到”的问题。

根目录 `/` 和主目录 `~` 也不能混淆。`/` 是整个文件系统的起点，下面包含系统目录、用户目录、设备和挂载点；`~` 只是当前用户的私人目录。个人项目通常放在 `~/Projects`、`~/Code` 或 `~/Developer`，不应直接放进 `/System`、`/bin`、`/usr` 或 `/etc` 等系统位置。

## 3. 项目根目录和隐藏文件决定工具看到什么

一个项目根目录常包含 `.git/`、`README.md`、`pyproject.toml`、`package.json` 或 `Dockerfile`。在目录中运行：

```bash
pwd
ls -la
git status
git rev-parse --show-toplevel
```

如果 `git status` 正常显示分支和工作区，通常说明当前位于 Git 仓库内部；`git rev-parse --show-toplevel` 会给出仓库根目录。启动 AI CLI 前进入项目根目录通常更稳妥，因为 README、项目规则、测试配置和 Git 状态都在同一范围内。从主目录或多个仓库的父目录启动 Agent，会扩大可见范围，也容易在错误位置创建文件。

名称以 `.` 开头的隐藏对象不会出现在普通 `ls` 中，但可能非常重要，例如 `.git`、`.env`、`.zshrc`、`.gitignore`、`.claude` 和 `.codex`。使用 `ls -la` 查看它们。隐藏文件可能保存 Git 历史、工具设置和凭证，不能因为 Finder 默认不显示就随手上传。检查 `.env` 是否被 Git 跟踪可以运行：

```bash
git status --short -- .env
```

没有输出也不能单独证明安全，还要检查 `.gitignore` 和历史提交。涉及凭证时不要为了排错直接打印文件正文。

## 4. 空格、大小写和符号链接会改变路径解释

路径含空格时需要引号：

```bash
mkdir "My Project"
cd "My Project"
```

zsh 的 Tab 补全可能显示 `My\ Project/`，反斜杠表示空格属于文件名。变量保存路径时也要加双引号：

```bash
TARGET_DIR="$HOME/terminal-practice/paths-demo/My Project"
printf '%s\n' "$TARGET_DIR"
ls -la "$TARGET_DIR"
```

Linux 文件系统通常严格区分 `File.py` 和 `file.py`；许多 Mac 默认文件系统保留大小写但查找时不严格区分，因此项目可能在 Mac 正常、到 Ubuntu 或 CI 才出现导入错误。跨平台项目应统一文件名和代码引用的大小写，完成只改大小写的重命名后使用 `git status` 确认真实记录。

普通文件、目录和符号链接也不是同一种对象。检查类型可以运行：

```bash
ls -ld README.md src
file README.md src
```

创建符号链接：

```bash
ln -s src/app.py app-link.py
ls -l app-link.py
```

链接只是指向另一个路径的引用，删除链接本身通常不会删除目标文件，但复制、同步和 Docker 挂载对链接的处理可能不同。看到一个路径时，不能只凭名称判断它是实际文件还是链接。

## 5. 路径错误应先检查事实，不要加权限掩盖

`No such file or directory` 常见于当前目录错误、路径拼写或大小写不一致、中间目录不存在、空格未加引号，或目标位于另一台机器。`Not a directory` 则说明路径中的某一段可能是普通文件。遇到这类错误先运行：

```bash
pwd
ls -la
ls -ld TARGET
file TARGET
```

管理员权限不能修复拼写和目录层级。看到报错就加 `sudo`，可能把原本无害的路径错误变成系统级写入。

脚本和长命令常把目标保存在变量中。写操作前应把变量用明显边界打印出来：

```bash
TARGET_DIR="$HOME/terminal-practice/paths-demo"
printf 'TARGET_DIR=<%s>\n' "$TARGET_DIR"
ls -ld "$TARGET_DIR"
```

尖括号有助于发现空值或多余空格。如果变量为空、路径与预期不符或目标位于项目外，应立即停止。删除、同步、移动、改权限和 Bind Mount 等高影响操作，还要同时确认 `hostname`、`pwd`、目标内容与恢复能力。

## 6. 一套稳定的路径检查习惯

进入重要目录后运行：

```bash
hostname
pwd
ls -la
git status
```

`git status` 只适用于 Git 项目；显示“不是 Git 仓库”时，先检查目录，不要立刻重新初始化。SSH 登录、启动 AI CLI、删除或覆盖文件、同步 Mac 与 Ubuntu、使用 Docker Bind Mount、开始训练和写 checkpoint 前，都值得重新确认路径。
