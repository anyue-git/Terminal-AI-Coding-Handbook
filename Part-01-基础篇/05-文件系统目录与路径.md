# 05 文件系统、目录与路径

终端中的文件操作依赖路径。Finder 会通过窗口和图标告诉你当前打开了哪个文件夹，Shell 则维护一个“当前工作目录”。当你运行 `python3 app.py`、`git status`、`claude` 或 `codex` 时，程序通常会从当前目录开始寻找文件和项目配置。

先运行：

```bash
pwd
```

输出可能是：

```text
/Users/NAME/Projects/demo
```

这条路径就是当前工作目录。后面的相对路径、隐藏配置、Git 仓库和 AI CLI 启动范围，都与它有关。

## 1. 用一个小目录理解文件树

建立练习目录：

```bash
mkdir -p ~/terminal-practice/paths-demo/src
mkdir -p ~/terminal-practice/paths-demo/docs
cd ~/terminal-practice/paths-demo
touch README.md src/app.py docs/notes.md
find . -print
```

可能看到：

```text
.
./README.md
./docs
./docs/notes.md
./src
./src/app.py
```

可以把目录理解成一棵树。`paths-demo` 是这一小段树的起点，下面有两个目录和一个文件；`src/app.py` 表示先进入 `src`，再找到 `app.py`。

文件名本身不能唯一确定位置。系统中可以同时存在多个 `README.md`，真正区分它们的是完整路径。

## 2. 绝对路径不依赖当前目录

绝对路径从文件系统根目录 `/` 开始。例如：

```text
/Users/NAME/terminal-practice/paths-demo/src/app.py
```

无论当前位于哪里，这个路径都指向同一位置。查看一个文件的绝对路径，可以先进入其目录再运行：

```bash
cd ~/terminal-practice/paths-demo/src
pwd
```

Mac 用户的主目录通常位于：

```text
/Users/NAME
```

Ubuntu 用户的主目录通常位于：

```text
/home/NAME
```

因此，不要把一台机器上的绝对路径直接写死到另一台机器。跨设备项目更适合使用 `$HOME`、项目相对路径或本地配置文件。

## 3. 相对路径从当前目录开始计算

回到练习项目根目录：

```bash
cd ~/terminal-practice/paths-demo
pwd
```

此时：

```text
src/app.py
```

表示当前目录下的 `src/app.py`。完整位置是：

```text
/Users/NAME/terminal-practice/paths-demo/src/app.py
```

如果进入 `docs`：

```bash
cd docs
```

原来的 `src/app.py` 就不再指向正确位置，因为当前目录已经变化。可以使用：

```text
../src/app.py
```

其中 `..` 表示上一级目录。

相对路径更短，也更适合项目内部使用，但它依赖当前上下文。复制命令前先看 `pwd`，能避免很多“文件明明存在却找不到”的问题。

## 4. 几个常用路径符号

```text
/     文件系统根目录
~     当前用户主目录
.     当前目录
..    上一级目录
-     在 cd 中表示上一次所在目录
```

在练习目录中可以依次尝试：

```bash
pwd
cd src
pwd
cd ..
pwd
cd ~
pwd
cd -
pwd
```

`cd -` 会切换到上一次所在目录，并通常把新目录打印出来。它适合在两个目录之间来回工作，但不要把它当成跨很久历史的目录浏览器。

`.` 常用于明确表示“从当前目录开始”。例如：

```bash
find . -print
```

这里的 `.` 告诉 `find` 从当前目录搜索。

## 5. 根目录 `/` 和主目录 `~` 不是一回事

`/` 是整个文件系统的起点，下面包含系统目录、用户目录、设备和挂载点。`~` 只是当前用户的主目录。

运行：

```bash
printf 'root=%s\nhome=%s\n' / "$HOME"
```

可能看到：

```text
root=/
home=/Users/NAME
```

普通项目通常放在主目录下，例如：

```text
~/Projects
~/Code
~/Developer
```

不要把个人项目直接放进 `/System`、`/bin`、`/usr` 或 `/etc`。这些位置属于操作系统或全局软件环境，通常需要更高权限，也更容易影响系统行为。

## 6. 怎样判断项目根目录

一个项目根目录经常包含下面的一部分文件：

```text
.git/
README.md
pyproject.toml
package.json
Dockerfile
```

在目录中检查：

```bash
pwd
ls -la
git status
```

如果 `git status` 正常显示分支和文件状态，通常说明当前位于 Git 仓库内部。查看仓库根目录：

```bash
git rev-parse --show-toplevel
```

输出可能是：

```text
/Users/NAME/Projects/demo
```

在启动 AI CLI 前进入项目根目录通常最稳妥，因为 README、项目规则、测试配置和 Git 状态都在同一范围内。从主目录或多个仓库的父目录启动 Agent，会扩大它能读取的内容，也容易在错误位置创建文件。

## 7. 隐藏文件不是“可以忽略的文件”

名称以 `.` 开头的文件或目录通常不会出现在普通 `ls` 输出中，例如：

```text
.git
.env
.zshrc
.gitignore
.claude
.codex
```

查看它们：

```bash
ls -la
```

隐藏文件可能保存 Git 历史、Shell 配置、工具设置和凭证。`.env`、认证缓存和本地配置尤其不能因为“看不到”就随手上传仓库。

查看某个隐藏文件是否被 Git 跟踪：

```bash
git status --short -- .env
```

没有输出并不自动证明它安全；还要检查 `.gitignore` 和历史提交。涉及凭证时，不要直接打印文件正文来排错。

## 8. 空格、引号和 Tab 补全

建立一个含空格的目录：

```bash
cd ~/terminal-practice/paths-demo
mkdir "My Project"
```

进入时需要引号：

```bash
cd "My Project"
```

也可以输入前几个字符后按 Tab，让 zsh 自动补全。补全结果可能使用反斜杠：

```text
cd My\ Project/
```

反斜杠用于告诉 Shell 空格属于文件名，不是两个参数之间的分隔符。

变量中保存路径时，也应使用双引号：

```bash
TARGET_DIR="$HOME/terminal-practice/paths-demo/My Project"
printf '%s\n' "$TARGET_DIR"
ls -la "$TARGET_DIR"
```

没有引号时，Shell 可能把路径拆成多个参数。

## 9. Mac 和 Linux 对大小写的处理可能不同

Linux 文件系统通常严格区分：

```text
File.py
file.py
```

它们是两个不同文件。很多 Mac 默认文件系统保留大小写，但查找时不严格区分，因此项目在 Mac 上可能正常，在 Ubuntu 或 CI 中才出现导入错误。

跨平台项目应统一文件名和代码中的大小写。例如文件实际名为 `Parser.py`，代码中不要写成：

```python
from parser import parse
```

Git 在大小写不敏感的文件系统上处理“只改字母大小写”的重命名时也可能需要额外确认。完成后使用 `git status` 检查真实记录。

## 10. 文件、目录和符号链接不是同一种对象

查看对象类型：

```bash
ls -ld README.md src
file README.md src
```

输出会区分普通文件和目录。符号链接则是指向另一个路径的引用，例如：

```bash
ln -s src/app.py app-link.py
ls -l app-link.py
```

可能看到：

```text
app-link.py -> src/app.py
```

修改链接目标会影响通过链接访问到的内容；删除链接本身通常不会删除目标文件。复制、同步和 Docker 挂载对符号链接的处理可能不同，看到路径时不能只凭名称判断对象类型。

## 11. 路径变量为空时风险很大

假设脚本使用变量保存目标目录：

```bash
TARGET_DIR="$HOME/terminal-practice/paths-demo"
```

执行写操作前先打印：

```bash
printf 'TARGET_DIR=<%s>\n' "$TARGET_DIR"
ls -ld "$TARGET_DIR"
```

尖括号有助于看出空值或多余空格。如果变量为空、路径与预期不符或目标位于项目外，应停止操作。

对于删除、同步、移动、改权限和 Bind Mount，至少先确认：

```bash
hostname
pwd
ls -ld TARGET
```

命令中有变量时，再单独打印变量。不要把递归强制删除形式当作通用模板；目标路径、匹配范围和恢复方式没有独立验证前，不应执行。

## 12. 一套稳定的路径检查习惯

进入重要目录后运行：

```bash
hostname
pwd
ls -la
git status
```

其中 `git status` 只适用于 Git 项目。遇到“不是 Git 仓库”的提示时，先检查目录，不要马上重新初始化 Git。

以下场景尤其应重新确认路径：

- SSH 登录远程机器后；
- 启动 AI CLI 前；
- 删除、覆盖或批量移动文件前；
- 运行安装脚本或修改系统配置前；
- 同步 Mac 与 Ubuntu 项目前；
- 使用 Docker Bind Mount 前；
- 启动训练和写入 checkpoint 前。

路径不是命令旁边的次要细节。它决定命令实际作用于哪里，也是本地、远程、容器和 AI Agent 之间最基本的边界。
