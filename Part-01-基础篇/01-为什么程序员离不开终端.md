# 01 为什么程序员离不开终端

很多人第一次看到终端，会觉得它只是把鼠标点击换成键盘输入。用上一段时间后，差别会逐渐显现：操作可以被准确写下来、重复执行、组合成流程，并留下可检查的记录。图形界面很适合浏览文件、调整少量设置和完成一次性的可视化操作；终端更擅长处理项目、远程机器、日志、批量文件和自动化任务。它们各有合适的场景。理解底层命令以后，再使用 VS Code、Docker Desktop 或 Git 客户端，也更容易判断界面背后发生了什么。

## 1. 开发工具最终都要处理明确的目录、文件和进程

Git、SSH、Python、Node.js、Docker、ffmpeg、Claude Code 和 Codex CLI 都可以直接在终端中运行。图形工具通常是在这些能力之上增加按钮、菜单和状态显示；遇到认证、路径、权限或环境问题时，终端输出往往提供更直接的线索。

例如，在一个 Git 项目中运行：

```bash
pwd
git status
git diff --stat
```

你可能看到当前项目路径、所在分支、哪些文件有变化以及改动规模。相比只看到一个“有未提交更改”的图标，这些文字更容易复制到问题记录中，也能让远程协作者复现同一组检查。命令还可以写进 README、脚本和 CI；某次测试失败时，保存“在哪个目录执行了什么命令、输出和退出状态是什么”，比只写“我点了运行但失败了”更容易继续调查。

## 2. 小工具可以组成可复现的流程

许多 Unix 工具只负责一类工作：`find` 查找文件，`grep` 或 `rg` 筛选文字，`sort` 排序，`wc` 统计数量。它们可以通过管道连接，让前一个命令的输出成为后一个命令的输入。例如，在练习目录中统计 Markdown 文件数量：

```bash
find . -type f -name '*.md' | wc -l
```

这里没有额外安装一个“Markdown 计数软件”，只是把文件搜索和行数统计接在一起。查找包含 `TODO` 的 Python 文件则可以使用：

```bash
rg -l 'TODO' --glob '*.py'
```

组合能力很强，也会放大错误。初学阶段不必急着写一条复杂命令。可以逐步运行每一段，观察中间输出，再决定是否连接。准备批量重命名、同步或让 Agent 修改多个文件时，也先生成候选清单或使用 dry run，避免把搜索结果直接送进写操作。

## 3. 远程机器让终端成为基本工作界面

服务器和 GPU 工作站经常没有你熟悉的桌面环境。通过 SSH 登录后，主要交互方式就是终端：

```bash
ssh USER@SERVER_IP
```

登录成功后应先运行：

```bash
hostname
whoami
pwd
```

窗口仍然显示在 Mac 上，但命令已经在远程 Linux 执行；安装软件、修改文件和启动训练，影响的都是远程机器。终端让本地与远程共享一套基本操作，同时也要求你始终知道当前连接到了哪里。看到 `/home/NAME`、远程主机名或不同用户时，不要凭窗口外观继续操作。

长时间任务还需要考虑会话断开。普通后台运行不一定能抵抗关闭窗口或 SSH 中断，可靠方案通常还包括 tmux、日志、checkpoint 和可重复的启动参数。终端提供控制入口，却不会自动保证任务一直存活。

## 4. AI 编程提高速度，也提高了范围判断的重要性

AI 可以生成命令、修改代码和运行测试，但执行结果仍由当前机器、目录、权限和数据状态决定。Agent 收到“清理项目”后，可能建议删除构建产物；这个建议是否安全，取决于匹配范围、文件能否恢复、当前是否位于正确仓库，以及命令有没有越过项目边界。

使用 AI CLI 时，至少要能回答：当前是哪台机器和哪个目录，Agent 能读取与修改哪些文件，命令会不会访问网络、凭证或系统服务，修改后怎样查看真实 diff，测试在哪里运行，以及方向错误时怎样停止。例如 Agent 准备处理日志时，可以先列出对象：

```bash
find . -type f -name '*.log' -print
```

确认数量、路径和用途后，再决定哪些文件可以移动、归档或删除。AI 提高了操作速度，因此更需要在执行前看清范围，不能把审批简化成“模型觉得没问题”。

## 5. 自动化可靠的前提是可观察和可恢复

手工改错一个文件和脚本一次改错一千个文件，可能只差一个循环或通配符。可靠流程通常包括确认环境、预览目标、执行尽可能小的操作、检查输出和文件变化，并保留恢复手段。Git、备份、测试、dry run、日志和 checkpoint 共同构成这套保护；有了它们，自动化才适合扩大规模。

终端还会把很多问题直接暴露出来。运行：

```bash
cd does-not-exist
```

会看到类似：

```text
cd: no such file or directory: does-not-exist
```

这说明路径无法解析，不代表电脑损坏。`command not found` 通常指向命令名称、安装位置或 PATH；`permission denied` 则提示当前用户没有所需权限，或文件缺少执行权限。学习终端的重要部分不是避免所有报错，而是根据报错判断应检查哪一层。不断重装软件、重复执行或直接加 `sudo`，往往会把原本清楚的问题变得更复杂。

## 6. 第一阶段只需要形成几项习惯

刚开始不必背几十条命令。可以从下面几条开始：

```bash
hostname
pwd
ls -la
git status
```

它们分别帮助确认机器、目录、文件和项目状态。还要记住 `Ctrl + C` 可以取消当前输入或中断多数前台程序。长命令输错时，停下来修改比勉强执行更稳妥。每次操作多问一句：“这条命令会在哪个位置处理哪些对象？”随着使用次数增加，命令自然会记住。
