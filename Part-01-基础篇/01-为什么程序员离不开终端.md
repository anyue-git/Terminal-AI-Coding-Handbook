# 01 为什么程序员离不开终端

终端不是为了显得专业，也不是把“点击”换成“打字”。它真正的价值在于：操作可以精确描述、组合、重复、记录和自动化。

图形界面适合少量、可见、一次性的操作；终端更适合项目管理、日志分析、远程连接、批量处理和开发自动化。

---

## 1. 许多开发工具原本就运行在终端里

常见工具包括：

- Git；
- SSH；
- Python；
- Node.js；
- Docker；
- ffmpeg；
- Claude Code；
- Codex CLI；
- Grok CLI；
- 训练与推理脚本。

VS Code 中的提交按钮仍然在调用 Git；Remote SSH 插件仍然依赖 SSH。理解底层命令后，图形界面不再是黑箱。

---

## 2. 终端最大的优势是可组合

Unix 工具通常只完成一类任务：

```text
ls      列出文件
grep    筛选文本
sort    排序
head    取开头
wc      统计
```

它们可以通过管道连接：

```bash
ls -1 | grep '\.md$' | sort | head
```

这不是一个庞大的专用功能，而是几个小工具组成的处理链。相同命令可以保存进脚本、写入文档或交给团队复用。

---

## 3. AI 时代反而更需要理解终端

AI 可以生成命令，但不会替你承担后果。

例如：

```bash
rm -rf build
```

你至少需要知道：

- `rm` 删除文件；
- `-r` 递归处理目录；
- `-f` 减少确认与报错；
- `build` 是相对路径；
- 它最终指向哪里取决于当前目录。

命令本身可能正确，但在错误目录执行仍然会造成损失。

使用 AI CLI 时需要保留四种判断：

```text
当前上下文是什么
作用范围有多大
结果是否可恢复
怎样停止和验证
```

---

## 4. 先观察，再行动

最基础的观察命令：

```bash
hostname
pwd
ls -la
```

它们分别回答：

- 当前是哪台机器；
- 当前在哪个目录；
- 当前目录有哪些文件，包括隐藏文件。

进入 Git 项目后再看：

```bash
git status
```

批量操作前先预览匹配对象。例如不要直接删除日志：

```bash
rm *.log
```

先查看：

```bash
ls -l *.log
```

确认后再决定如何处理。

---

## 5. 自动化会放大正确，也会放大错误

手动改错一个文件和一次改错一万个文件，可能只差一个通配符、循环或递归选项。

所以终端操作需要形成以下顺序：

```text
检查目录
→ 预览范围
→ 执行最小操作
→ 验证结果
→ 保留恢复空间
```

Git、备份、dry run 和测试都属于恢复空间的一部分。

---

## 6. 每个运行中的程序都要知道怎样停止

最常见的中断方式：

```text
Ctrl + C
```

它通常向当前前台程序发送中断信号。训练脚本、开发服务器、`ping` 和 AI CLI 都会遇到它。

`Ctrl + Z` 通常只是暂停程序，不是结束。详见 [进程、前台、后台与任务控制](../Part-02-终端命令/06-进程前台后台与任务控制.md)。

---

## 7. 第一阶段不需要记住很多命令

先形成这些习惯：

- 操作前运行 `pwd`；
- 远程登录后运行 `hostname`；
- 路径和变量不确定时先打印；
- 批量处理前先预览；
- 看不懂的命令不直接运行；
- 修改项目后查看 Git diff；
- 长任务知道日志在哪里、怎样停止；
- 重要数据有备份或 checkpoint。

终端更像一种操作计算机的语言，不需要“学完”才开始使用。
