# 02 Terminal 到底是什么

Terminal 是承载文字交互的界面，不是命令解释器本身。

它主要负责：

- 显示文字；
- 接收键盘输入；
- 把输入交给 Shell 或其他命令行程序；
- 把程序输出显示出来。

可以把关系理解成：

```text
你
→ Terminal 窗口
→ Shell，例如 zsh
→ 命令和程序
→ 操作系统
```

---

## 1. 为什么很多界面都“像终端”

你可能见过：

- macOS Terminal；
- iTerm2；
- VS Code 集成终端；
- Warp；
- JetBrains Terminal；
- SSH 登录后的远程命令行。

它们的外观和快捷键可能不同，但里面运行的 Shell 可以相同。

同一条 `cd` 或 `git status` 在不同终端中通常都能运行；真正导致行为差异的往往是：

- 当前 Shell；
- 当前操作系统；
- 当前用户；
- PATH 和环境变量；
- 当前目录；
- 按键是否被某个程序接管。

---

## 2. 提示符在告诉你什么

打开 macOS Terminal 后，可能看到：

```text
username@MacBook ~ %
```

提示符通常包含：

- 用户名；
- 计算机名称；
- 当前目录；
- 提示符符号。

其中：

```text
~
```

表示当前用户主目录。

很多教程在命令前写 `$`：

```text
$ pwd
```

这通常只是表示“普通用户在这里输入命令”。实际只输入：

```bash
pwd
```

---

## 3. 普通 Shell 与程序接管状态

### Shell 提示符状态

```text
username@MacBook project %
```

此时输入：

```bash
ls
```

由 Shell 解释。

### 程序接管状态

启动：

```bash
claude
codex
grok
less README.md
```

之后，键盘输入会先交给当前程序。此时：

- 回车可能发送 Prompt 或确认选项；
- `Ctrl + C` 可能取消当前操作；
- `q` 可能退出分页器；
- zsh 的快捷键可能不再生效。

同一个按键在不同界面中行为不同，不一定是终端故障。

---

## 4. 回车意味着什么

在普通 Shell 中，回车通常表示：

> 把当前整行交给 Shell 解析并执行。

在 AI CLI 或交互程序中，回车可能表示：

- 发送提示词；
- 接受默认选项；
- 同意工具调用；
- 进入下一步。

不确定当前界面时，不要连续按回车。尤其在权限审批界面中，回车可能直接接受默认动作。

---

## 5. 关闭窗口后程序会怎样

直接运行：

```bash
python train.py
```

程序通常附属于当前终端会话。关闭窗口、退出 Shell 或断开 SSH 后，它可能终止。

长任务需要使用更合适的机制，例如：

- tmux；
- systemd；
- 后台容器；
- 作业调度器；
- 经过验证的 nohup 流程。

tmux 可以让终端会话在 SSH 断开后继续，但不能让任务跨越关机或系统崩溃。

---

## 6. 清屏不等于删除历史

```bash
clear
```

或：

```text
Ctrl + L
```

只会整理当前显示区域，不会：

- 删除文件；
- 清除 Shell 历史；
- 停止程序；
- 撤销已经执行的命令。

zsh 历史可能保存在：

```text
~/.zsh_history
```

曾经输入过 Token 或密码，并不会因为 `clear` 就消失。

---

## 7. 集成终端和远程终端

VS Code 集成终端仍然是终端界面。通过 Remote SSH 连接 Ubuntu 后：

```text
界面在 Mac
命令在 Ubuntu 执行
```

此时删除文件、安装软件和运行 Python，影响的是远程 Ubuntu，而不是 Mac。

远程登录后应立即确认：

```bash
hostname
whoami
pwd
```

---

## 8. 最短结论

```text
Terminal ≠ Shell ≠ 命令 ≠ 操作系统
```

遇到输入或快捷键异常时，先问：

1. 当前焦点在哪个程序；
2. 当前是哪台机器；
3. 当前运行哪个 Shell；
4. 当前目录是什么；
5. 按键是否被 AI CLI、less、Vim 或 tmux 接管。
