# 01 安装、登录与启动

> 最近核对：2026-07-28
>
> Codex CLI 更新较快。安装方式、登录入口和命令参数应同时参考本机 `codex --help` 与 OpenAI 当前官方文档。

Codex CLI 是运行在本机终端里的编程 Agent。它可以读取项目、修改文件、执行命令、运行测试和审查 Git 差异。

它和 ChatGPT 网页里的普通对话不是一回事：Codex CLI 站在你的项目目录里，能接触本机文件和工具链，所以启动位置、权限配置与 Git 状态都会直接影响结果。

---

## 1. 先确认你要安装的是终端版 Codex

OpenAI 的 Codex 可以出现在 ChatGPT、桌面应用、IDE、云端任务和终端等入口。本章讨论的是：

```bash
codex
```

它使用当前机器上的 Git、Python、Node.js、Docker 和其他命令行工具。

---

## 2. 安装前检查

```bash
git --version
uname -m
echo "$SHELL"
```

准备使用 npm 安装时，再检查：

```bash
node --version
npm --version
```

macOS 和 Linux 是本手册主要覆盖的平台。Windows 用户优先使用官方当前支持的环境，不要把 PowerShell、Git Bash 和 WSL 的教程混着照搬。

---

## 3. 选择一种安装方式

### npm

```bash
npm install -g @openai/codex
```

### Homebrew

官方当前也提供 Homebrew 路线。实际命令以 Codex 官方安装页为准。

安装后先检查，不要因为没看到图标就重复装三遍：

```bash
type -a codex
codex --version
codex --help
```

npm 权限报错时不要直接使用 `sudo npm install -g`。优先检查 Node.js 来源、npm 全局目录和 PATH。

---

## 4. 判断实际运行的是哪一份 Codex

```bash
type -a codex
which codex
codex --version
```

如果出现多个路径，可能同时存在 npm、Homebrew、旧版二进制或其他同名程序。先确认 PATH 顺序，再决定保留哪一套。

---

## 5. 登录方式

首次运行：

```bash
codex
```

按照界面选择当前支持的官方登录方式。常见路线包括使用 ChatGPT 账户，或者在适用场景中使用 API Key。具体选项取决于账户、工作区和组织策略。

不要使用：

- 浏览器 Cookie；
- 网页 Session Token；
- 共享认证目录；
- 来源不明的账号转换工具；
- 别人的 API Key。

本地终端和 CI 的认证也应分开。CI 使用组织批准的 Secret 或工作负载身份，不要复制个人电脑的登录缓存。

---

## 6. 从项目根目录启动

```bash
cd ~/Projects/my-project
pwd
git status
git branch --show-current
codex
```

不要从家目录、下载目录或多个仓库的共同父目录启动。Codex 会把当前目录当作主要工作区，目录选错后，它可能读取无关文件、漏掉项目规则或在错误位置创建内容。

如果 `git status` 已经显示修改，先弄清这些内容属于谁、属于哪个任务。

---

## 7. 第一次任务只做项目体检

```text
当前阶段只读，不要修改文件、安装依赖、访问外部服务或执行 Git 写操作。

请检查：
- 当前目录和 Git 状态；
- README 与 AGENTS.md；
- 依赖声明；
- 测试配置；
- 与任务相关的模块。

然后说明：
1. 项目入口；
2. 运行与测试方式；
3. 任务可能涉及的文件；
4. 不应修改的目录；
5. 当前未提交修改；
6. 已确认事实和仍然存在的推测。

重要结论给出文件路径。
```

如果项目地图不可靠，不要进入修改阶段。

---

## 8. `AGENTS.md` 是什么

`AGENTS.md` 用于保存稳定的项目约定，例如：

```md
# 项目规则

- Python 命令使用 `uv run`。
- 修改后运行 `uv run pytest -q`。
- 不读取或修改 `.env`、`data/` 和 `models/`。
- 不执行 `git commit` 或 `git push`。
- 新增依赖前先说明理由。
```

它适合写项目结构、测试命令、编码规范和安全边界，不适合写密码、Token 或一次性任务细节。

---

## 9. 交互模式与 `codex exec`

人在回路中的交互模式：

```bash
codex
```

非交互入口：

```bash
codex exec "只读检查当前项目"
```

`codex exec` 适合固定范围的分析、脚本和 CI。模糊重构、生产环境操作和不可逆删除不适合直接自动化。

使用前检查：

```bash
codex exec --help
```

---

## 10. 常用交互命令

进入界面后，常见命令包括：

```text
/status
/permissions
/model
/review
/init
```

它们用于查看状态、权限、模型、审查变更和初始化项目规则。具体名称可能随版本变化，以当前界面帮助为准。

---

## 11. Mac 与 Ubuntu 分别安装

两台机器应分别安装和登录。可以同步：

- Git 仓库；
- `AGENTS.md`；
- 测试；
- 依赖声明；
- 非敏感项目配置。

不要直接同步：

- Codex 可执行文件；
- 全局 npm 目录；
- 认证存储；
- 系统级配置；
- 一台机器的缓存或虚拟环境。

---

## 12. 启动前和结束后

启动前：

```bash
hostname
pwd
git status
type -a codex
codex --version
```

任务中明确：

```text
只修改列出的文件。
不要执行 git add、commit 或 push。
安装依赖、访问网络、删除文件或扩大范围前先说明。
完成后列出修改文件、测试结果、未验证内容和风险。
```

结束后：

```bash
git status --short
git diff --name-status
git diff --stat
git diff
```

---

## 13. 常见故障

### 找不到命令或版本不对

```bash
type -a codex
echo "$PATH"
codex --version
```

### 项目识别错误

```bash
pwd
git rev-parse --show-toplevel
git status
```

### 交互模式与自动化表现不同

```bash
codex --help
codex exec --help
```

两者的默认权限、输出和适用场景可能不同。
