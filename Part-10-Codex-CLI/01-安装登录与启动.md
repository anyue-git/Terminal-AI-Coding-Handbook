# 01 安装、认证与第一次启动

> 最近核对：2026-07-29
>
> Codex CLI 更新较快。安装和认证命令以本机 `codex --help`、`codex login --help` 与 OpenAI 当前官方文档为准。

Codex CLI 是在本机终端中运行的编程 Agent。它能够读取项目文件、修改代码、执行命令、运行测试、审查 Git 差异，并通过 `codex exec` 进入非交互自动化流程。

第一次使用时不要把所有问题混成“Codex 能不能用”。应分别确认：

```text
可执行文件
→ 当前终端实际运行哪一份 codex

认证方式
→ ChatGPT 登录、API Key 或组织提供的 Access Token

计费与策略
→ ChatGPT 工作区规则，或 OpenAI Platform API 规则

工作目录
→ Codex 当前能够看到和修改哪个项目
```

## 1. 本章讨论的是终端版 Codex

OpenAI 的 Codex 可以出现在 ChatGPT、桌面应用、IDE、云端任务和终端中。本章讨论的入口是：

```bash
codex
```

它使用当前机器上的 Git、Python、Node.js、Docker 和其他命令行工具。模型负责分析和规划，真正的文件读写与命令执行发生在你的电脑或远程主机上。因此，启动目录、权限配置、环境变量和现有 Git 修改都会影响结果。

## 2. 安装前先检查当前环境

在准备安装 Codex 的机器上运行：

```bash
uname -s
uname -m
git --version
echo "$SHELL"
```

本手册主要覆盖 macOS 和 Ubuntu。Windows 用户应根据当前官方支持选择原生 Windows 或 WSL，不要把 PowerShell、Git Bash 与 WSL 命令混在同一个步骤中。

准备使用 npm 路线时，再检查：

```bash
node --version
npm --version
```

Node.js 只影响 npm 安装方式，不代表 Codex 本身是一个需要你写 JavaScript 才能使用的工具。

## 3. 选择一种安装来源

### 3.1 macOS 与 Linux 独立安装器

OpenAI 当前提供独立安装器：

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

这是一条下载并直接执行远程脚本的命令。执行前应确认域名确实来自 OpenAI 官方文档；学校、团队或公司设备还应遵守组织的软件安装要求。

使用同一安装器可以更新由该路线安装的 Codex。不要再同时用 npm 或 Homebrew 覆盖同一个命令路径。

### 3.2 npm

官方也提供 npm 包：

```bash
npm install -g @openai/codex
```

如果出现全局目录权限错误，不要直接改成：

```text
sudo npm install -g ...
```

应先检查 Node.js 来源、npm 全局目录和 PATH。通过 nvm、fnm 或 Homebrew 安装的 Node.js，可能分别维护不同的全局包目录。

### 3.3 Homebrew

Codex 官方安装页也提供 Homebrew 选项。命令和 Formula/Cask 形式可能随发布方式变化，应从当前安装页复制，不要依赖旧博客中的固定命令。

选择原则不是哪一种“更高级”，而是只让一种包管理方式负责安装与升级。

## 4. 安装后确认实际运行的是哪一份

在 Mac 或 Ubuntu 本机终端运行：

```bash
type -a codex
command -v codex
codex --version
codex --help
```

正常情况下，`type -a` 最好只显示你准备保留的路径。如果同时看到 npm、Homebrew、独立安装器或旧版本路径，不要继续重复安装。先判断 PATH 顺序：

```bash
printf '%s\n' "$PATH" | tr ':' '\n'
```

还可以检查命令最终指向什么：

```bash
ls -l "$(command -v codex)"
```

版本异常通常是“运行了另一份 Codex”，不一定是更新失败。

## 5. ChatGPT 登录与 API Key 登录不是同一套用量

Codex CLI 使用 OpenAI 模型时，官方支持两类主要登录方式。

### 5.1 使用 ChatGPT 登录

运行：

```bash
codex login
```

浏览器会打开登录页面，完成后把认证状态交回 Codex。使用这条路线时，Codex 的访问能力、用量和数据策略跟随所选 ChatGPT 账户与工作区。

这意味着 ChatGPT Plus、Pro、Business、Enterprise 等计划中包含的 Codex 使用权，不会自动变成一个可任意调用的 Platform API Key。

### 5.2 使用 OpenAI Platform API Key

先在安全环境中设置变量，再通过标准输入交给登录命令：

```bash
printenv OPENAI_API_KEY | codex login --with-api-key
```

不要把真实 Key 直接写进命令参数、截图、Git 仓库或聊天记录。

API Key 登录按 OpenAI Platform 的标准 API 规则计费，并受 API 组织、项目、额度和数据设置控制。它不会消耗 ChatGPT 订阅中包含的 Codex 用量。

可以这样理解：

```text
ChatGPT 登录
→ 使用 ChatGPT 计划或工作区提供的 Codex 权益

API Key 登录
→ 使用 OpenAI Platform 账户并按 API 规则计费
```

客户端仍然叫 Codex CLI，但认证、计费和管理边界已经改变。

### 5.3 企业 Access Token

部分 ChatGPT Enterprise 环境可以由管理员允许创建 Codex Access Token，用于可信的非交互本地工作流。它不是普通 API Key，也不应由个人自行从网页登录信息中提取。

已有 Access Token 时，官方入口是：

```bash
printenv CODEX_ACCESS_TOKEN | codex login --with-access-token
```

个人用户不需要为了“更专业”主动寻找这一方式。

## 6. 查看当前认证状态

运行：

```bash
codex login status
```

退出当前认证：

```bash
codex logout
```

切换 ChatGPT 账户、工作区或 API Key 时，应先明确清理哪套状态，再重新登录。不要通过覆盖未知认证文件来碰运气。

Codex 可能把登录信息保存在操作系统凭据存储中，或者保存在：

```text
~/.codex/auth.json
```

该文件不是普通配置示例，而是敏感认证材料。不要提交、共享、截图或同步到公共云盘。详细的状态目录、Keyring 与 `CODEX_HOME` 见 Part 10C。

## 7. SSH 或无浏览器环境使用设备码登录

在 Ubuntu 游戏本、远程服务器或没有可用浏览器的终端中，可以使用当前的 beta 设备码流程：

```bash
codex login --device-auth
```

终端会显示网址与一次性代码。你可以在另一台可信设备的浏览器中完成登录。设备码同样属于临时敏感信息，不应发给别人。

官方文档还描述了复制认证缓存的回退方式，但这等于复制可用凭据。个人跨机器场景优先分别登录；组织环境应使用正式 Access Token、API Secret 或工作负载身份，不要把个人 `auth.json` 当成部署包。

## 8. Mac 与 Ubuntu 应分别安装和认证

Mac 与 Ubuntu 可以共享：

- Git 仓库；
- `AGENTS.md`；
- 测试与依赖声明；
- 不含秘密的项目配置。

不要直接同步：

- Codex 可执行文件；
- npm 全局目录；
- `auth.json`；
- 整个 `~/.codex`；
- 一台机器的 Python 虚拟环境；
- 平台相关缓存与二进制。

两台机器即使登录同一个账户，也可能使用不同工作区、配置 Profile 或权限策略。每台机器都应单独运行：

```bash
hostname
type -a codex
codex --version
codex login status
```

## 9. 从项目根目录启动

在 Mac 本地项目中：

```bash
cd ~/Projects/my-project
pwd
git rev-parse --show-toplevel
git status
codex
```

通过 SSH 登录 Ubuntu 后，则先确认远程身份：

```bash
hostname
whoami
cd ~/Projects/my-project
pwd
git status
codex
```

不要从家目录、下载目录或多个仓库的共同父目录启动。当前目录会影响工作区边界、项目规则发现、Git 状态和默认命令执行位置。

也可以显式指定目录：

```bash
codex --cd ~/Projects/my-project
```

脚本和快捷方式中显式写目录，比依赖“当前终端碰巧在哪”可靠。

## 10. 建立一个安全的第一次练习

在 Mac 或 Ubuntu 本机终端创建独立项目：

```bash
mkdir -p ~/terminal-practice/codex-first-project
cd ~/terminal-practice/codex-first-project

cat > calculator.py <<'PY'
def add(a: int, b: int) -> int:
    return a + b
PY

cat > test_calculator.py <<'PY'
from calculator import add


def test_add():
    assert add(2, 3) == 5
PY

python3 -m venv .venv
. .venv/bin/activate
python -m pip install pytest
python -m pytest -q

git init
git add calculator.py test_calculator.py
git commit -m "chore: create codex practice project"
```

如果 Git 尚未配置姓名和邮箱，应先完成自己的 Git 配置，不要让 Codex替你随便填写身份。

## 11. 第一次进入只做项目调查

在练习目录启动：

```bash
codex
```

先使用：

```text
/status
/permissions
/model
```

确认目录、模型、认证、权限和 Sandbox。第一次 Prompt 使用：

```text
当前阶段只读，不要修改文件、安装依赖、访问网络或执行 Git 写操作。

请检查当前目录、Git 状态、calculator.py、test_calculator.py 和测试方式，然后回答：
1. 项目当前行为；
2. 怎样运行测试；
3. 如果要增加 subtract 函数，最小修改范围是什么；
4. 哪些结论来自文件，哪些仍是推测。

重要结论给出文件路径。
```

调查结果不可靠时，不要立刻允许修改。先纠正它对项目的理解。

## 12. `AGENTS.md` 保存长期项目规则

可以在项目根目录创建：

```md
# 项目约定

- Python 命令使用项目 `.venv` 中的解释器。
- 修改后运行 `python -m pytest -q`。
- 不读取或修改 `.env`、凭据和项目外目录。
- 不执行 `git add`、`git commit` 或 `git push`。
- 新增依赖前先说明理由。
```

在 Codex 中可使用：

```text
/init
```

生成初稿，但必须人工审查。`AGENTS.md` 是模型指令，不是操作系统权限控制；它适合写项目结构、测试命令和协作规则，不适合保存密码、Token 或一次性任务。

Codex 还支持全局与嵌套的 `AGENTS.override.md`。更具体目录中的规则可以覆盖同目录的普通 `AGENTS.md`。发现异常规则时，应检查从 `~/.codex` 到当前工作目录的整个指令链。

## 13. 常用交互入口

进入 Codex 后，当前常用命令包括：

```text
/status
/permissions
/model
/init
/review
/resume
/fork
```

其中：

- `/status` 查看当前会话配置；
- `/permissions` 选择允许范围；
- `/model` 选择模型与推理强度；
- `/init` 生成项目指令初稿；
- `/review` 对当前变化执行独立审查；
- `/fork` 从当前对话分叉一个新会话，而不破坏原会话。

具体命令以当前界面 `?` 帮助和 `codex --help` 为准。

## 14. 会话恢复不是项目恢复

继续最近会话：

```bash
codex resume --last
```

从历史会话分叉：

```bash
codex fork --last
```

恢复或分叉后先重新检查：

```bash
pwd
git branch --show-current
git status
git log -5 --oneline
```

会话保存的是对话和工具过程，不是 Git 工作区、依赖环境、数据库或远程主机的快照。

## 15. 每次任务开始与结束的固定检查

启动前：

```bash
hostname
pwd
git status
type -a codex
codex --version
codex login status
```

任务中明确：

```text
只允许修改列出的文件。
不要执行 git add、commit 或 push。
安装依赖、访问网络、删除文件或扩大范围前先说明。
完成后列出修改文件、运行命令、测试结果、未验证内容和风险。
```

结束后：

```bash
git status --short
git diff --name-status
git diff --stat
git diff
```

Codex 的总结只是描述，Git diff 才是实际发生的变化。

## 16. 常见故障按层排查

找不到命令或版本不对：

```bash
type -a codex
command -v codex
codex --version
printf '%s\n' "$PATH" | tr ':' '\n'
```

认证来源不符合预期：

```bash
codex login status
```

API Key 登录却没有消耗 ChatGPT 订阅额度，这是正常的，因为它走 Platform API 计费。反过来，ChatGPT 登录也不等于你获得了一个可给任意第三方程序使用的 API Key。

项目识别错误：

```bash
pwd
git rev-parse --show-toplevel
git status
```

配置或身份切换异常时，先查看 Part 10C，不要直接删除整个 `~/.codex`。
