# 06 进程、前台、后台与任务控制

命令启动后会变成进程。进程可能占用当前终端、进入后台、被暂停、继续运行或终止。

这几个概念需要分清：

```text
前台
→ 当前终端的键盘输入交给它

后台
→ Shell 可以继续接收命令

暂停
→ 进程暂时不继续执行

脱离终端
→ SSH 或窗口关闭后仍能继续
```

后台运行不等于已经脱离终端。

---

## 1. 前台进程

```bash
python app.py
```

如果程序持续运行，当前终端会被它占用。常见前台程序包括：

- 开发服务器；
- 训练脚本；
- `ping`；
- `less`；
- Claude Code、Codex CLI 和 Grok CLI。

此时输入先交给程序，而不是 Shell。

---

## 2. `Ctrl + C`：请求中断

```text
Ctrl + C
```

通常向前台程序发送中断信号。程序可能立即退出，也可能先保存状态、打印信息或忽略信号。

AI CLI 中，它可能只停止当前生成或工具调用，不一定退出整个程序。

它是第一选择，不是无条件强杀。

---

## 3. `Ctrl + Z`：暂停

```text
Ctrl + Z
```

通常暂停前台进程并放入当前 Shell 的任务列表。

查看：

```bash
jobs
```

可能看到：

```text
[1]+  Stopped  python app.py
```

暂停不等于结束。

恢复到前台：

```bash
fg
```

在后台继续：

```bash
bg
```

指定任务：

```bash
fg %1
bg %1
```

---

## 4. 使用 `&` 启动后台任务

```bash
python app.py &
```

Shell 会立即返回提示符，但程序仍可能向当前终端输出。

重定向：

```bash
python app.py > app.log 2>&1 &
```

查看最近后台任务 PID：

```bash
printf '%s\n' "$!"
```

这仍不保证关闭终端或断开 SSH 后继续。

---

## 5. 查找进程

当前 Shell PID：

```bash
printf '%s\n' "$$"
```

查看进程：

```bash
ps
ps aux
```

按名称：

```bash
pgrep -fl python
```

GPU 任务还可查看：

```bash
nvidia-smi
```

名称匹配只能作为线索。结束进程前核对 PID、用户、启动命令和项目目录。

---

## 6. `kill`：向指定进程发送信号

正常请求结束：

```bash
kill PID
```

默认通常发送 TERM，程序有机会清理资源。

只有普通方式无效，并且确认 PID 正确时，才考虑：

```bash
kill -9 PID
```

强制终止可能导致：

- 文件只写了一部分；
- 数据库或缓存状态不一致；
- checkpoint 未保存；
- 临时资源残留。

不要把 `kill -9` 作为第一步。

---

## 7. `pkill` 会扩大匹配范围

```bash
pkill python
```

可能结束所有匹配的 Python 进程，包括其他项目或其他用户的任务。

更安全的流程：

```bash
pgrep -fl python
kill SPECIFIC_PID
```

在共享服务器上不得随意批量终止进程。

---

## 8. 为什么关闭终端后程序会停

程序通常属于当前终端会话。关闭窗口、退出 Shell 或断开 SSH 时，它可能收到挂断信号并终止。

因此：

```bash
python train.py &
```

不等于“断网后训练一定继续”。

长任务应使用：

- tmux；
- systemd；
- 后台容器；
- 作业调度器；
- 经过验证的 nohup 流程。

对于个人 Ubuntu 游戏本，优先使用 tmux。

---

## 9. `nohup` 的基本用法

```bash
nohup python train.py > training.log 2>&1 &
```

记录 PID：

```bash
printf '%s\n' "$!"
```

查看日志：

```bash
tail -f training.log
```

nohup 不提供可重新进入的交互终端，排错和管理不如 tmux 直观。

---

## 10. tmux 解决什么、不解决什么

```text
SSH 断开
→ tmux 会话和其中进程仍在 Ubuntu 上
```

它不能防止：

- Ubuntu 关机或休眠；
- 断电；
- Python 崩溃；
- GPU OOM；
- 磁盘写满；
- checkpoint 损坏。

真正的断点续训依赖训练程序和 checkpoint。

---

## 11. AI CLI 启动长期任务时

可以明确要求：

```text
不要把长期任务静默放到后台。
先说明启动命令、运行目录、日志路径、PID 或 tmux 会话名，以及安全停止方式。
未经确认不要使用 kill -9、pkill 或终止其他 GPU 进程。
```

Agent 启动任务后，仍要人工检查日志和进程状态。

---

## 12. 最短记忆卡片

```text
Ctrl + C  请求中断
Ctrl + Z  暂停
jobs      查看 Shell 任务
fg        恢复到前台
bg        后台继续
pgrep     查找进程
kill PID  请求结束指定进程
```
