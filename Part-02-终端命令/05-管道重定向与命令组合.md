# 05 管道、重定向与命令组合

Shell 可以把多个小工具连接成处理链。先认识三条基本通道：

```text
stdin   标准输入
stdout  标准输出
stderr  标准错误
```

常用符号：

```text
|      管道
>      覆盖写入
>>     追加写入
2>     保存错误
2>&1   合并错误和正常输出
&&     前一条成功才继续
||     前一条失败才继续
;      无论成功失败都继续
```

---

## 1. 管道 `|`

```bash
ls -la | less
```

左侧标准输出成为右侧标准输入。

筛选：

```bash
rg 'ERROR' app.log | less
```

统计：

```bash
find . -type f -name '*.py' | wc -l
```

管道默认不包含标准错误。

---

## 2. `>` 会覆盖文件

```bash
printf 'hello\n' > note.txt
```

如果 `note.txt` 已存在，原内容通常会被覆盖，而且不一定询问。

执行前检查：

```bash
ls -l note.txt
```

需要保留旧文件时，可以先写新文件并比较：

```bash
printf 'hello\n' > note.new.txt
diff note.txt note.new.txt
```

---

## 3. `>>` 追加内容

```bash
printf 'new line\n' >> note.txt
```

反复执行可能产生重复内容。不要无脑把 PATH、alias 或环境变量多次追加到 `.zshrc`。

配置文件更适合先备份并人工编辑：

```bash
cp ~/.zshrc ~/.zshrc.backup
```

---

## 4. 保存错误和完整输出

只保存错误：

```bash
COMMAND 2> error.log
```

只保存正常输出：

```bash
COMMAND > output.log
```

全部保存：

```bash
COMMAND > all.log 2>&1
```

`2>&1` 的顺序有意义，它让 stderr 指向 stdout 当前的目标。

---

## 5. `tee`：显示并保存

```bash
COMMAND 2>&1 | tee output.log
```

追加：

```bash
COMMAND 2>&1 | tee -a output.log
```

训练示例：

```bash
python train.py 2>&1 | tee training.log
```

脚本中应启用：

```bash
set -o pipefail
```

否则管道最后的 `tee` 成功，可能掩盖前面的训练命令失败。

---

## 6. `&&`、`||` 和 `;`

前一条成功才继续：

```bash
python -m pytest && git status
```

前一条失败才执行：

```bash
python app.py || printf '运行失败\n'
```

无论成功失败都继续：

```bash
date; pwd; ls
```

有依赖关系的步骤优先使用 `&&`。破坏性流程中不要用 `;` 无条件继续。

---

## 7. 退出状态

查看上一条命令：

```bash
printf '%s\n' "$?"
```

通常：

```text
0      成功
非 0   失败或特殊状态
```

具体数字由程序定义。`&&` 和 `||` 就是根据退出状态决定是否继续。

---

## 8. 命令替换和变量

```bash
CURRENT_BRANCH=$(git branch --show-current)
printf '%s\n' "$CURRENT_BRANCH"
```

不要把不可信或未经检查的命令输出直接拼入删除、权限或远程命令。

危险思路：

```bash
rm -rf "$(some-command)"
```

先打印和验证值，再执行修改。

---

## 9. 引号仍然重要

```bash
printf '%s\n' "$PROJECT_PATH"
```

不加引号时，空格、通配符和换行可能被 Shell 再次解释。

单引号通常按原样保留：

```bash
printf '%s\n' '$HOME'
```

双引号允许变量展开：

```bash
printf '%s\n' "$HOME"
```

---

## 10. 向 AI 发送日志前先脱敏

管道可能把内容发送给外部 AI 服务。先确认：

- 工具是否联网；
- 日志是否含凭据；
- 文件是否过大；
- 项目是否允许上传；
- 上游模型供应商是谁。

可以先搜索：

```bash
rg -n 'TOKEN|PASSWORD|Authorization|Cookie' error.log
```

---

## 11. 最短常用组合

```bash
COMMAND | less
COMMAND > file
COMMAND 2>&1 | tee file
COMMAND_A && COMMAND_B
```

每次看到 `>` 时，都先问目标文件是否已经存在。
