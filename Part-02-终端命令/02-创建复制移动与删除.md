# 02 创建、复制、移动与删除

文件操作看起来很基础，却也是终端里最容易造成实际损失的一组命令。图形界面通常会显示文件图标、目标文件夹和确认窗口；终端只根据你输入的路径执行。少写一个目录、把相对路径理解错，或者让通配符匹配到比预期更多的文件，都可能让结果完全不同。

这一章不把 `touch`、`cp`、`mv` 和 `rm` 拆成互不相关的命令卡片，而是在一个练习目录中完成一套连续操作。练习不会接触你的正式项目，完成后也不要求立刻删除目录。

## 1. 先建立练习目录

在 Mac 终端执行：

```bash
mkdir -p ~/terminal-practice/file-operations
cd ~/terminal-practice/file-operations
pwd
ls -la
```

`pwd` 应该输出类似下面的路径：

```text
/Users/YOUR_USERNAME/terminal-practice/file-operations
```

用户名会因电脑而异，但路径末尾应是 `terminal-practice/file-operations`。如果输出的是正式项目、下载目录或家目录，不要继续复制后面的文件操作命令，先重新执行 `cd`。

`ls -la` 初次运行时通常只看到 `.` 和 `..`。其中 `.` 代表当前目录，`..` 代表上一级目录。它们不是刚刚创建的普通文件。

## 2. 创建文件和目录

先创建两个目录和一个空文件：

```bash
mkdir notes backups
touch notes/today.md
ls -la
ls -la notes
```

你可能看到：

```text
notes:
total 0
drwxr-xr-x  3 YOUR_USERNAME  staff   96 Jul 29 10:00 .
drwxr-xr-x  4 YOUR_USERNAME  staff  128 Jul 29 10:00 ..
-rw-r--r--  1 YOUR_USERNAME  staff    0 Jul 29 10:00 today.md
```

这里最值得注意的是 `today.md` 的大小为 `0`，因为 `touch` 只创建了空文件。它不会自动打开编辑器，也不会向文件写入正文。如果文件已经存在，再执行一次 `touch notes/today.md` 通常只会更新时间戳，不会清空原内容。

需要一次创建多层目录时使用 `mkdir -p`：

```bash
mkdir -p project/src/components
find project -print
```

可能输出：

```text
project
project/src
project/src/components
```

如果不使用 `-p`，而 `project/src` 尚不存在，直接创建 `project/src/components` 会报错：

```text
mkdir: project/src/components: No such file or directory
```

这不是权限问题，而是中间目录不存在。

目录名含空格时需要加引号：

```bash
mkdir "Meeting Notes"
```

如果写成 `mkdir Meeting Notes`，Shell 会把它解释成两个名称，于是创建 `Meeting` 和 `Notes` 两个目录。发现这种错误时先运行 `ls -la` 确认结果，再分别处理，不要立刻使用通配符批量删除。

## 3. 给文件写入一点内容

为了后面观察复制和移动的结果，先向文件写入两行文字：

```bash
printf '第一行：学习文件操作\n第二行：保留备份\n' > notes/today.md
cat notes/today.md
```

输出应为：

```text
第一行：学习文件操作
第二行：保留备份
```

这里的 `>` 会覆盖目标文件原有内容。它虽然不是本章重点，但需要记住：有些“写文件”操作不会询问是否覆盖。重要文件应先用 `cat`、`less` 或编辑器确认内容。

## 4. 复制文件，并确认复制结果

把 `today.md` 复制到 `backups` 目录：

```bash
cp notes/today.md backups/today.md
ls -l notes/today.md backups/today.md
```

两份文件此时内容相同，但它们已经是两个独立文件。可以修改原文件验证：

```bash
printf '第三行：原文件继续修改\n' >> notes/today.md
printf '%s\n' '--- 原文件 ---'
cat notes/today.md
printf '%s\n' '--- 备份文件 ---'
cat backups/today.md
```

你会看到原文件多出第三行，而备份文件仍然只有两行。`cp` 复制的是执行当时的内容，之后两份文件不会自动同步。

目标文件已经存在时，普通 `cp` 可能直接覆盖。练习中可以使用交互确认：

```bash
cp -i notes/today.md backups/today.md
```

终端可能询问：

```text
overwrite backups/today.md?
```

输入 `n` 并回车可以放弃覆盖。不同系统和语言环境的提示文字可能略有差异，但它都会等待你的选择。

复制目录时需要递归参数：

```bash
cp -R project project-copy
find project-copy -print
```

在复制大型目录前，先查看大致体积：

```bash
du -sh project
```

源码项目的长期版本管理应交给 Git。连续创建 `project-copy`、`project-final`、`project-final-2` 虽然直观，但很快会让你不知道哪个目录才是最新版本。

## 5. 移动和重命名其实使用同一个命令

`mv` 既负责移动，也负责重命名。先把备份文件改名：

```bash
mv backups/today.md backups/today-first-copy.md
ls -la backups
```

因为源和目标位于同一目录，这次操作表现为重命名。接着把它移动到新目录：

```bash
mkdir archive
mv backups/today-first-copy.md archive/
find . -print
```

可能看到：

```text
.
./archive
./archive/today-first-copy.md
./backups
./notes
./notes/today.md
```

如果目标路径是现有目录，文件会进入该目录；如果目标路径不存在，`mv` 会把它解释成新的名称。拿不准时先检查：

```bash
ls -ld archive
file archive
```

目标位置已经有同名文件时，`mv` 可能覆盖它。需要确认时使用：

```bash
mv -i notes/today.md archive/today.md
```

练习到这里先输入 `n`，保留原文件。真实工作中不要把“移动成功”仅理解为终端没有报错，还要运行 `ls` 或 `find` 检查源位置和目标位置。

## 6. 路径写错时会出现什么

假设误写了一个不存在的目录：

```bash
cp notes/today.md backup/today.md
```

由于我们创建的是 `backups`，不是 `backup`，可能出现：

```text
cp: backup/today.md: No such file or directory
```

遇到这种错误不要马上加 `sudo`。先确认拼写和目录：

```bash
pwd
ls -la
ls -ld backup backups 2>/dev/null
```

`No such file or directory` 最常见的原因是路径拼错、中间目录不存在、大小写不一致或当前目录不是预期位置。管理员权限无法修复这些问题。

路径含空格却没有加引号时，也可能出现多个报错。例如：

```bash
cp notes/today.md Meeting Notes/
```

Shell 会把 `Meeting` 和 `Notes/` 当成两个目标参数。正确写法是：

```bash
cp notes/today.md "Meeting Notes/"
```

## 7. 删除文件前先做一次可见确认

终端中的 `rm` 通常不会把文件送进 macOS 废纸篓，也没有统一的撤销按钮。先创建一个专门用于删除的临时文件：

```bash
touch delete-me.txt
ls -l delete-me.txt
rm -i delete-me.txt
```

出现确认提示后输入 `y`。再检查：

```bash
ls -l delete-me.txt
```

这次应该看到类似：

```text
ls: delete-me.txt: No such file or directory
```

这里的报错反而说明删除已经发生。

批量删除前先预览匹配范围。创建三个练习文件：

```bash
touch app.log server.log keep.txt
printf '%s\n' *.log
```

输出应只包含：

```text
app.log
server.log
```

确认后再使用带交互确认的删除：

```bash
rm -i *.log
```

通配符通常由 Shell 在执行 `rm` 前展开。`*.log` 不是“交给 rm 自己慢慢找”，而是先被替换为所有匹配文件。当前目录不对时，匹配范围也会随之改变。

## 8. 删除目录时为什么风险更高

空目录可以使用：

```bash
mkdir empty-folder
rmdir empty-folder
```

`rmdir` 只删除空目录。如果目录里还有文件，它会拒绝执行。这种限制对新手是有帮助的。

删除非空目录需要递归处理，这意味着命令会进入子目录并处理其中全部内容。再叠加强制参数后，确认和部分错误提示还会减少。本书不提供可直接复制的递归强制删除命令，也不建议新手把它当作普通清理方法。

在处理非空目录前，至少检查：

```bash
hostname
pwd
ls -la DIRECTORY_NAME
du -sh DIRECTORY_NAME
```

这四项分别确认当前机器、当前目录、待处理内容和大致体积。如果目录中包含数据集、模型、实验结果或未提交源码，先停止操作。

更稳妥的过渡做法是把目录移动到本机的待清理区：

```bash
mkdir -p ~/Trash-Staging
mv DIRECTORY_NAME ~/Trash-Staging/
```

这样原位置已经清理，但内容仍可在确认后恢复。需要注意，`~/Trash-Staging` 只是普通目录，不是系统废纸篓，也不会自动清空。

## 9. 名称以连字符开头的文件

有些文件名本身以 `-` 开头，例如：

```text
-important.txt
```

直接把它放在命令参数位置时，程序可能把文件名误解为选项。可以在文件名前加 `./`：

```bash
rm -i ./-important.txt
```

或者使用 `--` 表示后续参数不再作为选项解析：

```bash
rm -i -- -important.txt
```

## 10. 变量中的路径要先显示再执行

脚本和长命令经常通过变量保存路径：

```bash
SOURCE_FILE="notes/today.md"
BACKUP_DIR="backups"
```

先打印值：

```bash
printf 'SOURCE=%s\nDEST=%s\n' "$SOURCE_FILE" "$BACKUP_DIR"
```

再执行：

```bash
cp "$SOURCE_FILE" "$BACKUP_DIR/"
```

双引号可以保护空格并避免某些意外展开。如果变量为空、显示出项目外路径或目标目录名称不符合预期，应立即停止。

## 11. Git 能恢复什么，不能恢复什么

在 Git 仓库中操作前先运行：

```bash
git status
```

操作后检查：

```bash
git status --short
git diff --stat
git diff
```

如果误删的是 Git 已跟踪文件，而且删除尚未提交，可以先查看差异：

```bash
git diff -- PATH_TO_FILE
```

确认确实要丢弃当前未提交修改后，再恢复：

```bash
git restore PATH_TO_FILE
```

`git restore` 会覆盖该文件当前未提交内容，不能在没看 diff 时随手执行。未被 Git 跟踪的文件删除后，Git 通常无法帮助恢复；数据库、模型文件和项目外目录也不在普通源码版本控制范围内。

## 12. 完成练习后的状态

运行：

```bash
cd ~/terminal-practice/file-operations
find . -print
```

你的结果不必与示例完全相同，但应该能够说明每个文件为什么在那里。这个练习目录可以暂时保留。等你确定不再需要时，再从上一级目录检查它的内容和体积，而不是立即寻找一条强制清理命令。

让 AI CLI 帮助处理文件时，可以给出下面的约束：

```text
只允许操作当前项目中明确列出的文件。
移动、覆盖、删除目录或使用通配符前，先列出目标和影响范围。
不要执行递归强制删除，不要删除未跟踪文件，不要操作项目外路径。
完成后列出所有变更，并显示 git status 和 git diff。
```
