# 02 创建、复制、移动与删除

文件操作是终端中最容易产生实际影响的一组命令。图形界面会显示图标、目标目录和确认窗口，Shell 只根据路径执行；少一层目录、当前目录不同或通配符多匹配几个文件，结果都会改变。

下面的操作全部在独立练习目录中完成，不接触正式项目。练习结束后保留目录，等能够解释其中每个文件的来源，再决定是否清理。

## 1. 创建目录、文件和可见内容

```bash
mkdir -p ~/terminal-practice/file-operations
cd ~/terminal-practice/file-operations
pwd
ls -la
```

`pwd` 的末尾应为 `terminal-practice/file-operations`。输出若仍是主目录、Downloads 或真实项目，停在这里修正位置，确认无误后再执行写操作。

创建目录与空文件：

```bash
mkdir notes backups
touch notes/today.md
ls -la notes
```

`touch` 创建的文件大小为 0；文件已经存在时，再次执行通常更新时间戳，不会清空内容。多层目录使用 `-p`：

```bash
mkdir -p project/src/components
find project -print
```

缺少 `-p` 且中间目录不存在时，`mkdir` 会报告 `No such file or directory`，这与管理员权限无关。名称含空格需要引号：

```bash
mkdir "Meeting Notes"
```

`mkdir Meeting Notes` 会创建两个目录。文件写入也会立即改变目标：

```bash
printf '第一行：学习文件操作\n第二行：保留备份\n' \
  > notes/today.md
cat notes/today.md
```

`>` 覆盖原内容，`>>` 追加。练习文件可以直接使用；真实配置和源码更适合写入新文件并比较差异，确认内容正确后再替换原文件。

## 2. 复制与移动都要看清目标类型

复制文件：

```bash
cp notes/today.md backups/today.md
ls -l notes/today.md backups/today.md
```

两份文件此刻内容相同，但已经独立。修改原文件后，副本不会同步：

```bash
printf '第三行：原文件继续修改\n' >> notes/today.md
printf '%s\n' '--- 原文件 ---'
cat notes/today.md
printf '%s\n' '--- 备份文件 ---'
cat backups/today.md
```

目标文件已经存在时，普通 `cp` 可能覆盖。需要人工确认可以使用：

```bash
cp -i notes/today.md backups/today.md
```

输入 `n` 会放弃覆盖。复制目录需要递归：

```bash
cp -R project project-copy
find project-copy -print
du -sh project
```

复制大型目录前查看体积。源码的长期版本交给 Git，连续建立 `project-final`、`project-final-2` 会让版本来源越来越难追踪。

`mv` 同时承担重命名和移动：

```bash
mv backups/today.md backups/today-first-copy.md
mkdir archive
mv backups/today-first-copy.md archive/
find . -print
```

源和目标位于同一目录时，它表现为重命名；目标是现有目录时，文件进入该目录；目标不存在时，目标文本成为新名称。目标类型不明确时，可以查看：

```bash
ls -ld archive
file archive
```

目标位置已有同名文件时，`mv` 也可能覆盖。移动完成后同时查看源位置与目标位置，不能只根据“命令没有报错”判断成功。

把 `backups` 误写成 `backup` 时，查看当前目录和真实名称：

```bash
pwd
ls -la
ls -ld backup backups 2>/dev/null
```

拼写、大小写、中间目录和当前目录错误，不能用 `sudo` 修复。含空格的路径继续使用引号，例如：

```bash
cp notes/today.md "Meeting Notes/"
```

## 3. 删除前把目标变成清单

终端的 `rm` 通常不会把文件送入 macOS 废纸篓，也没有统一撤销按钮。使用专用文件练习：

```bash
touch delete-me.txt
ls -l delete-me.txt
rm -i delete-me.txt
ls -l delete-me.txt
```

确认时输入 `y`。最后的 `No such file or directory` 说明文件已经不存在。

批量删除依赖 Shell 展开，预览匹配结果后再决定是否执行：

```bash
touch app.log server.log keep.txt
printf '%s\n' *.log
rm -i *.log
```

当前目录改变后，`*.log` 的匹配范围也会改变；预览清单不符合预期就停止。

空目录可以用 `rmdir`，目录非空时它会拒绝。非空目录需要递归处理，而强制参数会减少确认和错误提示，因此本书不把递归强制删除作为新手日常模板。处理目录前查看主机、位置、内容和体积：

```bash
hostname
pwd
ls -la DIRECTORY_NAME
du -sh DIRECTORY_NAME
```

目录中包含数据集、模型、实验结果或未提交源码时，需要先决定这些内容的去向。一个可恢复的过渡方法是移动到自己创建的待清理区：

```bash
mkdir -p ~/Trash-Staging
mv DIRECTORY_NAME ~/Trash-Staging/
```

它只是普通目录，不是系统废纸篓，也不会自动清空；作用是给人工复核留下时间。

## 4. 特殊文件名和脚本变量要显式处理

文件名以 `-` 开头时，程序可能把它识别为选项。加 `./` 或 `--` 表示后面是路径：

```bash
rm -i ./-important.txt
rm -i -- -important.txt
```

脚本通过变量保存路径时，把值打印出来并始终加双引号：

```bash
SOURCE_FILE="notes/today.md"
BACKUP_DIR="backups"
printf 'SOURCE=<%s>\nDEST=<%s>\n' \
  "$SOURCE_FILE" "$BACKUP_DIR"
cp "$SOURCE_FILE" "$BACKUP_DIR/"
```

尖括号可以暴露空值，双引号保护空格并阻止意外单词拆分。变量为空、指向项目外或目标名称异常时，脚本应停止，而不是继续交给后续命令猜测。

通配符、重定向和变量展开都发生在程序处理文件之前。复杂删除、移动、上传和同步任务可以把候选路径先输出到文件，人工检查后再执行写操作。

## 5. Git 恢复只覆盖它记录过的源码

在 Git 仓库中操作前查看 `git status`，操作后检查：

```bash
git status --short
git diff --stat
git diff
```

误删的是已跟踪文件、且删除尚未提交时，查看该文件的差异：

```bash
git diff -- PATH_TO_FILE
```

确认要丢弃当前未提交变化后，才能恢复：

```bash
git restore PATH_TO_FILE
```

`git restore` 会用 Git 记录的版本覆盖当前工作区内容。未跟踪文件、数据库、模型权重、运行结果和项目外目录通常不在普通源码版本控制中，项目使用 Git 并不意味着所有删除都可撤销。

完成练习后查看最终状态：

```bash
cd ~/terminal-practice/file-operations
find . -print
```

结果不必与示例一模一样，但应能说明每个文件为什么存在。让 AI CLI 处理文件时，任务应列出允许路径；覆盖、移动、删除目录或使用通配符前输出目标清单，完成后显示 `git status` 和 `git diff`。递归强制删除、清理未跟踪文件和项目外操作不属于默认授权范围。
