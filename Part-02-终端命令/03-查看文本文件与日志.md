# 03 查看文本文件与日志

终端里“查看一个文件”并不总是使用同一条命令。几行配置可以直接完整显示，几万行日志更适合分页浏览，而正在增长的训练日志需要持续追踪。本章通过一份练习日志，理解 `cat`、`less`、`head`、`tail`、`wc` 和 `tee` 各自适合什么场景。

先建立练习目录并生成一份小日志：

```bash
mkdir -p ~/terminal-practice/log-reading
cd ~/terminal-practice/log-reading
printf '%s\n' \
  '2026-07-29 10:00:00 INFO server started' \
  '2026-07-29 10:00:02 INFO request path=/health status=200' \
  '2026-07-29 10:00:05 WARN cache response slow' \
  '2026-07-29 10:00:08 ERROR database connection failed' \
  '2026-07-29 10:00:10 INFO retry succeeded' \
  > app.log
```

随后确认文件类型、大小和行数：

```bash
file app.log
ls -lh app.log
wc -l app.log
```

可能看到：

```text
app.log: ASCII text
-rw-r--r--  1 student staff   287B Jul 29 10:01 app.log
       5 app.log
```

`file` 判断内容类型，`ls -lh` 显示文件大小，`wc -l` 统计行数。先做这一步，可以避免把压缩包、模型权重或数 GB 日志直接输出到终端。

## 1. `cat` 适合一次看完的短文件

练习日志只有五行，可以直接运行：

```bash
cat app.log
```

`cat` 会从第一行到最后一行完整输出。它适合 README、短配置和小日志；文件很长时，内容会快速滚过屏幕，反而难以阅读。

`cat` 还可以把多个文件按顺序输出。例如建立另一份日志：

```bash
printf '%s\n' \
  '2026-07-29 10:01:00 INFO shutdown requested' \
  '2026-07-29 10:01:01 INFO server stopped' \
  > shutdown.log

cat app.log shutdown.log
```

把输出重定向到新文件时，要注意 `>` 会覆盖目标原内容：

```bash
cat app.log shutdown.log > combined.log
wc -l combined.log
```

这里目标是刚创建的练习文件，因此可以安全观察。处理真实文件前，先执行 `ls -l TARGET`，确认目标是否已经存在。

## 2. `less` 适合分页阅读长文件

运行：

```bash
less combined.log
```

进入后，键盘输入由 `less` 处理，不再是普通 Shell。常用按键如下：

```text
Space    下一页
b        上一页
/ERROR   向后搜索 ERROR
n        跳到下一个匹配
N        跳到上一个匹配
g        回到开头
G        跳到结尾
q        退出
```

新手有时会误以为终端“卡住了”，其实只是进入了分页器。看到底部出现文件名、百分比或冒号时，先尝试按 `q`。

`less` 不会因为浏览文件就修改它。查看大日志时，优先使用：

```bash
less training.log
```

而不是完整 `cat`。

## 3. 只看开头或结尾

CSV、配置和日志经常只需要先看一小部分。查看前几行：

```bash
head -n 3 app.log
```

输出：

```text
2026-07-29 10:00:00 INFO server started
2026-07-29 10:00:02 INFO request path=/health status=200
2026-07-29 10:00:05 WARN cache response slow
```

查看最后两行：

```bash
tail -n 2 app.log
```

输出：

```text
2026-07-29 10:00:08 ERROR database connection failed
2026-07-29 10:00:10 INFO retry succeeded
```

对于训练日志，开头通常包含参数和环境信息，结尾则更接近最新进度和错误。遇到失败任务时，可以先用 `tail -n 100 training.log` 看最后一段，再决定是否搜索整个文件。

## 4. 持续观察正在增长的日志

先在一个终端中运行：

```bash
tail -f app.log
```

这个命令会停留在前台，等待文件出现新内容。再打开另一个终端，进入同一练习目录并追加一行：

```bash
cd ~/terminal-practice/log-reading
printf '%s\n' '2026-07-29 10:02:00 INFO background task completed' >> app.log
```

第一个终端会立即显示新行。观察完成后，在第一个终端按 `Ctrl + C` 停止追踪。

`tail -f` 适合开发服务器和训练日志，但它只是显示新增内容，不会判断程序是否健康。日志长时间没有变化，可能是程序正在计算、被阻塞、已经退出或写入了另一个文件，需要结合进程状态继续判断。

## 5. 用 `wc` 判断文件规模

常用统计包括：

```bash
wc -l app.log
wc -w app.log
wc -c app.log
```

它们分别统计行数、单词数和字节数。准备把日志交给 AI 分析前，先看规模非常有用：几十行可以直接阅读，几十万行则应先筛选时间范围、错误级别和上下文。

当命令输出中只想得到数字时，也可以使用：

```bash
wc -l < app.log
```

这种写法把文件作为标准输入，输出中不会附带文件名。

## 6. `tee` 让输出同时显示并保存

普通重定向会把输出写入文件，终端上不再显示。`tee` 可以同时完成两件事：

```bash
python3 -c 'print("task started"); print("task completed")' \
  2>&1 | tee task.log
```

终端会显示两行内容，同时生成 `task.log`。查看结果：

```bash
cat task.log
```

追加而不是覆盖时使用 `tee -a`：

```bash
python3 -c 'print("second run")' 2>&1 | tee -a task.log
```

反复追加会让日志不断增长，也可能把多次实验混在一起。训练任务更适合为每次运行建立独立目录和带时间戳的日志文件。

在脚本中使用管道时，还要注意退出状态。假设左侧 Python 程序失败，而右侧 `tee` 成功，Shell 可能只报告最后一个命令的状态。需要在脚本开头启用：

```bash
set -o pipefail
```

这样管道中较早的失败不会被 `tee` 掩盖。

## 7. JSON、CSV 和二进制文件怎样查看

JSON 文件可以先用 `file` 和 `head` 判断，再使用 `jq` 格式化：

```bash
printf '%s\n' '{"name":"demo","enabled":true}' > config.json
jq . config.json
```

如果出现 `command not found: jq`，说明本机没有安装该工具；不要因此怀疑 JSON 文件损坏。

CSV 通常先看表头和前几行：

```bash
printf '%s\n' 'name,score' 'Alice,90' 'Bob,85' > scores.csv
head -n 3 scores.csv
```

对于模型权重、图片、压缩包和可执行文件，只检查元数据：

```bash
file PATH_TO_FILE
ls -lh PATH_TO_FILE
```

不要直接 `cat` 二进制文件。误操作导致终端显示乱码时，可以尝试运行 `reset` 恢复显示。

## 8. 日志不一定适合直接发给外部 AI

日志可能包含用户名、本机绝对路径、服务器地址、请求头、Cookie、Token、数据库连接信息和业务数据。发送前先做基础搜索：

```bash
rg -n 'API_KEY|TOKEN|PASSWORD|Authorization|Cookie' app.log
```

没有搜索结果只能说明这些明显关键词没有出现，不能证明文件完全没有敏感内容。还要人工查看路径、URL、邮箱、数据样本和内部错误信息。

较安全的做法是只提取与问题相关的小段，并用占位符替换真实凭证和地址。已经泄露的凭证不能靠文本脱敏补救，应立即撤销和更换。

## 9. 文件不存在或没有权限时

出现“没有这个文件”时，先检查位置和文件名：

```bash
pwd
ls -la
```

常见原因包括当前目录错误、文件名大小写不同、路径中有空格、文件已移动，或者日志实际写在远程机器上。

出现 `Permission denied` 时，先查看文件所有者和权限：

```bash
ls -l PATH_TO_FILE
```

不要因为读不到就立即加 `sudo`。先确认自己是否本来就应该读取它，以及是否含有其他用户或系统的敏感信息。

## 10. 一套实际排查顺序

应用出错后，可以按下面的顺序查看：

```bash
cd PROJECT_PATH
pwd
ls -lh logs/
tail -n 100 logs/app.log
rg -n -C 3 'ERROR|Traceback|Exception' logs/app.log
less logs/app.log
```

这套顺序先确认文件位置和大小，再查看最新错误、搜索上下文，最后按需浏览全文。它比一上来把整个日志复制进聊天更容易抓住重点，也更能控制敏感信息范围。
