# 04 搜索文件与文本

终端中的“搜索”包含两个不同问题：文件在哪里，以及某段文字出现在哪些文件中。前者通常使用 `find`，后者可以使用 `grep` 或 `rg`。先分清问题类型，再缩小目录和文件范围，通常比把所有条件塞进一条长命令更可靠。

继续使用日志练习目录，并补充源码、测试和归档文件：

```bash
cd ~/terminal-practice/log-reading
mkdir -p src tests archive
printf '%s\n' \
  'def connect_database():' \
  '    return "connected"' \
  > src/database.py
printf '%s\n' \
  'def test_connect_database():' \
  '    assert True' \
  > tests/test_database.py
cp app.log archive/app-2026-07-29.log
find . -print
```

## 1. 用 `find` 按路径、名称和类型建立候选清单

查找 Python 文件：

```bash
find . -type f -name '*.py'
```

其中 `.` 表示当前目录，`-type f` 只保留普通文件，`-name '*.py'` 按名称匹配。星号放在单引号中，是为了让 `find` 接收模式，而不是先由 zsh 展开。查目录或忽略大小写可以运行：

```bash
find . -type d -name 'archive'
find . -type f -iname '*readme*'
```

macOS 自带 BSD 工具，Ubuntu 常见 GNU 工具，部分扩展参数并不完全相同。看到 `unknown primary` 或不支持的选项时，先运行 `man find` 查看本机能力，不要让 AI 反复猜测参数。

搜索结果首先是候选清单，不应直接接到删除、移动、上传或改权限。先检查日志数量和体积：

```bash
find . -type f -name '*.log' -print
find . -type f -name '*.log' -print | wc -l
find . -type f -name '*.log' -exec ls -lh {} \;
```

项目根目录、主目录或远程服务器中的匹配结果都不天然安全。范围写错后，自动写操作会把错误迅速扩大。

## 2. 明确文件用 `grep`，代码仓库通常优先 `rg`

在一个日志中搜索错误：

```bash
grep -n -C 2 'ERROR' app.log
```

`-n` 显示行号，`-C 2` 同时显示前后两行。递归搜索可以使用 `grep -Rni 'database' .`，但包含依赖、虚拟环境和生成文件的仓库可能很慢。

ripgrep 的命令是 `rg`，更适合代码项目：

```bash
rg -n 'database'
rg -n 'database' src/ tests/
rg -n -t py 'database'
rg --files
```

输出会同时给出路径、行号和匹配内容。`rg` 通常尊重 `.gitignore`，会跳过依赖、缓存和构建目录，因此速度很快；“没有结果”也不代表所有磁盘文件都不存在匹配。需要检查隐藏文件时可明确使用 `--hidden`，但隐藏目录可能包含凭证和认证缓存，结果不要直接粘贴到聊天、Issue 或公开日志。

## 3. 区分普通文字与正则表达式

`grep` 和 `rg` 默认会把部分符号解释为正则表达式。搜索字面内容 `torch.cuda` 时，可以转义点号：

```bash
rg -n 'torch\.cuda'
```

只想按普通字符串匹配，可以使用固定字符串模式：

```bash
rg -n -F 'torch.cuda'
```

日志中查多个关键词可以写成：

```bash
rg -n 'ERROR|WARN|Traceback|Exception' app.log
```

复杂正则看起来紧凑，却容易匹配过多或过少。用于替换、删除和权限修改前，先在少量文件中只读验证结果，必要时将表达式拆成几个简单搜索。

## 4. 文件名可能包含空格、换行和连字符

创建带空格的文件：

```bash
printf '%s\n' 'TODO: review this note' > 'review notes.txt'
```

下面的循环不可靠：

```bash
for file in $(find . -name '*.txt'); do
  printf '%s\n' "$file"
done
```

命令替换的输出会按空白再次拆分，`review notes.txt` 可能被当成两个路径。只搜索文字时直接使用：

```bash
rg -n 'TODO' --glob '*.txt'
```

确实需要把 `find` 结果交给其他程序时，可使用 NUL 分隔：

```bash
find . -type f -name '*.txt' -print0 \
  | xargs -0 grep -n 'TODO'
```

它比依赖空格或换行更能正确处理特殊文件名。涉及写操作时仍要先打印候选并确认数量，不能因为分隔方式正确就跳过范围审查。

## 5. 从运行错误定位源码和测试

假设日志出现 `ERROR database connection failed`，先查看运行时上下文：

```bash
rg -n -C 2 'database connection failed' app.log
```

随后在源码与测试中搜索相关符号：

```bash
rg -n 'connect_database|database connection' src/ tests/
sed -n '1,120p' src/database.py
sed -n '1,120p' tests/test_database.py
```

这条路径从运行现象进入实现和测试。匹配只是调查线索，不能因为关键词相同就断定某个函数是根因；还要阅读调用关系、配置来源和可复现测试。

提交前也可以搜索明显的敏感词：

```bash
rg -n --hidden \
  'API_KEY|SECRET|TOKEN|PASSWORD|Authorization|Cookie'
```

这不能代替 Secret Scanner、Git 历史检查和人工审查。随机字符串、私钥、云配置和认证 JSON 可能完全不含这些词。发现真实凭据时，应停止提交与分享；已经进入远程仓库或群聊的凭据还需要服务端撤销和轮换。

## 6. 让 Agent 搜索时保留路径与证据

适合交给 AI CLI 的只读任务可以写成：

```text
当前阶段只读，不要修改文件。
请从日志中的错误信息出发，使用 rg、find 或项目索引定位相关源码和测试。
每个结论给出文件路径和行号，并区分已经确认的事实与推测。
不要读取 .env、认证缓存、SSH 私钥、云凭据或项目外目录。
```

Agent 能快速整理跨文件线索，但一段完整解释若没有路径、符号或测试支持，仍可能只是根据错误文字做出的推测。

工具选择可以概括为：找“某种文件在哪里”使用 `find`；查“明确文件中有没有某段文字”使用 `grep`；在代码仓库中定位函数、配置或错误优先使用 `rg`。常用命令包括：

```bash
find . -type f -name '*.py'
grep -n -C 2 'ERROR' app.log
rg -n -t py 'connect_database'
rg --files
```
