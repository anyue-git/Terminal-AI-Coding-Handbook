# 01 Grok Build：安装、认证与第一次使用

> 官方产品名：Grok Build
>
> 终端命令：`grok`
>
> 最近核对：2026-07-29

Grok Build 是 xAI 提供并开源的终端编程 Agent。它可以读取和修改代码、执行命令、运行测试、使用 Web Search、管理会话、创建 Git Worktree，并通过 Skills、Plugins、Hooks、MCP 和 ACP 接入更多工具。

第一次使用时需要分清：

```text
Grok Build 客户端
→ 本机运行的 grok 命令

认证方式
→ 浏览器账户登录、设备码或 XAI_API_KEY

账户与计费
→ xAI 消费者订阅权益，或 xAI API 账户用量

工作目录
→ Agent 实际读取和修改的项目范围
```

## 1. 产品名、命令和模型名不是一回事

启动命令是：

```bash
grok
```

产品名是 Grok Build。具体模型可能通过账户、配置和版本变化，例如默认模型、快速模型和专用构建模型都可能调整。

因此团队文档不应把某个模型 ID 当成产品永久名称。正确做法是：

```bash
grok models
```

在 TUI 中则使用：

```text
/model
```

模型、客户端和订阅属于不同层，排错时要分别确认。

## 2. 安装前检查平台和基础工具

在准备安装的 Mac 或 Ubuntu 上运行：

```bash
uname -s
uname -m
git --version
echo "$SHELL"
```

Grok Build 当前覆盖 macOS、Linux、WSL 以及官方支持的 Windows 路线。Windows 用户不要把 PowerShell、Git Bash 与 WSL 教程混着执行。

如果计划在远程 Ubuntu 游戏本使用，还应先确认：

```bash
hostname
whoami
pwd
```

## 3. 使用官方安装脚本

xAI 当前官方安装命令是：

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
```

这条命令会下载并执行远程安装脚本。执行前应确认域名来自 xAI 官方文档；在学校、团队或公司设备上，还应遵守组织的软件安装要求。

安装完成后重新打开终端，或按照安装器提示加载 PATH。然后检查：

```bash
type -a grok
command -v grok
grok version
grok --help
```

部分版本也支持：

```bash
grok --version
```

以当前帮助为准。

## 4. 出现多个 `grok` 时先解决 PATH

运行：

```bash
type -a grok
```

如果显示多个路径，可能同时存在：

- 当前官方安装器版本；
- 旧测试版本；
- 手工复制的二进制；
- 其他同名命令；
- 不同用户目录下的安装。

查看 PATH 顺序：

```bash
printf '%s\n' "$PATH" | tr ':' '\n'
```

查看实际文件：

```bash
ls -l "$(command -v grok)"
```

不要通过再次运行安装脚本来“覆盖到正确版本”。先确认 Shell 调用哪一份，再删除或调整明确的旧路径。

## 5. 第一次启动使用浏览器认证

运行：

```bash
grok
```

首次启动通常会打开浏览器，要求使用 xAI 支持的账户完成认证。登录完成后，终端获得可继续使用的本地认证状态。

也可以显式运行：

```bash
grok login
```

退出登录：

```bash
grok logout
```

认证状态可能保存在：

```text
~/.grok/auth.json
```

Unix 平台上官方实现会把它限制为仅当前用户可读写。即使文件权限严格，它仍然是敏感认证材料，不应提交 Git、发送给他人、制作公开截图或同步到不可信云盘。

## 6. SSH 与无浏览器环境使用设备码

在远程 Ubuntu、容器或无法直接打开浏览器的环境中，可以使用：

```bash
grok login --device-auth
```

当前别名可能包括：

```bash
grok login --device-code
```

终端会显示一次性设备码和认证地址。应在自己的可信浏览器中完成授权。

设备码属于临时凭据：

- 不要发到群聊；
- 不要让别人替你输入；
- 不要截图公开；
- 授权后检查登录的是哪个账户。

## 7. `XAI_API_KEY` 是 API 路线，不等于消费者订阅

无浏览器、自动化或明确使用 xAI API 时，可以设置：

```bash
export XAI_API_KEY="YOUR_XAI_API_KEY"
```

这里是占位符。不要把真实 Key 写进教程、Git 仓库或聊天记录。

重要区别：

```text
浏览器账户登录
→ 使用该账户在 Grok Build 中获得的消费者产品权益与策略

XAI_API_KEY
→ 使用 xAI API 账户、项目、额度和 API 计费规则
```

SuperGrok、Grok App 或其他消费者订阅不会自动变成一个可给任意程序调用的 xAI API Key。反过来，xAI API 余额也不是消费者订阅中的消息额度。

终端客户端名称相同，不代表两种认证共用一套额度。

## 8. 登录状态优先于 API Key 回退

Grok Build 当前的认证逻辑中，已经保存的浏览器登录会优先于 `XAI_API_KEY` 回退。

因此，下面这种情况可能发生：

```text
~/.grok/auth.json 存在有效会话
+
Shell 设置了 XAI_API_KEY

结果
→ 仍然使用已登录账户
```

准备测试 API Key 路线时，不要只设置环境变量后凭感觉判断。先检查并明确退出账户：

```bash
grok logout
```

然后在当前 Shell 设置 Key，再启动 Grok Build。

不要手工编辑或拼接 `auth.json` 来切换账户。需要多账户或多供应商时，应使用明确的状态目录、独立系统用户、容器或经过审查的配置工具，而不是共享认证缓存。

## 9. MCP OAuth 凭据是另一份状态

MCP Server 的 OAuth 凭据可能保存在：

```text
~/.grok/mcp_credentials.json
```

它与 Grok Build 主账户认证不是同一个文件。运行：

```bash
grok logout
```

不一定等于清除所有外部 MCP 凭据。

移除某个 MCP 时，应同时理解：

- Grok 配置是否还引用它；
- OAuth 凭据是否仍存在；
- 服务端是否保留授权；
- 是否需要在外部账户中撤销访问。

## 10. 安装后运行状态检查

在项目外先检查客户端：

```bash
grok version
grok --help
grok models
grok inspect
```

它们分别用于：

```text
grok version
→ 当前客户端版本

grok models
→ 当前账户和配置可用的模型

grok inspect
→ 当前目录实际加载的配置、规则与扩展
```

`grok inspect` 还支持结构化输出时，可以查看：

```bash
grok inspect --json
```

排查“为什么用了某个模型、加载了哪个 MCP、出现了什么规则”时，应看真实解析结果，不要只翻自己记得的配置文件。

## 11. Mac 与 Ubuntu 分别安装、分别认证

可以共享：

- Git 仓库；
- `AGENTS.md` 和项目规则；
- 测试与依赖声明；
- 不含敏感信息的 `.grok` 项目配置。

不要直接同步：

- Grok 可执行文件；
- `auth.json`；
- `mcp_credentials.json`；
- 整个 `~/.grok`；
- 平台相关二进制；
- 一台机器的虚拟环境。

每台机器分别运行：

```bash
hostname
type -a grok
grok version
grok inspect
```

远程 Ubuntu 还应确认当前账户和目录，避免把 Mac 的项目规则、远程训练目录和系统目录混在同一个会话中。

## 12. 从项目根目录启动

在 Mac 本地项目：

```bash
cd ~/Projects/my-project
pwd
git rev-parse --show-toplevel
git status
grok
```

在 Ubuntu SSH 会话：

```bash
hostname
whoami
cd ~/Projects/my-project
pwd
git status
grok
```

也可以显式指定工作目录：

```bash
grok --cwd ~/Projects/my-project
```

启动位置会影响：

- Git 仓库识别；
- `.grok/config.toml`；
- `AGENTS.md`；
- Skills、Plugins、Agents、Hooks；
- Sandbox 工作区；
- 默认命令执行目录。

不要从整个家目录启动，再让 Agent 自己寻找项目。

## 13. 创建安全的第一次练习

在独立目录建立项目：

```bash
mkdir -p ~/terminal-practice/grok-first-project
cd ~/terminal-practice/grok-first-project

cat > greeting.py <<'PY'
def greet(name: str) -> str:
    return f"Hello, {name}!"
PY

cat > test_greeting.py <<'PY'
from greeting import greet


def test_greet():
    assert greet("Grok") == "Hello, Grok!"
PY

python3 -m venv .venv
. .venv/bin/activate
python -m pip install pytest
python -m pytest -q

printf '.venv/\n__pycache__/\n.pytest_cache/\n' > .gitignore

git init
git add greeting.py test_greeting.py .gitignore
git commit -m "chore: create Grok Build practice project"
```

预期基线：

```text
1 passed
```

## 14. 第一次任务使用 Plan + Ask

启动：

```bash
grok
```

进入界面后先查看：

```text
/help
/context
/model
```

切换到 Plan：

```text
/plan
```

确保权限处于 Ask，而不是 Always-approve。第一次输入：

```text
当前阶段只读，不要修改文件、安装依赖、访问网络或执行 Git 写操作。

请检查当前目录、Git 状态、greeting.py、test_greeting.py 和测试方式，然后回答：
1. 项目当前行为；
2. 怎样运行测试；
3. 如果增加 farewell 函数，最小修改范围是什么；
4. 哪些结论来自文件，哪些仍是推测。
```

项目理解错误时，不要立刻批准修改。先纠正入口、测试和允许范围。

## 15. TUI 中的按键属于 Grok，而不一定属于 zsh

运行 `grok` 后进入文本用户界面。此时输入框、滚动区域和快捷键由 Grok TUI 处理。

按键异常时先判断焦点：

```text
普通 zsh
Grok 输入框
Grok 历史区域
tmux
SSH 远程终端
编辑器或 ACP 客户端
```

例如 `Ctrl+C` 在普通 Shell、TUI 输入框和运行中工具调用里的作用可能不同。不要看到快捷键行为变化就认为 zsh 配置损坏。

## 16. 常用 TUI 命令

当前常用入口包括：

```text
/help
/new
/resume
/sessions
/model
/context
/compact
/rewind
/export
/plan
/auto
/always-approve
/plugins
/skills
/hooks
/mcps
```

具体名称以 `/help` 为准。

它们可以分为四类：

```text
会话
→ /new /resume /sessions /compact /rewind /export

模型与上下文
→ /model /context

工作模式
→ /plan /auto /always-approve

扩展系统
→ /plugins /skills /hooks /mcps
```

不要把所有斜杠命令写进永久肌肉记忆。版本升级后先查看 `/help`。

## 17. Ask、Auto、Always-approve 与 Plan

权限模式主要包括：

```text
Ask
→ 未明确允许的操作询问用户

Auto
→ 分类器自动批准判断为安全的操作

Always-approve
→ 自动批准工具调用
```

Plan 是任务阶段，不是同一维度的权限模式。

新手推荐：

```text
Plan
+
Ask
```

确认计划后，再切到 Ask 或受控 Auto 执行。

Always-approve 不会让操作变安全。即使开启，Deny 规则和能够阻断的 PreToolUse Hook 仍应生效，但它们不能替代完整隔离。

不要在以下环境默认开启：

- 主分支；
- 工作区已有重要未提交修改；
- 唯一 SSH 连接；
- 可访问 Docker Socket；
- 包含真实数据库与凭据；
- 未审查的项目 Skills、Hooks、Plugins 或 MCP。

## 18. 模型与推理强度显式检查

查看模型：

```bash
grok models
```

命令行指定模型：

```bash
grok --model MODEL_NAME
```

简写可能是：

```bash
grok -m MODEL_NAME
```

推理强度可通过当前版本的：

```bash
grok --effort LEVEL
```

进行设置。

模型名、可用范围和默认值都可能变化。书中不给某个模型永久贴上“主力”“最强”或“最便宜”的标签。实际选择前查看 `grok models`、账户计划和当前 xAI 文档。

## 19. 会话查看、继续与分叉

查看会话：

```bash
grok sessions list
```

搜索：

```bash
grok sessions search KEYWORD
```

继续最近会话：

```bash
grok --continue
```

简写：

```bash
grok -c
```

恢复指定会话：

```bash
grok --resume SESSION_ID
```

或：

```bash
grok -r SESSION_ID
```

从旧会话分叉而不覆盖原会话：

```bash
grok --resume SESSION_ID --fork-session
```

会话保存在本机状态目录中，通常位于：

```text
~/.grok/sessions/
```

它保存上下文，不保存 Git、虚拟环境、数据库或远程机器快照。

## 20. 恢复会话前重新检查现实

Shell 中运行：

```bash
pwd
git branch --show-current
git status
git log -5 --oneline
```

恢复后输入：

```text
先不要继续修改。
重新检查当前目录、Git 分支、HEAD、未提交改动、项目规则、依赖文件和测试状态。
说明现实状态与旧会话上下文不一致的地方。
```

文件可能在中断期间被人工、其他 Agent 或 Git 操作改变。

## 21. 导出和导入会话

当前 CLI 提供会话导出与导入入口：

```bash
grok export --help
grok import --help
```

导出的会话可能包含：

- Prompt；
- 文件路径；
- 代码片段；
- 工具调用；
- 项目内部信息。

不要把导出文件当作普通聊天文本公开分享。导入来源不明的会话也可能携带不可信指令和上下文，应先审查内容。

## 22. 更新与自动更新

检查当前命令：

```bash
grok update --help
grok version
```

交互使用时自动更新可能方便，但脚本、CI、Headless 和 ACP 环境中应固定版本或关闭自动更新，避免参数和输出格式在无人注意时变化。

当前 CLI 支持类似：

```bash
grok --no-auto-update
```

用户配置也可以设置：

```toml
[cli]
auto_update = false
```

具体字段以当前 Settings 文档为准。

## 23. 每次启动前与结束后

启动前：

```bash
hostname
pwd
git status
type -a grok
grok version
grok inspect
```

任务中明确：

```text
只允许修改列出的文件。
不要执行 git add、commit 或 push。
安装依赖、联网、删除文件或扩大范围前先说明。
完成后列出修改文件、执行命令、测试结果、未验证内容和风险。
```

结束后：

```bash
git status --short
git diff --name-status
git diff --stat
git diff
```

“任务完成”只是模型结论，测试和 diff 才是证据。

## 24. 常见故障按层排查

找不到命令或版本错误：

```bash
type -a grok
command -v grok
grok version
printf '%s\n' "$PATH" | tr ':' '\n'
```

明明设置 API Key，却仍使用登录账户：

```text
原因通常是有效 auth.json 的优先级更高。
先明确运行 grok logout，再测试 API Key 路线。
```

项目配置或扩展来源不明：

```bash
pwd
git rev-parse --show-toplevel
grok inspect
grok inspect --json
```

模型不存在：

```bash
grok models
```

不要凭旧教程猜模型 ID。
