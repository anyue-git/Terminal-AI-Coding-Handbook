# 01 先分清配置、凭证、供应商与实例

> 最近核对：2026-07-29

第一次接触 Claude Code、Codex、Grok Build、CC Switch 或 Cockpit Tools 时，最容易把模型、账号、API、配置和实例混成一个“当前选项”。界面里一次切换，背后可能只改默认模型，也可能替换 Base URL、覆盖登录缓存，或启动另一套状态目录。出现 401、模型列表为空、账号没有切换或两个窗口互相影响时，只有先确定变化发生在哪一层，才能找到正确排查入口。

## 1. 一次请求至少经过六个对象

以 Codex CLI 中输入“解释这个项目”为例：

```text
任务输入
→ 客户端读取配置
→ 客户端取得凭证
→ 请求发送到配置指定的入口
→ 入口按模型名称处理或转发
→ 结果返回客户端
```

**客户端**是 Claude Code、Codex CLI、Codex App 或 Grok Build，负责项目读取、工具权限、命令执行和结果展示；它不是模型，也不一定是收费方。**供应商**是实际接收或转发请求的一方，例如 OpenAI、Anthropic、xAI、DeepSeek、云平台、企业 Gateway 或第三方中转。**模型**是请求调用的具体能力，客户端显示的名称可能是官方 ID，也可能是网关别名，名称相同不能单独证明上游相同。

**配置**告诉客户端默认模型、Provider、Base URL、审批、Sandbox、规则和 MCP 等行为。Codex 主要使用 TOML，Claude Code 组合 JSON、环境变量和状态文件，Grok Build 也同时读取用户与项目配置。**凭证**证明账号或 API 使用权，包括 OAuth 缓存、API Key、Access Token 和由辅助程序临时生成的 Token；泄露凭证可能直接导致账号或额度被使用，不能把它当作普通配置。**实例**是一套关联的配置、凭证、历史与运行状态，两个终端窗口若都读取 `~/.codex`，仍然共享同一 Codex 实例。

## 2. 换模型、换供应商、换账号和并行多开是四种需求

只换模型时，官方入口和凭证不变，只调整模型参数或配置。换供应商则通常同时改变 Provider、Base URL、协议、模型名称和认证方式，只改模型名往往不够。换账号的核心是替换活动 OAuth 或 API Key，配置文件可能完全不变。希望账号 A 与 B 同时运行，则不能只覆盖同一份凭证，而要隔离状态目录、系统用户、容器或由管理工具建立独立实例。

```text
只改模型名称
→ 模型切换

改 Base URL、协议或 Provider
→ 供应商切换

替换 OAuth / API Key
→ 账号切换

配置、凭证和运行状态分别隔离
→ 独立实例
```

Profile 只是命名配置，通常仍共享同一个状态目录和登录缓存；两个窗口也不自动等于两个实例。判断“是否真正多开”时，要看状态目录、凭证存储、Keychain 条目、环境变量和本地路由是否独立。

## 3. Base URL、网络代理和 LLM Gateway 的职责不同

Base URL 是客户端请求的服务根地址，修改它就改变了第一跳入口。网络代理主要负责 HTTP/HTTPS 传输，通常不理解模型业务，也不会自动把 Anthropic Messages 转为 OpenAI Responses。LLM Gateway 则理解模型请求，可能处理认证、协议转换、模型路由、额度统计、审计、负载均衡与故障切换。

```text
Claude Code
→ HTTPS 网络代理
→ Anthropic 官方 API
```

```text
Codex CLI
→ 本地或远程 LLM Gateway
→ 选择账号或上游供应商
→ 返回 Codex 兼容响应
```

第二种结构中，客户端 Base URL 可能始终是 `127.0.0.1`，真正上游由网关状态决定；只看 `config.toml` 不能确定请求最终去了哪里，还要检查本地服务、监听端口、路由配置与日志。第三方 Gateway 可能看到完整 Prompt、源码、工具调用和响应，使用前必须确认数据保留和责任边界。

## 4. “默认”要明确到底默认什么

本书将相关术语固定为：**默认配置**是没有额外参数时读取的用户配置；**默认账号**是当前凭证存储中的活动账号；**Profile**是在基础配置上叠加的命名设置；**独立实例**拥有独立状态目录与凭证；**活动供应商**是管理工具当前投影给客户端或网关当前选中的路由。

例如 Codex 的状态目录由 `CODEX_HOME` 决定，默认是 `~/.codex`。两个进程共用该目录时，会共享 `config.toml`、凭证缓存和部分历史；第二个进程使用不同 `CODEX_HOME`，才建立更完整的配置和状态隔离。Claude Code 在 macOS 上还涉及 Keychain，仅改变目录变量未必能完全隔离 OAuth，因此必须按当前版本验证。

## 5. 配置管理工具通常采用三种实现

第一种是**配置投影**：工具内部保存多份 Provider 配置，切换时覆盖客户端正在读取的 `config.toml`、`settings.json` 或环境变量。第二种是**凭证替换**：保存多个账号的认证快照，选择账号后替换 Keychain 或凭证文件，已运行进程可能需要重启。第三种是**本地路由接管**：客户端统一指向 localhost，工具在本地 Gateway 中选择上游账号、转换协议并统计用量。

学习管理工具不能只记按钮位置。每次操作都要回答：修改了哪个文件或系统凭证项；是否备份原文件；API Key/OAuth 存在哪里；客户端是否需要重启；请求是否经过本地代理；如何退出接管并恢复官方登录和端点。

## 6. 修改前先观察环境并建立最小备份

下面只检查路径和文件是否存在，不输出凭证正文：

```bash
ls -ld ~/.codex ~/.claude ~/.grok 2>/dev/null
ls -l ~/.codex/config.toml ~/.codex/auth.json 2>/dev/null
ls -l ~/.claude/settings.json ~/.claude.json 2>/dev/null
ls -l ~/.grok/config.toml ~/.grok/auth.json 2>/dev/null
```

文件不存在不一定表示安装损坏，可能尚未登录，或凭证位于 macOS Keychain / Linux Keyring。再检查覆盖变量，但隐藏值：

```bash
env | grep -E '^(CODEX_HOME|OPENAI_|ANTHROPIC_|CLAUDE_CODE_|XAI_)' \
  | sed 's/=.*$/=<已隐藏>/'
```

发现 `CODEX_HOME`、`ANTHROPIC_BASE_URL`、认证变量或第三方 Key 时，要继续追踪它来自当前 Shell、`.zshrc`、`.zprofile`、启动脚本还是管理工具。

备份只复制准备修改的文件，不把整个状态目录上传到 Git 或网盘：

```bash
mkdir -p ~/.config-backups/codex
chmod 700 ~/.config-backups ~/.config-backups/codex
cp ~/.codex/config.toml \
  ~/.config-backups/codex/config.toml.before-switch 2>/dev/null || true
```

含凭证的备份等同复制密码，目录应为 `700`、文件为 `600`，不通过聊天或邮件传输。恢复前先比较非敏感配置：

```bash
diff -u ~/.codex/config.toml \
  ~/.config-backups/codex/config.toml.before-switch
```
