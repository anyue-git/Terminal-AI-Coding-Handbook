# 01 先分清配置、凭证、供应商与实例

> 最近核对：2026-07-29

很多人第一次接触 Claude Code、Codex、CC Switch 或 Cockpit Tools 时，会把“模型”“账号”“API”“配置”和“实例”混在一起。界面里看起来只是选择了一个项目或点了一次切换，但背后可能发生的是完全不同的事情：有时只是改了默认模型，有时替换了 API 地址，有时覆盖了登录缓存，还有时启动了另一套独立的配置目录。如果不先建立基本概念，遇到 401、模型列表为空或账号没有切换时，很难判断该检查哪一层。

本章先不要求安装任何第三方管理工具。目标是看懂一条请求从客户端出发后经过哪些环节，也学会在修改配置前判断自己真正想改变什么。

---

## 1. 一次请求经过哪些东西

假设你在项目目录中启动 Codex CLI，并输入“解释这个项目”。一个简化的数据流如下：

```text
你输入任务
→ Codex CLI 读取配置
→ Codex CLI 取得凭证
→ 请求发送到配置指定的服务
→ 服务根据模型名称处理请求
→ 结果返回 Codex CLI
```

这里至少包含六个不同对象。

**客户端**是你直接操作的软件，例如 Claude Code、Codex CLI、Codex App 或 Grok CLI。客户端负责读取项目、组织请求、申请工具权限、显示结果。它不是模型本身，也不一定等于最终收费方。

**模型供应商**是实际接收请求并提供模型服务的一方，例如 OpenAI、Anthropic、DeepSeek、云平台或企业网关。第三方中转站也可能扮演供应商入口，但它是否继续把请求转发给别的上游，需要由服务方说明。

**模型**是一次请求要调用的具体能力。客户端里显示的名称可能是官方模型名，也可能是网关建立的别名。名称相同并不能单独证明请求最终到达同一个上游。

**配置**告诉客户端如何工作，包括默认模型、供应商标识、Base URL、审批策略、Sandbox、项目规则和 MCP 等内容。Codex 主要使用 TOML；Claude Code 主要使用 JSON 设置、环境变量和其他状态文件。

**凭证**证明你有权使用某个账号或 API。常见形式包括 OAuth 登录缓存、API Key、访问令牌和由凭证辅助程序临时生成的 Token。凭证与普通配置不能混为一谈，因为泄露凭证可能直接导致账号或额度被他人使用。

**实例**是一套相互关联的配置、凭证、历史和运行状态。两个终端窗口并不一定代表两个独立实例；如果它们都读取 `~/.codex`，就仍然共享同一套 Codex 配置与登录缓存。

## 2. 四种常见需求并不相同

### 只想换模型

例如仍然使用 OpenAI 官方登录，只把默认模型从一个 Codex 模型改成另一个。此时供应商和凭证没有变化，通常只需要修改模型配置或使用命令行参数。

### 想换供应商

例如把 Codex 的请求发往一个 OpenAI Responses 兼容网关，或者让 Claude Code 连接企业 LLM Gateway。此时通常需要修改 Base URL、供应商配置、模型名称和认证方式。只改模型名称往往不够。

### 想换账号

例如在两个 Claude 账号之间切换，或者让 Codex 从一个 ChatGPT 登录切换到另一个。此时关键变化是活动凭证。配置文件可能完全不变，但登录缓存被替换了。

### 想同时运行两个账号

这比“切换账号”多一层要求。覆盖当前凭证只能让后启动的进程使用新账号；如果希望账号 A 和账号 B 同时运行，通常需要为它们准备不同的状态目录、不同的系统用户、不同的容器，或者由第三方工具创建隔离实例。

可以用下面的方式判断：

```text
只改模型名称
→ 模型切换

改 Base URL、协议或 Provider
→ 供应商切换

替换 OAuth / API Key
→ 账号切换

配置目录和凭证目录都隔离
→ 独立实例
```

## 3. Base URL、代理和网关有什么区别

这三个概念经常被混用。

**Base URL** 是客户端请求的服务根地址。把它从官方地址改为另一个地址，意味着客户端把请求交给了新的入口。

**网络代理**主要负责网络传输，例如 HTTP 或 HTTPS 代理。它通常不理解模型请求的业务含义，也不会自动把 Anthropic 协议改成 OpenAI Responses 协议。

**LLM 网关**会理解模型请求，可能负责认证、模型路由、协议转换、额度统计、审计、负载均衡或故障切换。Claude Code 官方文档将 LLM Gateway 描述为位于客户端与模型供应商之间的集中代理层。使用第三方网关时，要确认它是否保存 Prompt、源码、工具调用和响应。

下面是两种不同的数据流：

```text
Claude Code
→ HTTPS 网络代理
→ Anthropic 官方 API
```

```text
Codex CLI
→ 本地或远程 LLM 网关
→ 选择账号或上游供应商
→ 返回兼容 Codex 的响应
```

第二种模式中，客户端看到的地址可能一直是 `127.0.0.1`，实际账号和上游由本地网关决定。因此，只看 `config.toml` 中的 Base URL，不一定能知道最终请求去了哪里，还要检查网关自身的配置和日志。

## 4. “默认实例”到底指什么

“默认实例”不是所有工具共用的正式术语。不同软件可能用它表示默认配置、默认账号、默认 Provider、默认 Profile，或者启动时自动选择的工作区。

为了避免混乱，本书按下面的方式使用这些词：

- **默认配置**：没有额外参数时读取的用户级配置；
- **默认账号**：当前凭证存储中处于活动状态的账号；
- **Profile**：在基础配置上叠加的一层命名配置；
- **独立实例**：具有独立状态目录和凭证的客户端运行环境；
- **活动供应商**：管理工具当前投影到客户端实际配置中的供应商。

例如 Codex 默认把状态放在 `CODEX_HOME`，其默认值是 `~/.codex`。如果两个进程都使用这个目录，它们会共享 `config.toml`、凭证缓存和部分历史。将第二个进程的 `CODEX_HOME` 指向另一个目录，才建立了更完整的隔离边界。

## 5. 配置管理工具通常做了什么

CC Switch、Cockpit Tools 和其他切换工具的实现并不完全相同，但常见做法可以分成三类。

第一类是**保存多份配置快照并覆盖活动文件**。切换供应商时，工具把选中的配置写入 `config.toml`、`settings.json` 或环境变量。客户端下次启动时读取新内容。

第二类是**保存多份凭证并替换活动凭证**。这适合账号切换，但如果已有进程在内存中缓存了登录状态，通常需要重启客户端。

第三类是**启动本地网关**。客户端配置只指向本地地址，工具在网关内部选择上游账号、转换协议并记录用量。此时“切换”可能不会直接改写真实上游地址，而是改变网关的路由状态。

学习这类工具时，不应只记按钮位置。每次操作至少回答：

1. 它修改了哪个文件或系统凭证项；
2. 原文件有没有备份；
3. API Key 或 OAuth Token 被保存在哪里；
4. 客户端是否需要重启；
5. 请求是否经过本地代理；
6. 如何恢复官方登录和官方端点。

## 6. 第一次检查自己的环境

下面的命令只查看文件是否存在，不会输出凭证内容。

在 Mac 终端执行：

```bash
ls -ld ~/.codex ~/.claude 2>/dev/null
ls -l ~/.codex/config.toml ~/.codex/auth.json 2>/dev/null
ls -l ~/.claude/settings.json ~/.claude.json 2>/dev/null
```

看到 `No such file or directory` 不一定表示安装损坏。某些文件只有登录或保存设置后才创建，凭证也可能存放在 macOS Keychain 而不是普通文件中。

接着检查是否设置了可能覆盖文件配置的环境变量：

```bash
env | grep -E '^(CODEX_HOME|OPENAI_|ANTHROPIC_|CLAUDE_CODE_)' \
  | sed 's/=.*$/=<已隐藏>/'
```

这里使用 `sed` 隐藏等号后的值，避免把密钥直接打印到终端记录或截图中。如果发现 `CODEX_HOME`、`ANTHROPIC_BASE_URL` 或认证变量，应先弄清它们来自当前 Shell、`.zshrc`、启动脚本还是管理工具。

## 7. 修改前建立最小备份

不要直接把整个配置目录上传到网盘或 Git 仓库。更安全的做法是在本机创建权限受限的备份目录，并只复制将要修改的文件。

例如备份 Codex 的非敏感配置：

```bash
mkdir -p ~/.config-backups/codex
chmod 700 ~/.config-backups ~/.config-backups/codex
cp ~/.codex/config.toml ~/.config-backups/codex/config.toml.before-v2 2>/dev/null || true
```

如果需要备份含凭证的文件，必须理解它等同于复制密码。备份目录应保持 `700`，文件保持 `600`，不应通过聊天、邮件或公开仓库传输。

恢复时也不要覆盖整个目录。先比较配置：

```bash
diff -u ~/.codex/config.toml \
  ~/.config-backups/codex/config.toml.before-v2
```

确认差异后再决定是否恢复。
