# 01 终端十五分钟上手

> 适合第一次打开终端，或者隔了一段时间想快速找回基本操作的读者。
>
> 这一页只完成一件事：在一个安全的练习目录中移动、创建文件、查看结果，并知道输错或程序卡住时怎样停下来。

打开 macOS 的 Terminal 后，你会看到一行提示符，末尾常见 `%`。提示符本身不用输入；你只需要在它后面输入命令并按回车。终端是显示文字和接收输入的窗口，真正解释命令的通常是 zsh。现在不需要背这些名词，先通过一次练习熟悉操作节奏。

## 1. 先确认自己在哪台机器、哪个目录

在终端依次运行：

```bash
hostname
whoami
pwd
```

输出会因电脑而异，例如：

```text
MacBook
student
/Users/student
```

`hostname` 是当前机器名称，`whoami` 是当前用户，`pwd` 显示当前工作目录。以后通过 SSH 登录 Ubuntu 时，窗口仍然可能出现在 Mac 上，但命令已经在远程机器执行；因此，删除文件、安装软件或启动训练前，再看一眼 `hostname` 和 `pwd` 是很有用的习惯。

接着查看当前目录：

```bash
ls
ls -la
```

`ls` 显示普通文件，`ls -la` 还会显示以 `.` 开头的隐藏文件以及更详细的信息。你可能看到 `.zshrc`、`.gitconfig` 等配置文件。它们没有显示在 Finder 的普通视图中，并不代表它们不重要。

## 2. 建立一个不会影响真实项目的练习目录

这次练习全部放在主目录下的 `terminal-practice` 中：

```bash
mkdir -p ~/terminal-practice/first-session
cd ~/terminal-practice/first-session
pwd
```

最后一条命令应输出类似：

```text
/Users/student/terminal-practice/first-session
```

如果输出仍然是其他目录，不要继续创建文件，先重新检查上一条 `cd` 是否报错。终端中的相对路径会从当前目录开始计算，站错位置后继续操作，是新手最常见的错误之一。

现在运行：

```bash
ls -la
```

新目录通常只有 `.` 和 `..`。`.` 表示当前目录，`..` 表示上一级目录。

## 3. 创建文件和子目录，再亲自检查结果

在练习目录中执行：

```bash
touch notes.md
mkdir examples
cp notes.md notes-backup.md
mv notes-backup.md examples/
find . -print
```

可能看到：

```text
.
./examples
./examples/notes-backup.md
./notes.md
```

这里发生了四件事：`touch` 创建空文件，`mkdir` 创建目录，`cp` 复制文件，`mv` 把副本移动到 `examples`。最后的 `find` 从当前目录开始列出内容；这个练习目录很小，因此不需要依赖 GNU `find` 才支持的深度限制参数。你不需要立刻记住所有参数，只要能从输出确认文件确实出现在预期位置。

给 `notes.md` 写入一行文字：

```bash
printf '第一次终端练习完成。\n' > notes.md
cat notes.md
```

应看到：

```text
第一次终端练习完成。
```

`>` 会把输出写入文件，并覆盖文件原有内容。因为这里操作的是刚创建的练习文件，所以风险可控；在真实配置或代码文件上使用前，要先确认目标路径。查看较长文件时可以使用 `less FILE`，进入后按 `q` 退出。

## 4. 在目录之间移动

先进入子目录并确认位置：

```bash
cd examples
pwd
ls -la
```

返回上一级：

```bash
cd ..
pwd
```

回到主目录使用：

```bash
cd ~
```

回到刚才所在目录使用：

```bash
cd -
```

如果目录名包含空格，需要使用引号，例如：

```bash
mkdir "My Project"
cd "My Project"
```

更稳妥的输入方式是先键入目录名前几个字符，再按 Tab 让 zsh 补全。补全成功也说明当前目录中确实存在这个目标。

## 5. 输错路径时怎样判断

故意运行一个不存在的路径：

```bash
cd does-not-exist
```

你会看到类似：

```text
cd: no such file or directory: does-not-exist
```

这条报错没有破坏任何内容，只说明目录没有切换成功。此时运行：

```bash
pwd
ls -la
```

先确认自己仍在原目录，再检查拼写、大小写、空格和目标是否真实存在。不要在看到报错后连续猜十几个路径；先观察当前目录，通常更快。

## 6. 长命令输错时不用一直按退格

在普通 zsh 提示符中，可以先记住下面六个按键：

```text
Ctrl + A    移到行首
Ctrl + E    移到行尾
Ctrl + W    删除光标左侧一个单词
Ctrl + U    常见情况下清除当前输入
Ctrl + R    搜索以前输入过的命令
Ctrl + C    放弃当前输入，或中断正在运行的前台程序
```

快捷键可能被 Vi 模式、插件、tmux 或 AI CLI 的界面重新定义。本机使用 zsh 时，可以查看实际绑定：

```bash
bindkey '^U'
bindkey '^W'
```

现在可以做一个不执行的练习：输入一条较长命令，但先不要按回车。

```text
python3 very/long/path/example.py --output result.txt
```

尝试用 `Ctrl + A`、`Ctrl + E` 和 `Ctrl + W` 移动或删除内容，最后按 `Ctrl + C` 放弃这一行。只要还没按回车，命令就没有执行。

## 7. 程序卡住、暂停和清屏不是一回事

运行一个会持续输出的命令：

```bash
ping 127.0.0.1
```

看到输出后按 `Ctrl + C`，程序应停止并返回提示符。`Ctrl + C` 通常用于中断当前前台程序；它不会删除项目文件。

误按 `Ctrl + Z` 时，程序通常只是暂停。可以运行：

```bash
jobs
```

如果任务仍在列表中，使用 `fg` 把它恢复到前台，再按 `Ctrl + C` 正常中断。长时间任务需要 tmux、日志和 checkpoint，不能把普通后台运行当作可靠保护。

清理屏幕可以按 `Ctrl + L` 或执行 `clear`。这只会整理显示区域，不会删除历史命令、文件或已经执行过的操作。

## 8. 完成练习后留下什么

回到练习目录并检查：

```bash
cd ~/terminal-practice/first-session
pwd
find . -print
cat notes.md
```

本练习不要求删除目录。保留它可以供后面练习 Git 和 AI CLI 使用。现在你已经完成了最基本的一套循环：确认位置、执行小操作、查看输出、遇到错误时停下来检查。

日常进入项目时，可以先运行：

```bash
hostname
pwd
ls -la
git status
```

其中 `git status` 只有在 Git 项目中才有意义；普通目录显示“不是 Git 仓库”并不代表终端故障。
