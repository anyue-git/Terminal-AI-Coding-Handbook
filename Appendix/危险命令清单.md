# 危险命令与高权限操作清单

这份清单不是说下面的命令永远不能使用，而是提醒你：它们可能删除数据、覆盖文件、扩大权限、暴露服务或改写历史。执行前应明确目标、影响范围、验证方式和恢复方案。

---

## 1. 递归删除

```bash
rm -rf TARGET
```

风险来自：

- `-r` 递归进入子目录；
- `-f` 减少确认和报错；
- `rm` 通常不进入废纸篓；
- 相对路径、通配符和空变量可能放大错误。

执行前至少：

```bash
pwd
ls -la TARGET
du -sh TARGET
```

不确定时优先逐文件处理，或先移动到隔离目录。不要让 AI 自动批准递归删除。

---

## 2. 通配符和变量扩大范围

```bash
rm *.log
rm -rf *
rm -rf "$TARGET_DIR"
```

先预览匹配结果：

```bash
printf '%s\n' *.log
printf '<%s>\n' "$TARGET_DIR"
```

需要额外警惕：

- 当前目录与预想不同；
- 变量为空或包含意外路径；
- Shell 已经先展开通配符；
- `*` 通常不匹配隐藏文件，但这并不会让命令自动安全。

不要在未知目录运行 `rm -rf *`。

---

## 3. 覆盖写入与追加写入

```bash
COMMAND > FILE
COMMAND >> FILE
```

`>` 通常覆盖已有文件，`>>` 追加到末尾。二者都不会自动判断内容是否合理。

执行前：

```bash
ls -l FILE
```

重要配置可以先写入新文件：

```bash
COMMAND > FILE.new
diff FILE FILE.new
```

反复向 `.zshrc`、SSH Config、服务配置或环境文件追加内容，容易产生重复项和冲突。

---

## 4. 管理员权限与系统目录

```bash
sudo COMMAND
```

`sudo` 不会让错误命令变正确，只会扩大它能影响的范围。

看到 `Permission denied` 时先检查：

```bash
whoami
pwd
ls -ld TARGET
```

不要默认使用：

```text
sudo pip install
sudo brew install
递归 chmod/chown 整个用户目录
```

修改 `/etc`、系统服务、防火墙、驱动或 Docker daemon 前，应先备份配置并准备本机恢复入口。

---

## 5. Git 丢弃未提交修改

```bash
git restore .
git reset --hard TARGET
git clean -fd
```

可能丢失：

- 工作区修改；
- 暂存区修改；
- 未跟踪文件；
- 当前分支之后的提交引用。

执行前：

```bash
git status
git diff
git diff --cached
git log --oneline --decorate -10
```

清理未跟踪文件必须先预览：

```bash
git clean -n
git clean -nd
```

未被 Git 记录过的文件被删除后，Git 通常无法恢复。

---

## 6. Git 改写共享历史

```bash
git push --force
git push --force-with-lease
git rebase
git commit --amend
```

这些操作可能改变提交哈希。已经推送或多人共享的分支被改写后，其他人的本地历史可能分叉。

共享提交需要撤销时，通常优先考虑：

```bash
git revert COMMIT_SHA
```

`--force-with-lease` 比裸 `--force` 多一层检查，但仍然是历史改写，不应被当作普通推送。

---

## 7. 远程脚本直接执行

```bash
curl URL | sh
curl URL | sudo sh
```

这会把网络返回内容直接交给 Shell，第二种还同时授予管理员权限。

至少确认：

- URL 来自官方来源；
- HTTPS 域名正确；
- 当前官方文档仍推荐该方式；
- 脚本会创建或修改哪些文件；
- 是否需要管理员权限。

来源不明的安装命令不要因为“很多教程都这样写”就直接执行。

---

## 8. SSH 与防火墙修改

高风险操作包括：

```text
修改 sshd_config
关闭密码或公钥认证
删除整个 known_hosts
关闭 StrictHostKeyChecking
开放公网 TCP 22
重置全部防火墙规则
```

远程修改 SSH 服务时：

```text
保留当前会话
→ 备份配置
→ sudo sshd -t
→ reload 服务
→ 第二个终端测试
→ 成功后才关闭旧会话
```

不要把公网端口转发作为个人新手默认方案。局域网或 Tailscale 通常更容易控制暴露范围。

---

## 9. rsync 删除同步

```bash
rsync -av --delete SOURCE/ DESTINATION/
```

`--delete` 会删除目标端存在、但源端不存在的文件。源和目标写反，或源目录意外为空时，可能造成大量删除。

必须先运行：

```bash
rsync -av --delete --dry-run SOURCE/ DESTINATION/
```

同时确认源路径尾部 `/` 的含义。普通同步默认不需要 `--delete`。

---

## 10. Docker 高权限入口

高风险配置包括：

```text
--privileged
挂载 /var/run/docker.sock
挂载宿主机根目录
挂载整个 HOME
Host Network
注入真实 SSH 或云凭据
以 root 写入共享项目目录
```

Docker Socket 通常等价于很高的宿主机控制能力。不要把它挂给不可信容器或 AI 生成的任意代码。

容器共享宿主机内核，不是运行任意不可信代码的绝对安全边界。

---

## 11. Docker 数据与清理

```bash
docker compose down -v
docker system prune
docker volume prune
docker image prune -a
```

其中 `down -v` 可能删除 Compose 管理的命名卷，数据库和其他持久数据可能随之消失。

清理前检查：

```bash
docker ps -a
docker volume ls
docker image ls
docker system df
```

不要把 prune 当作解决所有 Docker 故障的第一步。

---

## 12. 进程强制终止

```bash
kill -9 PID
pkill python
pkill -f PATTERN
```

强制终止不给程序保存和清理的机会；名称或模式匹配还可能结束其他项目甚至其他用户的进程。

先检查：

```bash
pgrep -fl PATTERN
ps -p PID -o pid,user,command
```

普通停止优先使用 `Ctrl + C` 或 `kill PID`。不要停止不属于自己的 GPU、数据库或服务进程。

---

## 13. AI 自动批准和关闭隔离

任何类似下面含义的模式都不应作为日常默认：

```text
跳过审批
完全权限
关闭 Sandbox
危险模式
自动同意所有命令
```

批准前检查：

- 当前机器和目录；
- 可读写文件范围；
- 是否使用网络；
- 是否读取凭据；
- 是否修改 Git、服务、Docker 或驱动；
- 是否存在删除、覆盖或上传；
- 怎样停止和回滚。

自动化任务还应限制最大轮数、超时、输出位置和失败条件。

---

## 14. 凭据与认证信息

不要分享、提交或交给不可信工具：

```text
API Key
SSH 私钥
浏览器 Cookie
Session Token
Refresh Token
云服务凭据
Claude Code 或其他工具的认证缓存
.env 中的真实秘密
```

秘密一旦进入 Git 历史或第三方日志，仅删除文件通常不够。应立即撤销或轮换凭据，并检查传播范围。

---

## 15. 执行危险操作前的通用检查

```text
我在哪台机器？
我在哪个目录？
目标路径实际是什么？
会不会匹配多个对象？
会覆盖、删除、上传或改写历史吗？
是否有备份、Git 提交或恢复入口？
能否先 dry-run、预览或只读检查？
怎样确认成功？
怎样停止？
```

看不懂其中任意一项时，先停下来。高风险命令最需要的不是勇气，而是上下文。
