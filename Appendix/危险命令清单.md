# 危险命令与高权限操作清单

> 最近核对：2026-07-30

这份清单不是说下面的命令永远不能使用，而是提醒你：同一条命令在不同机器、目录、用户和参数下，影响范围可能完全不同。高风险操作开始前，应当能够回答：目标是什么、会影响哪些对象、能否预演、怎样确认成功、失败后怎样恢复。

## 1. 递归删除

```bash
rm -rf TARGET
```

风险来自：

- `-r` 会递归进入子目录；
- `-f` 会减少确认和部分报错；
- `rm` 通常不进入废纸篓；
- 相对路径、通配符、符号链接和变量展开都可能改变真实目标。

执行前至少查看：

```bash
hostname
pwd
ls -ld TARGET
du -sh TARGET
```

变量作为目标时，先单独显示展开结果：

```bash
printf 'TARGET=<%s>\n' "$TARGET_DIR"
```

不要让 AI 自动批准项目目录之外的递归删除。不能确认内容时，优先先移动到隔离目录，确认一段时间后再删除。

## 2. 通配符、变量和命令替换扩大范围

```bash
rm *.log
rm -rf *
rm -rf "$TARGET_DIR"
COMMAND "$(OTHER_COMMAND)"
```

Shell 可能在程序启动前已经展开通配符和命令替换。先预览：

```bash
printf '%s\n' *.log
printf '<%s>\n' "$TARGET_DIR"
```

特别警惕：

- 当前目录与预想不同；
- 变量为空、包含换行或指向根目录；
- `*` 匹配大量文件；
- 文件名以 `-` 开头，被程序误认成参数；
- 子命令输出被直接拼进破坏性命令。

删除具体文件时可使用 `--` 结束参数解析，例如：

```bash
rm -- "-strange-name"
```

这不能修复错误路径，只能避免文件名被解释成选项。

## 3. `find -delete`、`xargs` 与批量操作

```bash
find TARGET -type f -delete
find TARGET -type f -print0 | xargs -0 rm
```

它们可以在很短时间处理大量文件。正式删除前，把动作改成打印：

```bash
find TARGET -type f -print
```

确认目录、条件和匹配数量后再决定是否删除。不要把 `find` 的条件顺序、最大深度和目标目录当作无关细节；一个条件写错，范围可能从某个缓存目录扩大到整个项目。

## 4. 覆盖写入、移动和复制

```bash
COMMAND > FILE
cp SOURCE DESTINATION
mv SOURCE DESTINATION
```

`>` 会截断已有文件，`cp` 和 `mv` 在某些情况下会覆盖同名目标。重要配置先写入新文件：

```bash
COMMAND > FILE.new
diff -u FILE FILE.new
```

复制或移动前检查：

```bash
ls -ld SOURCE DESTINATION
```

需要保留旧文件时，先制作带时间戳的备份：

```bash
cp FILE "FILE.backup.$(date +%Y%m%d-%H%M%S)"
```

备份中可能包含凭据，仍需限制权限并在确认恢复完成后安全清理。

## 5. 反复追加配置

```bash
COMMAND >> ~/.zshrc
COMMAND >> ~/.ssh/config
```

`>>` 不会判断内容是否已存在。反复追加可能产生重复 PATH、冲突的环境变量和多条 SSH 通配规则。

修改前先定位现有内容：

```bash
grep -n 'KEYWORD' ~/.zshrc
```

修改后应重新加载并验证实际结果，而不是只确认文件末尾多了一行：

```bash
exec zsh
command -v COMMAND
```

SSH Config 使用：

```bash
ssh -G HOST_ALIAS | sed -n '1,40p'
```

## 6. 管理员权限、递归权限修复和系统目录

```bash
sudo COMMAND
chmod -R MODE TARGET
chown -R USER:GROUP TARGET
```

`sudo` 不会让错误命令变正确，只会扩大它能影响的范围。递归 `chmod` 或 `chown` 可能破坏可执行位、私钥权限、系统文件所有者和应用数据。

看到 `Permission denied` 时先检查：

```bash
whoami
pwd
ls -ld TARGET
namei -l TARGET 2>/dev/null || true
```

不要默认使用：

```text
sudo pip install
sudo brew install
chmod -R 777
递归修改整个 HOME 的所有者
```

修改 `/etc`、系统服务、防火墙、SSH、内核模块或 NVIDIA 驱动前，应准备配置备份、本机控制台和恢复步骤。

## 7. Git 丢弃工作区、暂存区或未跟踪文件

```bash
git restore .
git reset --hard TARGET
git clean -fd
git clean -fdx
```

可能丢失：

- 未暂存的已跟踪修改；
- 暂存区修改；
- 未跟踪文件；
- 被忽略的本地配置、环境或构建文件；
- 当前引用之后暂时不可见的提交。

执行前：

```bash
git status
git diff
git diff --cached
git log --oneline --decorate -10
```

清理必须先预览：

```bash
git clean -n
git clean -nd
git clean -ndx
```

`-x` 会把 `.gitignore` 中的文件也纳入清理，可能删除 `.env`、本地模型、构建缓存或其他未提交内容。未被 Git 记录过的文件被删除后，Git 通常无法恢复。

## 8. Git 改写共享历史

```bash
git push --force
git push --force-with-lease
git rebase
git commit --amend
```

这些操作可能改变提交哈希。已经推送或多人共享的分支被改写后，其他人的本地历史会分叉。

共享提交需要撤销时，通常优先评估：

```bash
git revert COMMIT_SHA
```

`--force-with-lease` 会检查远端引用是否仍符合本地预期，比裸 `--force` 多一层保护，但它仍是历史改写。AI 不应在没有明确分支、远端状态和人工确认时执行强制推送。

## 9. 远程脚本直接执行

```bash
curl URL | sh
curl URL | sudo sh
```

这会把网络返回内容直接交给 Shell，第二条还同时授予管理员权限。至少确认：

- URL 来自当前官方文档；
- HTTPS 域名正确；
- 脚本是否经过重定向；
- 会创建或修改哪些文件；
- 是否会安装自动更新或后台服务；
- 是否真的需要管理员权限。

能够先下载检查时：

```bash
curl -fsSL URL -o /tmp/installer.sh
less /tmp/installer.sh
```

大型官方安装脚本不一定容易完整审计，但先保存至少能确认来源、头部说明和明显的高风险动作。来源不明的命令不要因为“群里很多人用”就直接执行。

## 10. 包管理器的批量升级、精确同步和环境重建

下面这些操作可能改变大量依赖：

```bash
brew upgrade
python -m pip install -U PACKAGE
uv lock --upgrade
uv sync
conda update --all
```

风险不只来自安装失败，还包括：

- 锁文件大范围变化；
- 间接依赖升级；
- 本地未声明包被移除；
- 原生扩展重新编译；
- CUDA、Python 或系统库兼容性改变。

当前 uv 的项目同步默认采用精确同步，会移除锁文件中没有声明的额外包。使用前查看：

```bash
uv lock --check
uv sync --help
git diff -- pyproject.toml uv.lock
```

项目已有锁文件时，普通复现应优先使用项目规定的锁定参数；升级依赖应作为独立任务审查，不与普通 Bug 修复混在一起。

## 11. SSH 与防火墙修改

高风险操作包括：

```text
修改 sshd_config 或 sshd_config.d
关闭密码或公钥认证
删除整个 known_hosts
关闭 StrictHostKeyChecking
开放公网 TCP 22
重置全部防火墙规则
```

远程修改 SSH 服务时固定采用：

```text
保留当前会话和本机控制台
→ 备份配置
→ sudo sshd -t
→ reload 服务
→ 第二个终端测试新连接
→ 成功后才关闭旧会话
```

不要把公网端口转发作为个人新手默认方案。同一局域网或 Tailscale 加普通 OpenSSH 通常更容易控制暴露范围。

## 12. rsync 删除、覆盖和方向写反

```bash
rsync -av --delete SOURCE/ DESTINATION/
```

`--delete` 会删除目标端存在、但源端不存在的文件。源和目标写反，或源目录意外为空时，可能造成大量删除。

必须先运行：

```bash
rsync -av --delete --dry-run SOURCE/ DESTINATION/
```

同时确认：

- 当前机器；
- 源与目标方向；
- 源路径尾部 `/` 的含义；
- 排除文件是否生效；
- 目标端是否有独立生成的数据；
- dry run 中的删除列表。

普通源码同步默认不需要 `--delete`。

## 13. 网络服务监听到所有接口

```text
0.0.0.0
::
```

服务监听回环地址 `127.0.0.1` 时，通常只有本机能直接访问；监听 `0.0.0.0` 或 `::` 可能让局域网、Tailscale 网络或公网路径上的设备访问。

特别注意：

- Jupyter；
- TensorBoard；
- 开发服务器；
- 本地模型 API；
- Cockpit Tools 等本地网关；
- 无认证调试端口。

检查监听：

```bash
ss -lntp 2>/dev/null || lsof -nP -iTCP -sTCP:LISTEN
```

远程访问优先让服务监听 `127.0.0.1`，再通过 SSH 本地端口转发。不能只因为端口“暂时没人知道”就认为安全。

## 14. Docker 高权限入口

高风险配置包括：

```text
--privileged
挂载 /var/run/docker.sock
挂载宿主机根目录
挂载整个 HOME
Host Network
注入真实 SSH 或云凭据
以 root 写入共享项目目录
```

Docker Socket 通常意味着很高的宿主机控制能力。不要把它挂给不可信容器、任意插件或未经审查的 AI 生成代码。

容器共享宿主机内核。即使没有 `--privileged`，Bind Mount、网络、设备和凭据挂载仍会显著扩大影响范围。

## 15. Docker 数据删除和批量清理

```bash
docker compose down -v
docker system prune
docker system prune -a --volumes
docker volume prune
docker image prune -a
```

`docker compose down -v` 会删除 Compose 声明的命名卷和附加的匿名卷；数据库和其他持久数据可能随之消失。

清理前检查：

```bash
docker ps -a
docker volume ls
docker image ls
docker system df
docker compose config
```

重要 Volume 先确认备份和恢复命令。不要把 prune 当作解决端口冲突、容器退出或镜像构建失败的第一步。

## 16. 磁盘、分区和文件系统命令

下面类型的命令可能直接破坏磁盘数据：

```text
dd 写入块设备
mkfs 创建文件系统
磁盘分区工具的写入操作
mount 到错误目标
清空或覆盖双系统分区
```

操作前必须通过系统工具确认设备名、容量、挂载点和分区用途。你的 Windows 11 与 Ubuntu 双系统位于不同硬盘时，也不能只凭 `/dev/sda`、`/dev/nvme0n1` 的顺序猜测哪块盘是什么。设备顺序可能变化。

这类操作不应交给 Agent 自动执行。先备份数据，并保留可启动的恢复介质。

## 17. 进程批量终止和强制信号

```bash
kill -9 PID
pkill python
pkill -f PATTERN
killall PROCESS_NAME
```

强制终止不给程序保存和清理的机会；名称或模式匹配还可能结束其他项目甚至其他用户的进程。

先检查：

```bash
pgrep -af PATTERN
ps -p PID -o pid,user,etime,command
nvidia-smi
```

普通停止优先使用程序自己的退出方式、`Ctrl + C` 或 `kill PID`。不要停止不属于自己的 GPU、数据库、远程服务或桌面图形进程。

## 18. AI 自动批准、关闭隔离和高权限远程执行

任何类似下面含义的模式都不应作为日常默认：

```text
跳过审批
完全文件系统权限
关闭 Sandbox
自动同意所有工具调用
允许任意网络访问
在远程主机执行任意 sudo
```

自动批准减少的是确认步骤，不会自动限制：

- 当前用户本来就能访问的文件；
- Docker Socket；
- SSH 密钥和云凭据；
- MCP、Hook 和 Plugin；
- 数据集和模型目录；
- 远程机器或生产服务。

自动化任务还应限制最大轮数、超时、工作目录、输出位置和失败条件。高权限模式只在隔离环境、明确任务和可恢复数据上短时使用。

## 19. 配置切换工具与凭证替换

CC Switch、ccswitch、Cockpit Tools 或其他管理工具可能：

- 改写 `config.toml`、`settings.json`；
- 替换 `auth.json` 或 Keychain 中的凭证；
- 修改 Base URL；
- 启动本地代理；
- 轮换上游账号；
- 读取 Prompt、源码和请求日志。

切换前确认备份和恢复入口。工具仍在运行并监视配置时，不要同时手工覆盖 live 文件。恢复官方配置后检查：

```text
本地代理是否停止
Base URL 是否恢复
官方登录是否仍有效
Shell 中是否残留环境变量
客户端重启后实际 Provider 是否正确
```

## 20. 凭据与认证信息

不要分享、提交或交给不可信工具：

```text
API Key
Access Token
SSH 私钥
浏览器 Cookie
Session Token
Refresh Token
云平台凭据
AI CLI 认证缓存
.env 中的真实秘密
Tailscale 登录或设备授权链接
```

秘密一旦进入 Git 历史、聊天、截图或第三方日志，仅删除本地文件通常不够。应立即撤销或轮换凭据，并检查提交历史、远程仓库、CI 日志和共享渠道中的传播范围。

## 21. 执行高风险操作前的通用检查

```text
我在哪台机器？
我以哪个用户运行？
我在哪个目录？
完整命令展开后是什么？
目标路径或服务实际是什么？
会匹配多少对象？
会覆盖、删除、上传或改写历史吗？
是否影响远程机器或其他用户？
有没有备份、Git 提交、checkpoint 或本机控制台？
能否先 dry run、预览或只读检查？
成功后怎样验证？
失败后怎样停止和恢复？
```

看不懂其中任意一项时，先停下来。高风险命令需要的是上下文和恢复能力，不是更快按下回车。
