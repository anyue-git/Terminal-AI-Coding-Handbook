## 2026-07-30：建立自动发布审计

为把“发布前再检查一次”变成可重复流程，本轮新增：

- `scripts/audit_sensitive_patterns.py`：扫描当前文件树和完整 Git 补丁历史中的高置信度凭据特征，输出时只保留规则、位置、长度和短指纹；
- `scripts/audit_external_links.py`：忽略代码块与占位域名，检查公开快照中的外部链接，404/410 才作为阻断死链；
- `.github/workflows/source-release-audit.yml`：克隆当前公共仓库，真实执行 `scripts/export_public.sh --dry-run`，验证公共 clone 未变化，构建隔离公开快照并再次执行 Markdown、敏感信息与外部链接检查；
- `.publishignore` 新增源仓库专用工作流排除规则，避免该工作流进入公共快照；
- 新建[V3.0 发布说明草案](../RELEASE_NOTES_V3.0.md)，并确认当前 LICENSE 使用 CC BY-NC-SA 4.0 与 MIT 双许可证。

阶段性实际审计结果：当前树的 90 余个文本文件与约 10 万行 Git 历史新增内容均为 0 个高置信度敏感信息发现；真实导出预演成功且没有删除项，公共 clone 提交和工作区保持不变；隔离公开快照包含 80 余个 Markdown 文件，严格检查为 0 个错误、0 个警告；快照敏感扫描为 0 个未豁免发现；去重后的 60 个外部链接全部正常，没有确认死链、网络未知或反爬限制。

精确文件数、历史行数和导出差异数会随 PR 维护变化；后续每次 PR 更新都会重新执行两条工作流，最终状态以 PR checks 和最终公共导出 diff 为准。
