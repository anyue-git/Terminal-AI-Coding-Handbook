# V3.0 批次二内容覆盖记录

本记录覆盖“开发基础设施”批次：Part 04 Git、Part 05 SSH、Part 06 Homebrew、Part 07 Python 环境和 Part 08 Docker，共 17 篇正文。《Git 心智模型》已在样章阶段完成，其余 16 篇在本批次深度重写。所有章节均先重新划分职责，再重写段落和代码块衔接，没有使用脚本机械合并自然段。

## 1. Git：从状态模型到协作边界

四章分别承担 Git 心智模型、日常提交、恢复层次和 PR 协作。工作区、暂存区、提交、分支和远程的核心定义保留；`git status`、各类 diff、精确暂存、cached diff、测试、提交后复核和推送前检查仍组成完整日常链。

恢复章保留可控冲突、`git merge --abort`、`git restore --staged`、普通 restore、交互恢复、revert、amend、`git clean -n`、reflog、救援分支及强制历史操作风险。不同命令按问题发生在工作区、暂存区、合并状态、本地提交或共享历史重新组织，不再每种命令单独重复一套安全开场。

PR 章保留三点号分支差异、推送、PR 描述、Draft、CI 与人工审查职责、Review Comment 分类、同一分支更新、合并策略、合并后本地同步和 worktree 并行边界。旧文中“V2.0 Draft PR”的状态性示例改为当前 V3.0，属于项目状态同步。

## 2. SSH：按连接链划分四章职责

首次连接章保留 Ubuntu 安装与启用 sshd、地址和默认路由判断、Mac 端口测试、主机指纹核对、密码登录、远程环境确认、连接逃逸、防火墙和服务端配置安全流程。命令运行位置继续明确区分 Ubuntu 本机、Mac 和远程 Shell。

密钥章保留用户私钥/公钥、服务器主机密钥、`known_hosts` 与客户端 Config 的区别；专用 Ed25519 密钥、passphrase、公钥安装、文件权限、旧会话保留、`IdentitiesOnly`、`ssh -G`、局域网/异网别名、ssh-agent、Keychain、Agent Forwarding 风险和主机身份变化处理均保留。

传输章保留 scp 方向与端口选项、rsync 两端要求、`--dry-run`、末尾斜杠、排除文件、`.git` 与 `.venv` 边界、`--delete` 风险、训练结果回传、磁盘空间与本地端口转发。故障章按客户端目标、名称解析、超时、拒绝连接、主机身份、用户认证、远程 PATH 和上层工具逐层排查，避免针对每条报错重复完整模板。

## 3. Homebrew：命令来源与后台服务分开讲

第一章保留 Mac 架构、默认前缀、官方安装边界、`brew shellenv`、zsh 启动文件、PATH、`type -a`、双架构 Homebrew、Formula/Cask/keg-only、ripgrep 完整安装验证、升级、卸载、cleanup 预演和 `brew doctor`。主线从“是否安装”升级为“当前 Shell 实际运行哪一个文件”。

第二章保留 Formula/Cask/Service 区别、`brew services`、端口与协议验证、可选 Redis 练习、start/run/stop/restart 边界、started 但服务不可用、端口冲突、用户级与 sudo 服务、多版本、link/unlink、pin 和升级后数据迁移风险。服务状态、真实进程、端口和协议被组织成一条诊断链。

## 4. Python：解释器、工具选择和复现各讲一层

解释器章保留 `type -a`、`command -v`、`sys.executable`、prefix、`python -m pip`、venv 激活与直接路径、受控 `ModuleNotFoundError`、同名模块遮蔽、`sys.path`、pip 快照、禁止 `sudo pip` 及 Mac/Ubuntu 分别创建环境。

工具选择章保留 venv、Conda 与 uv 的职责表和独立示例；Conda Channel、base 环境、环境文件与新版锁文件，uv 的 `pyproject.toml`、`uv.lock`、精确同步、`--locked` 与升级命令均保留。2026-07 技术核对标记继续存在，防止快速变化的默认行为被写成永久事实。

复现章保留声明、锁文件和环境快照区别，直接/传递依赖，requirements、`pyproject.toml`、`pip freeze`、venv、uv、Conda、多平台和 GPU 差异、干净环境验证、秘密来源与锁文件 diff 审查。环境目录仍明确不得跨平台复制。

## 5. Docker：对象、宿主结构、Compose 与 GPU 各自负责

核心对象章继续使用 Python Web 服务，保留 Client/Server、镜像与容器、Dockerfile、构建上下文、端口绑定、重建与 Bind Mount、可写层、Named Volume、localhost、日志和逐对象清理。Volume 独立生命周期不被描述成备份，Bind Mount 的宿主文件风险继续保留。

Mac/Ubuntu 章保留 Docker Context、`DOCKER_HOST`、Docker Desktop Linux VM、Ubuntu Engine 与 Socket、docker 组权限、多架构镜像、模拟限制、Bind Mount 性能与文件所有权、端口方向和数据位置。禁止 `chmod 666` Socket、删除 `/var/lib/docker` 和把 Socket交给不可信容器等边界没有弱化。

Compose 章保留 V2 命令、完整 Nginx/PostgreSQL/db-check/Adminer 示例、`docker compose config`、前后台生命周期、服务名 DNS、端口、Healthcheck、Bind Mount/Volume、exec/run、Profiles、变量与秘密、镜像更新和 `down -v` 风险。

GPU 章保留宿主驱动、Docker daemon、NVIDIA Container Toolkit、最小 CUDA 容器、PyTorch 镜像和项目代码六层验证；`daemon.json` 备份、重启中断、GPU 数量/设备限制、驱动能力、Compose reservation、宿主与容器 CUDA 数字区别、挂载与用户权限、Socket 与 privileged 风险均保留。

## 6. 删除、合并与事实边界

本批次主要删除重复的“运行/查看/可能看到”短引导、同一检查清单在相邻章节的复制、每个参数独立成节的卡片结构，以及已经在主讲章节完整解释的通用安全模板。独特命令、典型输出、错误分类、恢复手段、平台差异、数据与权限边界均保留或明确迁移到职责更合适的位置。

除 PR 中项目状态示例更新外，本批次没有把外部工具事实校验与文风重构混为一谈。Conda、uv、Homebrew、Docker 与 NVIDIA 等快速变化内容仍要求读者结合本机帮助和官方文档，不宣称所有命令已在真实设备重新验证。
