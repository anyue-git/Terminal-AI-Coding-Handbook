# V3.0 样章内容覆盖记录

本记录用于证明第一阶段的三篇样章不是通过简单删减获得更短版面。重写时逐项核对原有命令、技术结论、输出示例、错误恢复和安全边界，并将每项处理归入保留、合并表达、移动位置、删除重复或事实修正。

## 1. 《终端十五分钟上手》

原章八个操作小节重组为五个连续阶段：确认环境、安全目录中的文件操作、目录移动与命令编辑、错误与前台程序处理、最终检查与日常习惯。

### 保留内容

- `hostname`、`whoami`、`pwd` 的运行场景、示例输出和远程机器提醒；
- `ls`、`ls -la` 与隐藏文件说明；
- `mkdir -p`、`cd`、`touch`、`mkdir`、`cp`、`mv`、`find` 的连续练习；
- `printf > notes.md` 的覆盖风险、`cat` 和 `less` 的使用边界；
- `cd ..`、`cd ~`、`cd -`、含空格目录与 Tab 补全；
- `Ctrl + A/E/W/U/R/C`、`bindkey` 和不按回车的输入练习；
- `cd does-not-exist` 的错误示例，以及用 `pwd`、`ls -la` 重新确认；
- `ping`、`Ctrl + C`、`Ctrl + Z`、`jobs`、`fg`、`Ctrl + L` 和 `clear`；
- 练习目录最终检查、保留目录的理由，以及进入真实项目时的启动命令。

### 合并与删除

“在终端依次运行”“接着查看”“现在运行”“可能看到”“应看到”等短引导被合并进有场景和目的的完整段落。原有八个小节没有对应八个独立信息问题，因此按操作流程重组；没有删除独特命令或错误恢复。

## 2. 《Git 心智模型》

原章十个小节重组为六个问题：工作区、暂存区、提交历史、精确暂存与分支、Git 与远程及恢复边界、AI CLI 的 Git 边界。

### 保留内容

- 练习目录、`git init`、初始化输出、`.git` 目录和作者身份说明；
- `calculator.py`、`test_calculator.py`、单元测试和 `??` 状态示例；
- 工作区定义，以及文件存在不等于已被 Git 保存；
- `git add`、`git diff --cached`、暂存后继续编辑同一文件的观察实验；
- `git commit`、`git log`、提交只发生在本地和工作区—暂存区—历史关系；
- `notes.txt` 与减法函数的混合现场、精确暂存和 `git add .` 风险；
- `git restore --staged` 不删除工作区修改；
- `git switch -c feature/subtraction`、分支、`HEAD`、提交关系图和未提交修改跟随工作区；
- 本地命令与远程命令的区别、`git remote -v` 和 `origin` 的含义；
- Git 能恢复和不能恢复的对象，尤其是未跟踪文件；
- AI CLI 开始前的状态检查、禁止的 Git 写操作和结束后的 diff 复核；
- 供下一章继续使用的最终练习状态。

### 合并与删除

多个“创建—查看—可能看到”的微型步骤被组织进连续实验。原章关于工作区、暂存区和提交的重复定义被保留在最合适的位置，其余位置改成承接关系；没有改变练习命令的核心顺序，也没有把 Git 写操作交给 Agent。

## 3. 《通用 AI 编程闭环》

原章十六个阶段重组为六个完整环节：任务与基线、调查与方案、隔离与实施、证据与差异、独立复核与人工提交、停止条件与复用模板。

### 保留内容

- 从完成标准到独立复核和人工提交的闭环；
- 制表符解析 Bug 的贯穿案例；
- 目标、预期行为、允许修改、禁止修改和验收标准任务单；
- 机器、用户、目录、分支、工作区、HEAD 和基线测试记录；
- 未提交修改不会因新建分支自动隔离的提醒；
- 只读调查 Prompt、入口/实现/测试/调用方检查，以及事实、推测、未知分类；
- 最小修复、整体重写和暂不修改三类方案，以及选择理由和文件级计划；
- `fix/parser-tab-handling` 分支与 Git 无法覆盖的外部副作用；
- 先写失败测试、无效失败类型和有效失败证据；
- 限定生产代码范围的小批实施 Prompt；
- 由小到大的测试命令、完整测试报告和“阅读不等于运行”的边界；
- `git status`、各类 `git diff`、范围外修改检查和暂存区/分支比较；
- 需求、基线、事实、修改、验证、未知和风险组成的证据账本；
- 新会话只读复核 Prompt，以及必须修复、需要确认、可选改进和误报分类；
- 人工精确暂存、检查、提交和提交后验证；
- 停止条件、通用任务模板和闭环各环对应关系。

### 合并与删除

十六个阶段标题造成的重复开场和总结被合并，多个只包含一段 Prompt 与一句解释的小节被放回所属环节。相同的“不要自动扩大范围”“证据优先于总结”只在关键位置完整解释，其余位置通过上下文承接。没有删除原章中的关键 Prompt、Git 命令、测试证据格式或停止条件。

三篇样章合计减少 57 个普通自然段、68 个微型段落和 82 个短段落。与此同时，普通正文字符增加 1721 个，说明本轮不是把原文压缩成速查表，而是在减少碎片的同时补足段落之间的解释和因果关系。代码块与标题的减少主要来自合并重复展示和过细分节，关键命令、输出格式和恢复方式仍按上面的覆盖清单保留。

《通用 AI 编程闭环》的平均段长上升幅度最大，因此后续人工阅读要特别检查是否出现过长段落。当前最长连续短段从 26 降至 2，薄小节从 10 降至 0，说明章节不再依靠大量微型阶段推进；但最终是否采用这一风格，仍应以实际阅读感受和内容查找效率为准。

## 5. 第一阶段结论

三篇样章的处理方式都是重新设计章节结构，再重写段落和过渡，而不是运行脚本自动合并。叙事审计用于比较短段、薄小节和空引导的变化；技术内容是否完整仍以本覆盖记录、Git diff 和人工复核为准。

后续批次应继续维护同样的覆盖原则。若某项内容被移动到其他章节，记录中必须写出目标位置；若因错误或过时而修正，需要单独说明事实依据，不能把技术变更隐藏在文风重构中。
