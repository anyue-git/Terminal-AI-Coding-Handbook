## 3. 终端基础审查

已经校准：

- Terminal、Shell、zsh、TUI 和具体命令不是同一层；
- 当前工作目录决定相对路径和多数命令作用位置；
- zsh 按键以实际 `bindkey` 为准；
- `Ctrl + U`、`Ctrl + D`、`Ctrl + Z` 不被过度简化；
- 通配符通常由 Shell 在程序执行前展开；
- `>` 覆盖、`>>` 追加，管道默认只传 stdout；
- 后台运行、脱离终端和可靠长任务是不同概念；
- macOS BSD 工具与 GNU/Linux 参数差异不被假定为完全一致；
- 快捷键速查表明确 tmux 前缀后使用小写 `d/c/n/p/w`。

基础章节已经加入练习目录、代表性输出、路径错误和停止方法。仍建议在真实 macOS zsh 上抽样执行快捷键和 BSD 命令。

## 4. Git 审查

正文统一使用：

```text
工作区
→ 暂存区
→ 本地提交
→ 远程仓库
```

已经确认：

- `git add` 不是上传；
- `git commit` 不会自动推送；
- 分支是提交引用，不是完整项目副本；
- `git diff`、`git diff --cached`、`git diff HEAD` 范围明确；
- 不把 `git add .` 写成无条件新手默认；
- `restore`、`revert`、`reflog` 和 reset 针对不同恢复层；
- `reset --hard`、`clean -fdx` 和强制推送具有明确风险；
- Agent 默认不执行 add、commit、push 或历史改写；
- 多 Agent 使用独立 Worktree 或只读复核；
- 实验快照使用 `git diff --binary HEAD` 记录已跟踪修改，并单独列出未跟踪文件。

未跟踪文件正文不会自动进入补丁，这一点已在 GPU 实验记录和端到端案例中说明。

## 5. SSH、网络与远程访问审查

排查顺序统一为：

```text
设备在线
→ 地址或名称
→ 网络路径
→ TCP 端口
→ SSH 服务
→ 主机身份
→ 用户认证
→ 远程 Shell 环境
```

已经确认：

- 首次连接需要核对主机指纹；
- 主机密钥变化不能通过删除全部 `known_hosts` 粗暴处理；
- 私钥留在可信客户端，公钥进入 `authorized_keys`；
- `IdentitiesOnly yes` 用于限制实际尝试的身份文件；
- Agent Forwarding 不作为普通默认；
- 修改 sshd 前运行 `sshd -t` 并保留旧会话；
- 不把公网 TCP 22 作为个人新手异网方案；
- 异网主线是 Tailscale + 普通 OpenSSH；
- MagicDNS 不代替主机身份验证；
- Jupyter、TensorBoard 和本地 API 通过 SSH 本地转发；
- `0.0.0.0` 和回环监听的暴露范围已进入术语和危险命令附录；
- rsync 尾部斜杠、排除规则和 `--delete` 风险明确。

## 6. Homebrew、Python 与依赖审查

已经确认：

- Homebrew 不使用 `sudo brew`；
- PATH 问题先判断实际命令来源，不连续追加配置；
- Python 先通过 `sys.executable` 确认解释器；
- 项目中优先使用 `python -m pip`；
- 不推荐 `sudo pip install`；
- venv、Conda 和 uv 的职责分开；
- `.venv` 和 Conda 环境不在 Mac 与 Ubuntu 间复制；
- 共享源码、依赖声明、锁文件和测试；
- `pip freeze` 是环境快照，不自动等于项目声明；
- uv 可能管理 Python；
- 当前 `uv sync` 默认精确同步，可能移除锁文件外的包；
- uv、Conda 和安装渠道的具体参数以当前帮助为准；
- Agent 不擅自迁移依赖管理工具或升级全部依赖。

## 7. Docker 与 GPU 容器审查

已经确认：

- Image、Container、Volume、Bind Mount、Network 和 Context 分层明确；
- macOS Docker Desktop 通过 Linux 虚拟机运行 Linux 容器；
- Ubuntu Docker Engine 直接运行于 Linux 宿主机；
- Docker Socket 和 docker 组属于高权限能力；
- 容器不是完整虚拟机或任意不可信代码的绝对边界；
- 不默认挂载整个 HOME、SSH、云凭据或 Docker Socket；
- Compose 使用 `docker compose` 与 Compose Specification；
- 不把“Compose v2”写成永久唯一实现代际；
- 顶层 `version` 不是新文件必需字段；
- `depends_on` 不自动等于服务健康；
- `down -v` 和 prune 有数据删除风险；
- GPU 容器按宿主驱动、Container Toolkit、容器框架三层验证；
- GPU 访问通常不需要 `--privileged`。
