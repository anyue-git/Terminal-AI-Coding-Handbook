## 3. 终端基础审查

已经校准：

- Terminal、Shell、zsh 和命令不是同一层；
- 当前工作目录决定相对路径和多数命令作用位置；
- zsh 的按键行为以实际 `bindkey` 为准；
- `Ctrl + U`、`Ctrl + D`、`Ctrl + Z` 不再被过度简化；
- 通配符通常由 Shell 在命令执行前展开；
- `>` 覆盖、`>>` 追加，管道默认只传 stdout；
- 后台运行、脱离终端和长期可靠运行是不同概念；
- macOS BSD 工具与 GNU/Linux 选项差异不被假定为完全一致。

附录已经移除星级“推荐指数”，避免用主观评分代替适用条件。

## 4. Git 审查

正文统一使用以下模型：

```text
工作区
→ 暂存区
→ 本地提交
→ 远程仓库
```

已经确认：

- `git add` 不是上传；
- `git commit` 不会自动推送；
- 分支是提交引用，不是项目副本；
- `git status`、`git diff`、`git diff --cached` 分工明确；
- 不把 `git add .` 写成新手默认；
- `restore`、`revert`、`reflog` 针对不同恢复层；
- `reset --hard`、`clean -fd`、强制推送均有明确风险；
- AI 默认不执行 `add`、`commit`、`push` 或历史改写；
- 多 Agent 使用独立分支或 Worktree，并由人工完成集成。

## 5. SSH 与远程访问审查

已经统一为分层排查：

```text
设备在线
→ 地址或名称
→ 网络路径
→ TCP 端口
→ 主机身份
→ 用户认证
→ 远程环境
```

已经确认：

- 首次连接需要核对主机指纹；
- 主机密钥变化不能靠删除全部 `known_hosts` 解决；
- 私钥只留在可信客户端，公钥进入 `authorized_keys`；
- `IdentitiesOnly yes` 用于限制实际尝试的身份文件；
- Agent Forwarding 不作为普通默认；
- 修改 sshd 配置前先 `sshd -t`，并保留旧会话；
- 不把公网 22 端口转发作为个人新手默认；
- 异网主线为 Tailscale + 普通 OpenSSH；
- Jupyter 和本地开发服务通过 SSH 本地转发访问；
- rsync 的尾部斜杠和 `--delete` 风险已经说明。

## 6. Python 与依赖环境审查

已经确认：

- 先通过 `sys.executable` 确认解释器；
- 项目中优先使用 `python -m pip`；
- 不推荐 `sudo pip install`；
- venv、Conda 和 uv 的职责分开解释；
- `.venv` 和 Conda 环境目录不在 Mac 与 Ubuntu 间复制；
- 共享源码、依赖声明、锁文件和测试；
- `pip freeze` 只是环境快照，不自动等于理想依赖声明；
- uv 和 Conda 的具体参数按当前 `--help` 验证；
- AI 不擅自迁移项目的依赖管理工具。

## 7. Docker 与 GPU 容器审查

已经确认：

- Docker Image、Container、Volume、Bind Mount 和 Network 分层明确；
- macOS Docker Desktop 通过 Linux 虚拟机运行 Linux 容器；
- Ubuntu Docker Engine 直接运行在 Linux 宿主机；
- Docker Socket 和 `docker` 组属于高权限能力；
- 容器不是完整虚拟机，也不是运行任意不可信代码的绝对安全边界；
- 不挂载整个 HOME、SSH、云凭据或 Docker Socket；
- Compose 使用当前 `docker compose` 路线；
- 顶层 `version` 不再作为新 Compose 文件必需字段；
- `depends_on` 不自动等于服务已经健康；
- `down -v` 和 prune 操作有数据删除风险；
- GPU 容器按宿主机驱动、Container Toolkit、容器框架三层检查；
- GPU 支持通常不需要 `--privileged`。


检查范围包括：

1. **事实最新性**：Claude Code、Codex CLI、Grok CLI、DeepSeek、Docker、uv、Tailscale、PyTorch 和 NVIDIA 文档是否有新变化；

6. **外部链接**：逐项检查官方链接是否仍有效；
