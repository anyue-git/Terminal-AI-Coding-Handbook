## 3. V3.0 叙事审查结果

只比较 `main` 中原有、当前仍存在的同一批 73 个文档，普通正文字符从 137786 变为 131924，下降 4.3%；自然段从 4526 降至 2180，微型段从 2311 降至 566，短段从 3355 降至 1013，平均段长从 30.4 字升至 60.5 字，短段占比从 74.1% 降至 46.5%。标题、列表、代码块、薄小节和空引导也明显下降。

正文字符下降的一部分来自把术语表、危险命令、版本核对表和维护状态改成表格。叙事审计不统计表格单元格，因此不能把这部分变化解释为术语或规则被删除。结构改善仍需通过内容覆盖、Git diff 和人工阅读判断；较长段落、步骤扫描和表格适配性都已列入最终复核。

## 4. 自动检查与发布审计

仓库当前使用：

```text
scripts/check_markdown.py
scripts/audit_prose_structure.py
scripts/audit_sensitive_patterns.py
scripts/audit_external_links.py
scripts/export_public.sh
.github/workflows/markdown-check.yml
.github/workflows/source-release-audit.yml
```

Markdown Check 负责脚本语法、叙事趋势、UTF-8、本地链接、越界路径、围栏代码块、一级标题、重复二级标题、异常短文件和 `SUMMARY.md` 引用。Source Release Audit 只在私有源仓库运行：它检出真实分支、扫描当前树和完整 Git 补丁历史、克隆当前公共仓库、真实执行 `export_public.sh --dry-run`、确认目标 clone 未变化、构建隔离公共快照，再对快照运行 Markdown、敏感信息和外部链接检查。该源仓库专用工作流已通过 `.publishignore` 排除，不进入公共快照。

阶段性实际结果：

| 审计项 | 结果 |
| --- | --- |
| 源树与 Git 历史 | 90 余个文本文件和约 10 万行历史新增内容，0 个高置信度敏感信息发现 |
| 公开导出预演 | 成功；没有删除项，精确差异数以当次 Actions 产物为准 |
| 公共 clone 完整性 | 预演前后提交一致，工作区保持干净 |
| 隔离公开快照 Markdown | 80 余个文件，0 个错误、0 个警告 |
| 隔离快照敏感扫描 | 90 余个文本文件，0 个未豁免发现 |
| 外部链接 | 去重后 60 个，全部正常；0 死链、0 网络未知、0 受限 |

精确文件数、历史行数和导出差异数会随 PR 后续维护变化，最终发布以最新一次 PR checks 和最终导出 diff 为准。自动检查不能证明命令在作者真实 Mac、Ubuntu/NVIDIA GPU、账号和网络环境中已经执行，也不能替代历史 Actions 日志、最终上下文信息和发布决策的人工审查。

2. **最终事实确认**：发布前再次核对快速变化的 AI CLI、第三方 Provider、模型与平台政策；
3. **人工敏感信息复核**：检查历史 Actions 日志、最终 PR diff、最终导出差异中的账号、主机、私人路径与上下文信息；
4. **发布决策**：明确最终标签、GitHub Release 文案和发布时间，确认双许可证、README、路线图、发布说明与公共仓库状态一致；
5. **正式导出**：Draft PR 经批准并合入私有源仓库 `main` 后，从 `main` 向公共仓库非 `main` 发布分支执行 `--apply`；
6. **公共仓库复核**：人工阅读公共 diff，等待公共仓库检查通过后再合并、打标签和发布 Release。
