# 术语表

> 最近核对：2026-07-30

本表解释全书中反复出现的概念。定义以帮助读者判断“当前是哪一层、什么东西会被修改”为目标，不代替各工具的完整官方文档。

## 终端、Shell 与程序

### Terminal

显示文字界面、接收键盘输入并展示程序输出的终端程序或终端模拟器。macOS Terminal、iTerm2、Warp 和 VS Code 集成终端都属于这一层。

### Shell

解释命令、变量、通配符、管道和重定向，并启动其他程序的命令解释器，例如 zsh、bash 和 fish。

### zsh

Z Shell。macOS 默认 Shell，提供历史、补全、配置文件和 ZLE 命令行编辑能力。

### ZLE

Zsh Line Editor。zsh 在普通提示符中处理光标移动、删除、历史搜索和按键绑定的组件。

### CLI

Command-Line Interface，命令行界面。通过命令和参数使用程序，例如 `git`、`ssh` 和 `docker`。

### TUI

Text User Interface，文本用户界面。运行在终端中，但可以包含菜单、窗口、输入框和快捷键，例如 AI CLI 的交互界面。

### 当前工作目录

Shell 当前所在的目录。相对路径、文件命令和多数 AI CLI 的默认项目范围都从这里计算。

### 项目根目录

项目的主要目录，通常包含 `.git`、`README.md`、`pyproject.toml` 或 `package.json` 等标志文件。

### 主目录

当前用户的个人目录，用 `~` 表示。macOS 常见为 `/Users/NAME`，Ubuntu 常见为 `/home/NAME`。

### 绝对路径

从文件系统根目录 `/` 开始的完整路径，例如 `/Users/NAME/Projects/demo`。

### 相对路径

相对于当前工作目录的路径，例如 `src/app.py`。

### PATH

Shell 查找可执行命令时依次搜索的目录列表。多个同名程序存在时，PATH 顺序会影响最终运行哪一个。

### 环境变量

进程可以读取的键值配置，例如 `PATH`、`HOME`、模型端点和 API Key。子进程通常继承父进程的环境变量。

### stdin、stdout 与 stderr

- stdin：标准输入；
- stdout：标准输出；
- stderr：标准错误。

管道默认只把 stdout 交给下一条命令，错误输出需要单独重定向或使用 `2>&1` 合并。

### 管道

使用 `|` 把左侧命令的标准输出交给右侧命令作为输入。

### 重定向

把输入或输出改到文件或其他通道，例如 `>` 覆盖写入、`>>` 追加、`2>` 保存错误。

### 退出状态

命令结束时返回的数字。通常 0 表示成功，非 0 表示失败或其他状态；Shell 的 `&&`、`||` 和脚本自动化会依据它决定下一步。

### 进程

正在运行的程序实例，通常拥有 PID、用户、环境变量和打开的文件。

### 前台进程

当前占用终端交互的进程。键盘输入会先交给它，而不是 Shell。

### 后台进程

不占用当前 Shell 输入位置的进程。后台运行不等于脱离终端，也不保证 SSH 断开后继续。

### PID

Process ID，进程编号。结束进程前应核对 PID、用户和启动命令。

### tmux

终端复用器。它允许终端会话在 SSH 断开后继续，并可稍后重新接入；不能抵御关机、程序崩溃、磁盘写满或训练状态丢失。

## Git 与代码协作

### Git 仓库

由 Git 管理提交历史、分支和工作区状态的项目目录，内部元数据通常保存在 `.git`。

### 工作区

Git 仓库中当前可见、可编辑的文件状态。

### 未跟踪文件

尚未进入 Git 索引的文件。`git diff` 不会自动显示它们的正文，删除后也通常不能依靠 Git 恢复。

### 暂存区

Index 或 Staging Area。下一次提交准备包含的内容，可使用 `git diff --cached` 检查。

### Commit

Git 提交。记录一个项目快照、父提交、作者和说明。

### HEAD

Git 当前检出的提交位置，通常通过当前分支间接指向某个提交。

### Branch

Git 分支。本质上是指向提交的可移动引用，不是完整项目副本。

### Remote

远程 Git 仓库的连接定义，例如常见名称 `origin`。

### Pull Request

围绕一个分支相对于目标分支的差异进行讨论、自动检查、审查和合并的协作机制。

### Draft Pull Request

仍在开发或尚未准备正式审查的 Pull Request。Draft 不等于不会运行 CI，也不等于可以忽略差异审查。

### Worktree

同一 Git 仓库的额外工作目录，适合并行处理不同分支。它隔离 Git 工作区，不隔离系统权限、网络、进程、凭据和共享数据。

### Reflog

Git 本地引用移动记录，可帮助找回误 reset 或误移动前的提交。它不是永久备份，也不会恢复从未被 Git 记录的文件。

### Patch

描述文件差异的文本或二进制补丁。`git diff --binary HEAD` 可以记录相对 HEAD 的已暂存和未暂存的已跟踪修改，但不会自动包含未跟踪文件正文。

## SSH、网络与远程开发

### SSH

Secure Shell。用于安全远程登录、执行命令、传输文件和建立端口转发。

### SSH Client

发起 SSH 连接的客户端程序，例如 Mac 上的 `ssh` 命令。

### SSH Server

接受 SSH 连接的服务端程序，例如 Ubuntu 上的 OpenSSH Server `sshd`。

### SSH 主机密钥

证明远程服务器身份的密钥。首次连接应核对指纹，变化时应先调查原因。

### SSH 用户密钥

用于客户端身份认证的密钥对。私钥保存在可信客户端，公钥写入服务器的 `authorized_keys`。

### SSH Config

OpenSSH 客户端配置文件，常见位置为 `~/.ssh/config`。它可以保存主机别名、用户名、端口和密钥路径，但不应直接写入私钥正文。

### 端口转发

通过 SSH 加密连接转发网络端口。`ssh -L` 常用于在 Mac 安全访问远程 Jupyter、TensorBoard 或本地模型服务。

### 回环地址

只指向当前机器自身的地址，常见为 `127.0.0.1` 和 `::1`。服务只监听回环地址时，其他设备通常不能直接访问。

### `0.0.0.0`

IPv4 中表示监听所有可用网络接口。它可能把服务暴露给局域网、Tailscale 网络或公网路径，不等于“只在本机使用”。

### Tailscale

基于 WireGuard 的安全组网工具，用于让不同网络中的设备通过私有地址或名称互相访问。

### Tailnet

一组由同一 Tailscale 控制平面管理的用户、设备和访问规则。

### MagicDNS

Tailscale 提供的设备名称解析功能，让设备可以使用稳定名称连接。名称解析不能代替 SSH 主机身份验证。

### DERP

Tailscale 的加密中继路径。无法建立直接连接时可经 DERP 转发，通常延迟更高，但通信内容仍保持端到端加密。

### rsync

用于增量复制和同步文件的工具。源目录尾部斜杠、排除规则和 `--delete` 会明显改变结果，因此正式同步前应使用 `--dry-run`。

## Python、依赖与环境

### Python 解释器

实际执行 Python 代码的程序。`python -c 'import sys; print(sys.executable)'` 可以显示当前使用的解释器路径。

### pip

Python 包安装工具。项目环境中优先使用 `python -m pip`，确保 pip 属于当前解释器。

### 虚拟环境

为项目隔离 Python 解释器入口和第三方包的目录或环境，例如 venv、Conda 环境或 uv 管理的 `.venv`。它不是虚拟机，也不能在 macOS 与 Ubuntu 间直接复制使用。

### pyproject.toml

现代 Python 项目常用的项目元数据、构建和依赖配置文件。具体字段由 Python 标准和各工具定义。

### Lockfile

锁文件。记录依赖解析结果，帮助在不同时间重建接近一致的环境，例如 `uv.lock`。

### 精确同步

让当前环境与锁文件声明严格一致的同步方式。多余包可能被移除，因此不能把同步命令简单理解成“只安装缺少的包”。

### 环境快照

对某台机器当前已安装包的记录，例如 `pip freeze` 输出。它能帮助调查，但不一定等于理想的项目依赖声明，也可能包含平台特定包。

### uv

用于 Python 版本、项目依赖、锁定、同步和命令运行的工具。具体默认行为和参数应以当前 `uv --help` 与官方文档为准。

### Conda

环境和包管理系统，常用于科学计算和包含非 Python 依赖的项目。完整导出的环境可能具有操作系统和架构依赖性。

## Docker 与容器

### Docker Image

Docker 镜像。用于创建容器的只读分层模板。

### Docker Container

镜像的运行实例。容器共享宿主机内核，不是完整虚拟机。

### Docker Engine

负责构建镜像、创建容器、管理网络和 Volume 的后台服务及其组件。

### Docker Context

Docker CLI 当前连接的目标环境配置。Mac 上可能指向 Docker Desktop，远程或其他工具也可以创建不同 Context。

### Docker Compose

使用 Compose Specification 描述并运行多容器应用的工具。当前 CLI 仍使用 `docker compose`；具体实现代际和版本应通过 `docker compose version` 核对。

### Volume

由 Docker 管理、独立于单个容器生命周期的数据存储。

### Bind Mount

把宿主机路径直接挂入容器。容器对挂载路径的修改会影响宿主机文件。

### Docker Socket

Docker daemon 的控制接口，常见路径为 `/var/run/docker.sock`。访问它通常意味着很高的宿主机控制能力。

### `--privileged`

显著扩大容器设备和内核能力的高权限选项。GPU 访问通常不需要它。

### Healthcheck

用于判断容器内服务是否健康的检查机制。容器进程正在运行不自动表示应用已经可用。

## AI Agent、模型与配置

### Agent

能根据目标读取上下文、调用工具、修改文件并迭代执行任务的软件系统。Agent 能做什么取决于客户端、权限、工具和运行环境。

### AI CLI

运行在终端中的 AI 编程客户端，例如 Claude Code、Codex CLI 和 Grok Build 的 `grok` 命令。客户端不等于模型供应商。

### Claude Code

Anthropic 提供的 AI 编程客户端，可以读取项目、修改文件、执行命令并连接 Hooks、MCP 等扩展。

### Codex CLI

OpenAI 提供的终端编程 Agent。其审批策略和 Sandbox 是不同配置维度。

### Grok Build

xAI 的终端编程产品名称，终端命令为 `grok`。仓库路径中保留 `Grok-CLI` 是为了兼容现有目录和链接。

### 模型后端

真正接收请求并生成结果的模型服务。客户端可能连接官方 API、云平台、企业网关或兼容供应商。

### 模型供应商（Provider）

提供模型推理、认证、计费、日志和数据处理的服务。直连模型厂商与通过中转平台调用属于不同信任链。

### Model

客户端请求的具体模型标识。模型名称只在某个供应商和接口协议下有意义，不能脱离 Provider 单独判断。

### Base URL

客户端发送 API 请求时使用的基础地址。修改 Base URL 可能把 Prompt、源码和工具结果发送给不同服务。

### 配置

控制客户端模型、端点、权限、项目规则和行为的设置。配置可能保存在 TOML、JSON、Markdown 或环境变量中。

### 凭证

用于证明用户或应用身份的秘密，例如 OAuth 登录缓存、API Key 和访问令牌。配置和凭证不能因为位于同一目录就整目录同步。

### Profile

一组可命名切换的配置。Profile 是否同时隔离凭证和会话状态，取决于具体工具实现。

### 实例

一套相互隔离的配置、凭证和运行状态。Codex 可以通过不同 `CODEX_HOME` 构建独立实例；Profile 通常不等于完整实例隔离。

### LLM Gateway

位于客户端与一个或多个模型供应商之间的网关，可能负责统一认证、路由、审计、限流和模型映射。

### 本地网关

运行在当前机器上的代理或路由服务，例如监听 `127.0.0.1` 的兼容 API。它仍可能接触 Prompt、源码、凭证和上游响应。

### Anthropic 兼容接口

在请求与响应格式上兼容 Anthropic Messages API 的服务。协议兼容不等于 Claude Code 的所有工具调用、缓存和模型行为完全一致。

### OpenAI 兼容接口

在路径、请求或响应格式上兼容部分 OpenAI API 的服务。兼容程度可能只覆盖某些端点，不能假设所有 Responses、Chat Completions、工具调用和流式事件完全一致。

### CC Switch

常用于管理 Claude Code、Codex 等客户端配置的第三方桌面工具名称。它是配置管理工具，不是模型供应商，也不自动为上游服务的安全性背书。

### ccswitch

与 CC Switch 名称相近的命令行项目。使用前要确认具体仓库、安装来源和它会修改的文件，不能只按名称判断是同一工具。

### Cockpit Tools

可管理账号、路由和本地兼容端点的第三方工具。需要核对本地监听地址、上游账号、凭证存储和请求日志。

### MCP

Model Context Protocol。让 AI 客户端连接外部工具和数据源的协议。MCP Server 的权限和返回内容都属于 Agent 的安全边界。

### Hook

在特定事件前后自动执行的命令或脚本，例如工具调用前检查、任务结束后运行测试。Hook 会扩大自动执行范围。

### Plugin

向客户端增加命令、工具或集成功能的扩展。插件代码、安装脚本和更新渠道属于供应链风险。

### Skill

为 Agent 提供任务说明、脚本和参考资料的可复用能力包。Skill 不是天然可信，内部命令和依赖仍需审查。

### Subagent

由主 Agent 发起、承担特定子任务的额外 Agent。它能访问哪些文件和工具取决于客户端实现和继承的权限。

### Prompt Injection

通过文档、网页、工具输出或其他输入诱导模型偏离原任务、泄露数据或执行越权操作的攻击方式。

### Sandbox

用于限制程序可访问文件、网络、进程或系统能力的隔离机制。Sandbox 的强度取决于具体实现和配置。

### Approval

Agent 在执行命令、修改文件或访问外部资源前请求人工确认的机制。审批和 Sandbox 是不同维度。

### Headless / 非交互运行

不进入完整交互 TUI，由命令参数或标准输入提供任务并输出结果的运行方式。可靠自动化还需要稳定退出状态、超时、轮数限制和输出契约。

### JSONL

JSON Lines。每行一个独立 JSON 对象，适合流式记录 Agent 事件或训练指标。中途终止时，已经完整写入的行通常仍可解析。

## 凭据与认证

### API Key

调用网络服务时使用的秘密凭据，应像密码一样保护，不应进入 Git、截图、日志或聊天。

### Access Token

通常用于短期访问资源的令牌。具体有效期和权限由认证系统决定。

### Session Token

表示已登录会话的敏感令牌。泄露后可能允许他人冒用会话，不应作为非官方 API 接入方式。

### Refresh Token

用于申请新访问令牌的长期敏感凭据，通常比短期 Access Token 更需要保护。

### OAuth

让应用通过授权流程获得限定访问能力的标准机制。OAuth 登录缓存仍属于敏感凭据，不能随意复制给第三方工具。

### Keychain / Keyring

操作系统或桌面环境提供的安全凭据存储。工具可能把令牌保存在其中，而不是普通配置文件。

## GPU、训练与实验

### NVIDIA Driver

NVIDIA 驱动层，负责操作系统与 GPU 硬件通信。`nvidia-smi` 主要反映这一层。

### CUDA Toolkit

包含 `nvcc`、头文件和开发库的系统开发工具包。运行预编译 PyTorch wheel 不一定需要本机安装完整 Toolkit。

### CUDA Runtime

应用运行时使用的 CUDA 用户态库。PyTorch wheel 或容器镜像可能携带对应 Runtime。

### NVIDIA Container Toolkit

让 Docker 等容器运行时把 NVIDIA GPU 和相关驱动能力提供给容器的工具集。它不同于 CUDA Toolkit。

### MPS

Metal Performance Shaders。PyTorch 在 Apple Silicon Mac 上使用 GPU 的后端之一，不能替代 Ubuntu NVIDIA CUDA 验证。

### Checkpoint

训练过程中保存的可恢复状态，通常包含模型、优化器、调度器、步数和随机状态。它与只用于推理的模型权重文件不完全相同。

### Run Directory

某次独立实验的输出目录，通常保存配置、命令、代码状态、环境、日志、指标、checkpoint 和图表。

### `latest` 与 `best`

`latest` 表示最近可恢复状态，`best` 表示根据某个验证指标选出的最佳状态。两者不一定指向同一个 checkpoint。

### SHA-256

常用内容哈希算法。可用于验证 checkpoint 或传输文件是否发生变化，但不能证明文件来源可信或加载安全。
