## 4. 本轮纠正的关键事实

### Slash Commands 不是单一来源

斜杠菜单同时展示 Agent 后端内置命令、Pager 内置命令和用户可调用 Skill。Plugin 和兼容扫描还可以继续添加命令，因此不存在脱离版本与环境的永久封闭菜单。

### `/share` 与 `/transcript` 应保留

早期审查只依据仓库内 Slash Commands 文件，曾短暂认为 `/transcript` 没有正式依据。进一步对照较新的官方在线 Modes and Commands 后确认 `/share` 和 `/transcript` 都已进入正式在线文档，因此正文已恢复并说明文档同步差异。

### 键盘操作属于完整功能面

TUI 不只依赖斜杠命令。官方 Keyboard Shortcuts 还公开 Command Palette、Interject、Prompt Queue、Tasks、Todo、后台命令、Sessions、Extensions、Dashboard、Scrollback 导航、Raw Markdown、Viewer、复制、终止后台任务和空 Prompt 上的 Shell mode。按键受焦点、Vim Scrollback、Multiline 和终端协议影响；VS Code 系、Apple Terminal 与 WezTerm 不能完全共用同一张按键表。

### `@路径` 是项目文件引用，不是项目恢复

官方 Overview 使用 `@src/main.rs` 作为文件引用示例。该入口让 Prompt 明确指向文件，但不会改变工作目录、Git 分支、权限或 Sandbox，也不能代替对路径和实际文件状态的核对。

### Plan 不是完整只读模式

Plan 只对普通 Edit 工具施加计划文件门槛。Bash 重定向、拥有写能力的 MCP 和其他工具继续服从当前 Permission 与 Sandbox，父会话的 Plan 编辑门槛也不会自动限制子 Agent。正文已明确禁止把 `Plan + Always-approve` 当作安全隔离。

### Headless 有独立权限模式

官方 Enterprise 文档公开 `--permission-mode dontAsk` 和 `acceptEdits`。前者静默拒绝未被显式 Allow 的调用，适合 CI；后者自动批准文件编辑，但不自动批准所有 Shell 操作，也不限制编辑范围。企业还可从 root-owned Requirements 锁定 Bypass，阻止 `--yolo` 和 TUI 切换重新开启 Always-approve。

### 本地 Plugin 可以单次加载

官方 Plugin 文档公开 `--plugin-dir <PATH>`，用于把本地目录加入当前运行的 Plugin 来源。它不同于 Marketplace 安装、持久启用和信任；目录中的 Hook、MCP、Agent、Skill 与 LSP 仍需按源码审查。

### `/sessions` 同时是活动会话入口和 Dashboard 别名

在线 Modes and Commands 将 `/sessions` 描述为切换、重命名或关闭活动会话；上游随包 Slash Commands 指南又把 `/sessions` 与 `/agents-dashboard` 列为 `/dashboard` 的别名。两份说明并不冲突：它们共同指向当前 Pager 的实时会话与 Agent Dashboard，只是一个强调会话操作，一个强调多 Agent 管理。

这套实时界面必须与两类持久化入口分开：`/resume` 用于选择磁盘会话，Shell 层的 `grok sessions list/search/delete` 用于列出、搜索和删除磁盘会话。正文已按“活动会话、磁盘会话、Agent 定义”三层重新说明。

### 渲染模式决定部分命令是否出现

当前上游把 `/find`、`/jump`、`/timeline`、`/theme`、`/tutorial`、`/workflows` 和 `/dashboard` 列为 Fullscreen-only；`/expand` 与 `/edit-prompt` 仅在 Minimal 可用。`--no-alt-screen` 虽然使用终端主 Scrollback，命令可用性仍按 Fullscreen 处理。菜单缺少某个命令时不能只归因于版本或账号，还要先确认渲染模式。

### Goal 有两套驱动

Background Workflows 开启时，Goal 使用 Host-owned Workflow Engine；关闭时回退到旧式 `update_goal`。因此 `GROK_WORKFLOWS=0` 不只是隐藏 Workflow 界面，也会改变 Goal 运行机制。

### Workflow 不能跨进程恢复

同一进程内 Pause/Resume 保留原脚本、参数和已提交 Host 调用结果，但进程重启后不会恢复被中断的 Workflow。Resume 也不保证 exactly-once，外部调用可能在边界处重复执行。

### Agent Budget 与 Token Budget 不同

当前上游 Agent Budget 默认 128，显式范围 1–1024；每个逻辑子 Agent 消耗一个名额。它与 Goal Token Budget、API 费用和运行时间分别记录。

### 三种 Claude 导入不同

```text
/import-claude      设置迁移

grok import        Claude Code 会话导入

resume-claude       staged 兼容扫描与 Skill 路线
```

三者不能混写成同一个“恢复 Claude 会话”。

### `resume-codex` 不是稳定内置恢复

当前上游配置仍把 Codex Foreign-session Cell 标为 staged，并要求匹配的 `resume-codex` Skill；其他 Codex 兼容单元仍是保留字段。菜单中出现 `/resume-codex` 不能单独证明 Session Scanner 已经稳定接通。

### 配置没有一条适用于所有字段的覆盖直线

普通 CLI、环境变量和用户设置可以按运行时覆盖理解，但企业 `requirements.toml` 中受支持的 Policy Pin 不能被用户配置、环境变量或远程设置放宽。MCP、Plugin、Permission Rule、Hints 和 Version Bound 也各有自己的合并语义。正文已将“简化运行时顺序”和“企业策略钉死”分开说明。

### OAuth 有子命令参数和全局欢迎页入口

当前上游 Authentication 指南明确支持 `grok login --oauth`，并说明浏览器 OAuth 本来就是 `grok login` 的默认路线，因此该 Flag 通常可省略；CLI Reference 还公开 `grok --oauth`，用于从欢迎页启动认证时显式选择 OAuth。两种写法都有官方依据，但作用位置不同，正文已同时保留，不再把其中一种误判为未公开排列。

设备码登录同样有两个名称：`grok login --device-auth` 和它的别名 `grok login --device-code`。最终仍应分别用 `grok login --help` 和 `grok --help` 核对当前安装版本。

### 凭据优先级需要区分 `api_key` 与 `env_key`

官方 Enterprise 文档给出的精确顺序是：

```text
model.api_key
> model.env_key 指向的环境变量
> 活跃 Session Token
> XAI_API_KEY
```

前两项都属于模型级凭据，但并非同一优先级。已经登录时，仅设置 `XAI_API_KEY` 不能证明请求按 API Project 计费。

## 5. 安全和恢复边界

本轮统一保留以下判断：

```text
会话恢复 ≠ 项目恢复
Fork ≠ Git 分支
Rewind ≠ 外部副作用回滚
Compact ≠ 无损历史
Memory ≠ 可信事实库
Share ≠ 本地导出
Persona ≠ 权限隔离
Plan ≠ 完整只读 Sandbox
Worktree ≠ 外部资源隔离
Always-approve ≠ Sandbox
关闭 Web Search ≠ 禁止所有联网
Shell mode ≠ 自动安全执行
```

涉及数据库、云资源、付款、部署、权限和删除的 Workflow 或 Loop，默认只做只读调查和生成方案；真正写入要有人工门槛、幂等设计和产品自身恢复机制。

```text
最新私有 PR 检查通过
+ 关键命令和快捷键实机抽样完成

+ 公开导出差异人工批准
```
