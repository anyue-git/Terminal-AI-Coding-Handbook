# 版本化工具核对表

> 最近更新：2026-07-28

这张表记录变化较快的章节应该核对什么，而不是把某个时点的版本号当作永久结论。

实际使用前应同时检查：

```text
当前官方文档
+ 本机 --version
+ 本机 --help
+ 当前项目配置
+ 当前模型、平台或驱动兼容要求
```

固定模型名、安装命令、默认权限和兼容矩阵都可能变化。正文应保留稳定心智模型，具体数值则以实际环境为准。

## 1. Claude Code

最近核对范围：

- 客户端安装与诊断；
- 官方账户、API、云平台和 LLM Gateway；
- DeepSeek 官方 Anthropic 兼容接口；
- 权限模式、Settings、CLAUDE.md；
- 会话恢复、Hooks 与 MCP；
- 非官方供应商和 CC Switch 的信任边界。

使用前验证：

```bash
claude --version
claude --help
claude doctor
```

进入交互界面后再查看当前版本支持的权限和诊断命令。

维护提醒：

- Claude Code 是客户端，模型后端和认证方式应分开说明；
- Anthropic 兼容不保证所有工具调用、缓存和模型行为完全一致；
- 模型名称和供应商环境变量应以当前供应商文档为准；
- 不把 Cookie、Session Token 或共享认证缓存写成常规接入方式；
- CC Switch 是配置管理工具，不替第三方供应商背书。

## 4. Docker 与 Compose

最近核对范围：

- macOS Docker Desktop 与 Ubuntu Docker Engine 的架构差异；
- Docker Context、Socket、用户权限和后台服务；
- Compose Specification；
- 顶层 `version` 字段不再作为新文件必需内容；
- Bind Mount、Volume、端口发布和网络；
- GPU 设备声明与 NVIDIA Container Toolkit。

使用前验证：

```bash
docker version
docker info
docker context show
docker compose version
docker compose config
```

Ubuntu 还应检查：

```bash
systemctl status docker
```

维护提醒：

- Docker Desktop 的虚拟化和文件共享实现可能随版本变化；
- Docker 组和 Docker Socket 都属于高权限能力；
- 发布端口的实际暴露范围不能只凭 UFW 状态判断；
- 容器共享宿主机内核，不是运行任意不可信代码的绝对安全边界；
- `docker compose down -v` 和 prune 操作可能删除持久数据。

## 5. Python、pip、venv、Conda 与 uv

最近核对范围：

- `sys.executable` 与 `python -m pip`；
- venv、Conda 和 uv 的职责；
- `pyproject.toml`、锁文件与环境快照；
- uv 的锁定、同步、运行和 Python 管理；
- Conda 的环境导出与平台边界。

使用前验证：

```bash
python --version
python -c 'import sys; print(sys.executable)'
python -m pip --version
uv --version
uv --help
conda --version
conda export --help
```

维护提醒：

- `.venv` 和 Conda 环境目录不能在 Mac 与 Ubuntu 之间直接同步；
- `pip freeze` 是环境快照，不自动等于理想项目依赖声明；
- uv 子命令的默认同步行为和参数语义应按当前帮助验证；
- uv 可能管理或下载 Python，需明确项目使用的是系统还是托管解释器；
- Conda 的 explicit 导出通常具有平台依赖性。

## 6. PyTorch、CUDA 与 MPS

最近核对范围：

- NVIDIA 驱动、系统 CUDA Toolkit、应用 Runtime 和 PyTorch 构建的分层；
- PyTorch 官方安装选择器；
- Ubuntu CUDA 验证；
- Mac CPU/MPS 冒烟测试；
- 容器内 GPU 验证。

使用前验证：

```bash
nvidia-smi
nvcc --version
python - <<'PY'
import torch
print("torch:", torch.__version__)
print("built_cuda:", torch.version.cuda)
print("cuda_available:", torch.cuda.is_available())
print("mps_available:", hasattr(torch.backends, "mps") and torch.backends.mps.is_available())
PY
```

维护提醒：

- 不从旧文章复制固定 PyTorch、CUDA 或 Python 组合；
- `nvidia-smi` 中显示的 CUDA 能力不是本机 Toolkit 版本；
- 没有 `nvcc` 不自动表示预编译 PyTorch 无法使用 GPU；
- 系统 Toolkit 与 wheel Runtime 数字不同不自动表示错误；
- Mac MPS 测试不能替代 Ubuntu CUDA 正式验证。

相关章节：

## 7. NVIDIA Container Toolkit

最近核对范围：

- Container Toolkit 与 CUDA Toolkit 的区别；
- Docker Runtime 配置；
- 最小 GPU 容器验证；
- Compose GPU 声明；
- CDI 和相关诊断能力。

使用前验证：

```bash
nvidia-smi
nvidia-ctk --version
docker version
```

再按当前 NVIDIA 官方安装文档验证运行时配置。不要把某个补丁版本长期写死在正文。

维护提醒：

- 宿主机驱动必须先正常；
- 修改 Docker daemon 配置前检查正在运行的容器；
- GPU 访问通常不要求 `--privileged`；
- 不挂载 Docker Socket、整个 HOME、SSH 或云凭据目录。

## 8. OpenSSH

最近核对范围：

- Ubuntu OpenSSH Server 安装、服务和监听；
- `sshd_config` 与 `sshd_config.d`；
- 主机指纹、Ed25519 用户密钥和 SSH Config；
- `ssh -G`、`sshd -t` 与 `sshd -T`；
- Agent Forwarding、端口转发和故障排查。

使用前验证：

```bash
ssh -V
ssh -G HOST_ALIAS | head -n 40
```

Ubuntu：

```bash
systemctl status ssh
sudo sshd -t
sudo sshd -T
```

维护提醒：

- OpenSSH 配置片段的读取和覆盖行为应以当前手册页及最终配置输出为准；
- 修改服务端配置时保留旧会话，并用第二终端测试；
- 不删除整个 `known_hosts`，不关闭主机密钥检查；
- Agent Forwarding 不作为普通个人开发默认；
- 不直接把公网 22 端口作为新手默认方案。

## 9. Tailscale

最近核对范围：

- 设备状态、MagicDNS、直连和 DERP；
- 网络访问控制；
- 普通 OpenSSH 与 Tailscale SSH 的区别；
- 设备密钥、无人值守主机和异网故障排查。

使用前验证：

```bash
tailscale version
tailscale status
tailscale ping HOSTNAME
tailscale netcheck
```

维护提醒：

- 当前策略语法和管理后台能力可能变化，应查阅当前官方文档；
- 新网络不应被假定为天然最小权限；
- Tailscale 解决设备可达性，OpenSSH 解决 Linux 登录，tmux 解决断线后的终端会话；
- DERP 中继不等于不安全，但吞吐和延迟可能较差；
- 不为了追求直连而开放公网 SSH。

## 10. 每次更新版本化章节的动作

```text
确认官方产品名称
→ 查看当前官方文档
→ 查看本机 --version 与 --help
→ 区分稳定机制和版本细节
→ 更新正文及核对日期
→ 运行内部链接与 Markdown 检查
→ 更新审查记录和更新记录
```

核对表不能证明所有命令已经在每种操作系统、网络、显卡和账号条件下真实执行。它的作用是让维护者知道：哪些内容容易过期，以及使用前应该验证什么。
