# 03 分支、合并与安全恢复

Git 的恢复能力很强，但前提是先判断问题发生在工作区、暂存区还是提交历史。不要把 `reset --hard` 当成万能修复按钮。

---

## 1. 分支用于隔离任务

查看分支：

```bash
git branch
git branch --show-current
```

创建并切换：

```bash
git switch -c feature/search
```

切换已有分支：

```bash
git switch main
```

删除已合并分支：

```bash
git branch -d feature/search
```

`-D` 会强制删除，不应作为默认选项。

切换前先运行：

```bash
git status
```

未提交修改可能被带到新分支，也可能阻止切换。

---

## 2. 合并发生了什么

```bash
git switch main
git merge feature/search
```

`git merge X` 的含义是：把 X 合并进当前分支。

执行前确认：

```bash
git branch --show-current
git status
```

如果目标分支没有继续前进，Git 可能进行 fast-forward；两条历史都前进时，通常需要合并提交。

---

## 3. 冲突处理

冲突通常出现在两个分支修改同一文件的相同区域。

```bash
git status
```

文件可能包含：

```text
<<<<<<< HEAD
当前分支内容
=======
另一分支内容
>>>>>>> feature/search
```

人工编辑为最终版本，删除标记，再运行测试并暂存：

```bash
git add src/app.py
git commit
```

不想继续当前合并：

```bash
git merge --abort
```

不要为了解冲突直接运行 `git reset --hard`。

---

## 4. 三类常见恢复

### 暂存错了，但要保留修改

```bash
git restore --staged PATH_TO_FILE
```

### 未暂存修改明确不要了

先看：

```bash
git diff -- PATH_TO_FILE
```

再执行：

```bash
git restore PATH_TO_FILE
```

### 已共享提交需要撤销

```bash
git show COMMIT_SHA
git revert COMMIT_SHA
```

`revert` 创建反向提交，不删除旧历史，通常比重写共享分支更安全。

---

## 5. amend、reset 和 force push

修改最后一次尚未共享的提交：

```bash
git commit --amend
```

它会生成新的提交哈希。

高风险命令：

```bash
git reset --hard TARGET
git push --force
```

它们可能丢弃工作区、暂存区或重写远程历史。多人协作分支不应随意使用。

必须改写远程历史时，通常也应优先评估：

```bash
git push --force-with-lease
```

但它仍然是历史重写操作，不是普通推送。

---

## 6. `git clean` 会删除未跟踪文件

预览：

```bash
git clean -n
```

真正删除：

```bash
git clean -f
```

删除目录：

```bash
git clean -fd
```

未跟踪文件可能是尚未提交的源码、数据、配置或训练结果。Git 无法恢复从未记录的文件，所以 Agent 不应自动执行 `git clean`。

---

## 7. Reflog 是本地救援线索

```bash
git reflog
```

它记录本地 HEAD 和分支引用如何移动。发现误 reset 后，可以先创建救援分支：

```bash
git branch rescue COMMIT_SHA
git show rescue
```

Reflog 不是永久备份，也无法恢复从未进入 Git 的文件。

---

## 8. 安全恢复决策表

```text
暂存错了但保留修改
→ git restore --staged 文件

未暂存修改明确不要
→ 先 git diff，再 git restore 文件

共享提交需要撤销
→ git revert 提交

合并不想继续
→ git merge --abort

误移动分支
→ git reflog，先建 rescue 分支

准备清理未跟踪文件
→ git clean -n，只预览
```

---

## 9. AI CLI 的分支边界

```text
只在当前任务分支修改。
不要切换分支，不要执行 merge、rebase、reset、clean、commit、push 或 force push。
需要恢复文件时先说明将丢失什么，并等待确认。
```

较大任务开始前：

```bash
git status
git switch -c agent/short-description
```
