# 06 异网安全连接：Tailscale 与普通 OpenSSH

> 最近核对：2026-07-29
>
> 本章让 Tailscale 负责网络可达性，普通 OpenSSH 继续负责服务器身份和 Linux 用户登录。安装命令、Grants 与设备策略可能变化，实际配置以当前官方文档和管理后台校验为准。

离开寝室后，Ubuntu 的 `192.168.x.x` 私网地址通常不可达。异网连接可以让 Mac 与游戏本加入同一受控加密网络，而无需把路由器 TCP 22 暴露到公网：

```text
Mac
→ Tailscale 加密网络
→ Ubuntu 游戏本
→ 普通 OpenSSH
```

已有的 `ssh`、`scp`、rsync、VS Code Remote SSH 和 SSH 隧道都可以继续使用。

## 1. 以局域网 SSH 为基线，再加入 Tailscale

配置异网前，先在寝室确认局域网别名正常：

```bash
ssh gpu-laptop
```

后续链路按这一顺序成立：

```text
局域网 OpenSSH 正常
→ 两台设备加入 Tailnet
→ Tailscale 网络可达
→ Ubuntu TCP 22 可达
→ 普通 OpenSSH 登录成功
```

若局域网基线尚未通过，一个失败会同时混入地址、SSH、密钥、Tailscale 与防火墙，难以定位。公网端口转发还需要处理公网地址、动态 DNS、路由器映射、主机防火墙、扫描、暴力尝试、CGNAT 和设备撤销，不适合作为新手第一条异网路线。

Mac 使用 Tailscale 官方应用或当前官方安装方式。Ubuntu 安装后在本机运行：

```bash
sudo tailscale up
tailscale status
tailscale ip -4
```

以后修改单个持久选项时查看：

```bash
tailscale set --help
```

反复执行一条已忘记全部参数的 `tailscale up ...`，可能覆盖现有设置。认证 URL、设备授权码和一次性登录信息只在自己的可信设备中使用。

在 Mac 和 Ubuntu 分别确认：

```bash
hostname
tailscale status
tailscale ip -4
```

管理后台同时核对设备名称、登录身份、操作系统、最近在线、批准状态和重复旧节点。系统重装可能产生新节点，名称相似并不能证明它仍是原设备。

## 2. 从 Tailscale 路径测试到普通 SSH

Mac 先检查加密网络：

```bash
tailscale status
tailscale ping GPU_LAPTOP_NAME
tailscale netcheck
```

成功后测试 Ubuntu 的 TCP 22：

```bash
nc -vz GPU_LAPTOP_MAGICDNS_NAME 22
```

最后使用普通 OpenSSH：

```bash
ssh YOUR_UBUNTU_USER@GPU_LAPTOP_MAGICDNS_NAME
```

为异网地址建立单独别名：

```sshconfig
Host gpu-laptop-remote
  HostName GPU_LAPTOP_MAGICDNS_NAME
  User YOUR_UBUNTU_USER
  IdentityFile ~/.ssh/id_ed25519_gpu_laptop
  IdentitiesOnly yes
  ServerAliveInterval 30
  ServerAliveCountMax 3
```

```bash
ssh -G gpu-laptop-remote \
  | grep -E '^(hostname|user|identityfile|serveralive)'
ssh gpu-laptop-remote
```

保留 `gpu-laptop` 作为寝室局域网别名，`gpu-laptop-remote` 使用 Tailscale MagicDNS。局域网通常适合高速传输，异网别名适合外出控制和轻量结果回传。主机指纹、用户密钥和 Config 的完整规则见 Part 05；Tailscale 只改变到达服务器的网络路径。

## 3. MagicDNS、direct/DERP、Grants 与 Tailscale SSH

MagicDNS 提供稳定设备名，不负责验证服务器身份。首次连接、系统重装或主机密钥变化后，仍应在 Ubuntu 本机核对 OpenSSH 指纹。名称排查：

```bash
tailscale status
nslookup GPU_LAPTOP_MAGICDNS_NAME
tailscale ping GPU_LAPTOP_MAGICDNS_NAME
```

`tailscale ping` 显示 `direct` 时，两台设备直接建立加密连接；显示 `via DERP` 时，流量经过 Tailscale 中继，仍然加密，但速度和延迟可能较差。终端、源码和小日志通常不受明显影响，大 checkpoint 可以等回到局域网再传，不需要为了追求 direct 公开 SSH 端口。

私人 Tailnet 也要检查访问范围。当前推荐使用 Grants 表达策略；每次修改后在后台验证语法，并依次测试：

```bash
tailscale ping GPU_LAPTOP_NAME
nc -vz GPU_LAPTOP_MAGICDNS_NAME 22
ssh gpu-laptop-remote
```

本手册继续使用普通 OpenSSH：

```text
设备网络可达：Tailscale
服务器身份、Linux 用户与密钥：OpenSSH
```

Tailscale SSH 使用 Tailnet 身份与 SSH 策略，还涉及 Linux 用户映射和重新认证。需要采用时，应保留 Ubuntu 本机控制台与已经验证的普通 OpenSSH，单独设计和测试策略，而不是直接替换现有登录路线。

## 4. 异网主要用于控制、轻量传输与隧道

先用小文件测试：

```bash
printf 'remote test\n' > /tmp/remote-test.txt
scp /tmp/remote-test.txt \
  gpu-laptop-remote:~/projects/connection-test/

rsync -av --dry-run \
  ~/terminal-practice/gpu-connection-test/ \
  gpu-laptop-remote:~/projects/connection-test/
```

结合 `tailscale ping` 的 direct/DERP 结果决定是否传输大型文件。异网更适合启动/停止任务、查看日志、编辑少量源码和拉回轻量证据。

Jupyter 与 TensorBoard 仍只监听 Ubuntu 回环地址。Ubuntu 启动 Jupyter：

```bash
jupyter lab \
  --no-browser \
  --ip=127.0.0.1 \
  --port=8888
```

Mac 建立隧道：

```bash
ssh -N \
  -L 18888:127.0.0.1:8888 \
  gpu-laptop-remote
```

浏览器访问 `http://127.0.0.1:18888`。TensorBoard 同理：

```bash
# Ubuntu
tensorboard \
  --logdir ~/runs/my-project \
  --host 127.0.0.1 \
  --port 6006

# Mac
ssh -N \
  -L 16006:127.0.0.1:6006 \
  gpu-laptop-remote
```

开发服务不需要直接监听 `0.0.0.0`。VS Code Remote SSH 选择异网别名即可；命令行 SSH 尚未通过时，先修复网络或 OpenSSH 层，再处理编辑器扩展。

## 5. 长期在线、排错和离开寝室前演练

游戏本无人值守时，检查自动休眠、电源与散热、`tailscaled` 与 `ssh` 开机启动、设备密钥过期策略、安全更新、磁盘加密和设备丢失后的撤销方式。关闭设备密钥过期会提高无人值守可用性，也会减弱旧设备自动失效保护，应结合账户与磁盘安全决定。

Mac 侧沿链路排查：

```bash
tailscale status
tailscale ping GPU_LAPTOP_NAME
nc -vz GPU_LAPTOP_MAGICDNS_NAME 22
ssh -vv gpu-laptop-remote
```

Ubuntu 本机检查：

```bash
systemctl is-active tailscaled
systemctl is-active ssh
sudo journalctl -u tailscaled --no-pager -n 80
sudo journalctl -u ssh --no-pager -n 80
tailscale status
sudo ss -lntp | grep ':22'
```

一次只改变一个层次。Tailscale 未上线时无需重建 SSH 密钥，TCP 22 不通时也不应先删除 `known_hosts`。

离开寝室前，即使两台机器仍在同一局域网，也主动测试异网别名：

```bash
ssh gpu-laptop-remote
```

确认 Ubuntu 不休眠，Tailscale 与 SSH 会随系统启动，MagicDNS 和 Grants 正确，tmux 会话可以恢复，训练日志与 checkpoint 不依赖 Mac 持续连接。外出后第一次只做只读检查：

```bash
ssh gpu-laptop-remote '
  hostname &&
  uptime &&
  tmux ls 2>/dev/null || true &&
  nvidia-smi
'
```

链路稳定后再启动或修改正式任务。
