# 06 异网安全连接

同一局域网里，Mac 可以直接访问 Ubuntu 的内网地址。离开寝室后，原来的 `192.168.x.x` 地址通常不可达。

异网连接的目标不是把公网 22 端口暴露出去，而是让两台设备加入同一个受控加密网络，再继续使用普通 SSH。

对个人 Mac + Ubuntu 游戏本，推荐路线是：

```text
Tailscale
→ 负责让两台设备安全可达

OpenSSH
→ 负责主机身份、用户认证和远程会话
```

---

## 1. 为什么不推荐公网端口转发

公网端口转发需要处理：

- 是否有公网 IPv4；
- IPv6 暴露；
- 动态 DNS；
- 路由器端口规则；
- 防火墙；
- 公网扫描与暴力尝试；
- 系统补丁和日志审计。

它不是绝对不能用，但不应成为新手第一套异网方案。

Tailscale 通常不需要公网 IP，也不需要在路由器公开 SSH 端口。`scp`、rsync、VS Code Remote SSH 和 SSH 隧道仍可继续使用。

---

## 2. 先确保局域网普通 SSH 已经正常

在配置异网前，先完成：

```bash
ssh gpu-laptop
```

如果局域网 SSH 本身不通，不要同时排查 Tailscale、OpenSSH、密钥和防火墙四层问题。

推荐顺序：

```text
局域网普通 SSH 正常
→ 安装 Tailscale
→ 验证两台设备互相可达
→ 再配置异网 SSH 别名
```

---

## 3. 在两台设备安装并登录 Tailscale

Mac 和 Ubuntu 分别从 Tailscale 官方安装页面安装。

Ubuntu 常见初始连接：

```bash
sudo tailscale up
```

完成认证后检查：

```bash
tailscale status
tailscale ip
```

认证链接和设备授权信息属于敏感临时凭据，不要发送给别人。

后续只修改某个持久选项时，优先查看：

```bash
tailscale set --help
```

不要反复运行一条自己已经忘记其他参数的 `tailscale up` 命令。

---

## 4. 先测 Tailscale，再测 SSH

查看设备在线状态：

```bash
tailscale status
```

测试目标设备：

```bash
tailscale ping GPU_LAPTOP_NAME
```

查看当前网络条件：

```bash
tailscale netcheck
```

测试 TCP 22：

```bash
nc -vz GPU_LAPTOP_NAME 22
```

最后测试普通 SSH：

```bash
ssh YOUR_UBUNTU_USER@GPU_LAPTOP_NAME
```

固定排错顺序：

```text
设备在线
→ Tailscale 路径可达
→ 访问策略允许
→ TCP 22 可达
→ SSH 主机身份正确
→ 用户认证成功
```

---

## 5. 配置远程 SSH 别名

Mac 的 `~/.ssh/config`：

```sshconfig
Host gpu-laptop-remote
  HostName GPU_LAPTOP_MAGICDNS_NAME
  User YOUR_UBUNTU_USER
  IdentityFile ~/.ssh/id_ed25519_gpu_laptop
  IdentitiesOnly yes
  ServerAliveInterval 30
  ServerAliveCountMax 3
```

检查：

```bash
ssh -G gpu-laptop-remote | sed -n '1,30p'
```

连接：

```bash
ssh gpu-laptop-remote
```

局域网别名和异网别名可以同时保留。这样回到寝室时使用局域网地址，外出时使用 Tailscale 名称。

---

## 6. MagicDNS 是方便功能，不是新的认证方式

MagicDNS 允许使用稳定设备名而不是记住 Tailscale IP。

排查：

```bash
tailscale status
nslookup GPU_LAPTOP_MAGICDNS_NAME
tailscale ping GPU_LAPTOP_MAGICDNS_NAME
```

设备名变化或连接到不同主机时，仍需核对 SSH 主机指纹。DNS 能告诉你去哪里，不能替你证明对方一定是原来的机器。

---

## 7. 直连和 DERP 中继

`tailscale ping` 可能显示：

```text
direct
→ 两台设备直接建立加密连接

via DERP
→ 流量经过 Tailscale 中继
```

DERP 中继仍是加密连接，但速度和延迟可能不如直连。

不要为了追求 `direct` 状态而公开路由器 SSH 端口。路径优化和公网暴露是两件完全不同的事。

---

## 8. 默认 tailnet 不一定是最小权限

新建 tailnet 可能带有允许成员设备互相通信的初始策略。不要因为“这是私人 Tailscale 网络”就假设所有访问天然最小化。

应在管理后台检查访问控制，并逐步缩小为：

```text
我的身份或设备
→ 只能访问 GPU 游戏本
→ 只开放真正需要的端口
```

Tailscale 当前推荐使用 Grants 表达访问规则。具体语法、标签和身份选择器以管理后台校验和官方文档为准，不要照抄一段自己看不懂的策略。

---

## 9. 普通 OpenSSH 与 Tailscale SSH 的区别

### 普通 OpenSSH 运行在 Tailscale 网络上

```text
设备可达性
→ Tailscale

Linux 用户和 SSH 密钥
→ OpenSSH
```

这是本手册推荐的新手路线。

### Tailscale SSH

Tailscale SSH 会使用 tailnet 身份和 SSH policy 控制登录。它不是简单地“多开一个 SSH 功能”，还涉及网络规则、目标 Linux 用户和重新认证策略。

启用前必须保留：

- Ubuntu 本机控制台；
- 已验证的普通 OpenSSH；
- 可以撤销配置的管理入口。

不要只运行启用命令，就假设所有用户映射和策略都正确。

---

## 10. 长期无人值守设备

游戏本需要长期在线时，应检查：

- 自动休眠；
- 电源和散热；
- Tailscale 设备是否在线；
- 设备密钥是否会过期；
- Ubuntu 安全更新；
- SSH 日志；
- 丢失设备时如何撤销访问。

为特定设备关闭密钥过期会提高可用性，但也降低长期失控设备自动失效的保护。只对确实需要无人值守、磁盘和账户都受保护的设备考虑。

---

## 11. Jupyter 和其他服务仍使用 SSH 隧道

Ubuntu 让 Jupyter 只监听本机：

```bash
jupyter lab --no-browser --ip=127.0.0.1 --port=8888
```

Mac 建立隧道：

```bash
ssh -N -L 18888:127.0.0.1:8888 gpu-laptop-remote
```

浏览器访问：

```text
http://127.0.0.1:18888
```

不要把无认证 Jupyter、TensorBoard 或开发服务器直接监听到公网地址。

---

## 12. 最短故障清单

连接失败时依次执行：

```bash
tailscale status
tailscale ping GPU_LAPTOP_NAME
nc -vz GPU_LAPTOP_NAME 22
ssh -v gpu-laptop-remote
```

Ubuntu 本机：

```bash
systemctl is-active tailscaled
systemctl is-active ssh
sudo journalctl -u tailscaled --no-pager -n 50
sudo journalctl -u ssh --no-pager -n 50
```

不要一失败就同时重装 Tailscale、删除 `known_hosts`、重建 SSH 密钥和修改防火墙。逐层检查才知道哪一层真正坏了。
