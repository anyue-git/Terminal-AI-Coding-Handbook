# 06 异网安全连接：Tailscale 与普通 OpenSSH

> 最近核对：2026-07-29
>
> 本章推荐 Tailscale 负责网络可达性，普通 OpenSSH 继续负责主机身份和 Linux 用户登录。Tailscale 的安装命令、Grants 和设备策略可能更新，实际配置应以当前官方文档和管理后台校验为准。

在寝室局域网内，Mac 可以直接访问 Ubuntu 的 `192.168.x.x` 地址；离开寝室后，这个私有地址通常不可达。异网连接的目标不是把路由器公网 22 端口暴露出去，而是让两台设备加入同一个受控加密网络。

推荐结构：

```text
Mac
→ Tailscale 加密网络
→ Ubuntu 游戏本
→ 普通 OpenSSH
```

职责分工：

```text
Tailscale
→ 让两台机器在不同网络中安全可达

OpenSSH
→ 验证服务器主机指纹、Linux 用户和登录密钥
```

## 1. 为什么不把公网 22 端口作为第一方案

公网端口转发需要处理：

- 是否有公网 IPv4；
- IPv6 暴露；
- 动态 DNS；
- 路由器端口映射；
- 主机防火墙；
- 公网扫描与暴力尝试；
- 安全更新和日志审计；
- 运营商 CGNAT；
- 设备丢失后的撤销。

这不是绝对不能做，但不适合终端和网络新手作为第一套异网方案。

Tailscale 通常不要求公网 IP，也不要求在路由器公开 SSH 端口。已有的 `ssh`、`scp`、rsync、VS Code Remote SSH 和 SSH 隧道可以继续使用。

## 2. 异网配置前先完成局域网 SSH

先在寝室运行：

```bash
ssh gpu-laptop
```

只有局域网普通 SSH 已经稳定，才继续安装 Tailscale。推荐排错顺序：

```text
局域网 SSH 正常
→ Tailscale 设备上线
→ Tailscale 网络可达
→ TCP 22 可达
→ OpenSSH 登录成功
```

否则一个失败可能同时涉及地址、SSH、密钥、Tailscale 和防火墙，定位会非常困难。

## 3. 在 Mac 与 Ubuntu 分别安装

Mac 使用 Tailscale 官方应用或当前官方安装方式。安装后登录自己的 Tailnet。

Ubuntu 使用官方当前安装页面提供的命令。安装完成后在 **Ubuntu 本机**运行：

```bash
sudo tailscale up
```

浏览器或设备授权流程完成后：

```bash
tailscale status
tailscale ip -4
```

认证 URL、设备授权码和一次性登录信息都属于敏感凭据，不要发送给别人。

以后修改单个持久选项时，优先检查：

```bash
tailscale set --help
```

不要反复执行一条已经忘记所有参数的 `tailscale up ...`，以免无意中覆盖已有设置。

## 4. 核对设备身份

在 Mac 和 Ubuntu 分别执行：

```bash
hostname
tailscale status
tailscale ip -4
```

在管理后台确认：

- 两台设备名称；
- 当前登录身份；
- 操作系统；
- 最近在线时间；
- 设备是否被批准；
- 是否出现重复或旧设备记录。

不要只根据相似设备名判断目标。游戏本重装系统后可能产生新节点，旧节点仍留在后台。

## 5. 先测 Tailscale，再测 SSH

在 Mac：

```bash
tailscale status
tailscale ping GPU_LAPTOP_NAME
```

查看网络条件：

```bash
tailscale netcheck
```

再测试 TCP 22：

```bash
nc -vz GPU_LAPTOP_MAGICDNS_NAME 22
```

最后测试普通 SSH：

```bash
ssh YOUR_UBUNTU_USER@GPU_LAPTOP_MAGICDNS_NAME
```

排错链：

```text
设备是否在线
→ tailscale ping 是否成功
→ Grants/ACL 是否允许
→ TCP 22 是否可达
→ SSH 主机指纹是否正确
→ Linux 用户与密钥是否正确
```

## 6. 创建异网 SSH 别名

Mac 的 `~/.ssh/config`：

```sshconfig
Host gpu-laptop-remote
  HostName GPU_LAPTOP_MAGICDNS_NAME
  User YOUR_UBUNTU_USER
  IdentityFile ~/.ssh/id_ed25519_gpu_laptop
  IdentitiesOnly yes
  ServerAliveInterval 30
  ServerAliveCountMax 3
```

检查：

```bash
ssh -G gpu-laptop-remote \
  | grep -E '^(hostname|user|identityfile|serveralive)'
```

连接：

```bash
ssh gpu-laptop-remote
```

保留两个别名：

```text
gpu-laptop
→ 寝室局域网地址，通常速度更高

gpu-laptop-remote
→ Tailscale MagicDNS 名称，外出使用
```

## 7. MagicDNS 不是认证

MagicDNS 让你使用稳定设备名，不必记忆 Tailscale IP。排查：

```bash
tailscale status
nslookup GPU_LAPTOP_MAGICDNS_NAME
tailscale ping GPU_LAPTOP_MAGICDNS_NAME
```

DNS 只负责把名称解析到设备地址，不能证明服务器身份。首次连接、系统重装或主机密钥变化后，仍要在 Ubuntu 本机核对 SSH 指纹。

## 8. 直连与 DERP 中继

`tailscale ping` 可能显示：

```text
direct
→ 两台设备直接建立加密连接

via DERP
→ 通过 Tailscale 中继传输加密流量
```

DERP 仍是加密连接，但速度和延迟可能不如直连。源码、小日志和终端通常问题不大，大型数据集与 checkpoint 回传可能更慢。

不要为了追求 `direct` 而公开 SSH 端口。优化 Tailscale 路径与公网暴露是两件不同的事。

## 9. Tailnet 默认访问范围也要审查

私人 Tailnet 不等于天然最小权限。管理后台中的初始规则可能允许多个设备互相访问。

理想策略是逐步收缩为：

```text
自己的身份或指定 Mac
→ 只能访问 GPU 游戏本
→ 只允许需要的端口
```

Tailscale 当前推荐用 Grants 表达访问规则。不要直接复制陌生人的 JSON 策略；应在后台验证语法，并保留管理入口和恢复方式。

修改规则后按顺序测试：

```bash
tailscale ping GPU_LAPTOP_NAME
nc -vz GPU_LAPTOP_MAGICDNS_NAME 22
ssh gpu-laptop-remote
```

## 10. 普通 OpenSSH 与 Tailscale SSH

### 普通 OpenSSH 运行在 Tailscale 网络上

```text
设备网络可达
→ Tailscale

服务器身份、Linux 用户和密钥
→ OpenSSH
```

这是本手册推荐的新手路线，因为它复用了已经验证的局域网 SSH 配置。

### Tailscale SSH

Tailscale SSH 使用 Tailnet 身份和 SSH 策略控制登录，还涉及目标 Linux 用户映射、重新认证和访问规则。

启用前保留：

- Ubuntu 本机控制台；
- 已验证的普通 OpenSSH；
- Tailscale 管理后台；
- 可撤销的策略；
- 第二条测试连接。

不要在不了解用户映射和策略时直接替换现有 SSH 路线。

## 11. 异网同步不要一开始传大型数据

先测试小文件：

```bash
printf 'remote test\n' > /tmp/remote-test.txt
scp /tmp/remote-test.txt \
  gpu-laptop-remote:~/projects/connection-test/
```

再测试 rsync：

```bash
rsync -av --dry-run \
  ~/terminal-practice/gpu-connection-test/ \
  gpu-laptop-remote:~/projects/connection-test/
```

查看 `tailscale ping` 是 direct 还是 DERP，再判断是否适合传输大 checkpoint。大文件可在寝室局域网回传，异网主要用于控制、查看日志和传输小型结果。

## 12. Jupyter、TensorBoard 仍通过 SSH 隧道

Ubuntu 让服务只监听本机：

```bash
jupyter lab \
  --no-browser \
  --ip=127.0.0.1 \
  --port=8888
```

Mac 建立隧道：

```bash
ssh -N \
  -L 18888:127.0.0.1:8888 \
  gpu-laptop-remote
```

浏览器访问：

```text
http://127.0.0.1:18888
```

TensorBoard 同理：

```bash
tensorboard \
  --logdir ~/runs/my-project \
  --host 127.0.0.1 \
  --port 6006
```

Mac：

```bash
ssh -N \
  -L 16006:127.0.0.1:6006 \
  gpu-laptop-remote
```

不要把无认证的 Jupyter、TensorBoard 或开发服务器直接监听到 `0.0.0.0` 并暴露给整个网络。

## 13. VS Code Remote SSH 的异网使用

在 Mac VS Code 中选择：

```text
Remote-SSH: Connect to Host
→ gpu-laptop-remote
```

远程窗口打开 Ubuntu 项目：

```text
/home/YOUR_USER/projects/my-project
```

连接失败时先回到终端：

```bash
ssh -vv gpu-laptop-remote
```

命令行 SSH 不通时，不要先重装 VS Code 扩展。

## 14. 长期无人值守设备

游戏本长期在线时检查：

- Ubuntu 自动休眠；
- 电源和散热；
- `tailscaled` 与 `ssh` 开机启动；
- 设备密钥过期策略；
- Ubuntu 安全更新；
- SSH 与 Tailscale 日志；
- 磁盘加密和登录密码；
- 设备丢失后的撤销方式。

为设备关闭密钥过期能提高无人值守可用性，但也降低旧设备自动失效的保护。只对确实需要、磁盘和账户受保护的节点考虑，并定期检查后台设备列表。

## 15. 故障排查脚本

Mac：

```bash
echo '== tailscale status =='
tailscale status

echo '== tailscale ping =='
tailscale ping GPU_LAPTOP_NAME

echo '== tcp 22 =='
nc -vz GPU_LAPTOP_MAGICDNS_NAME 22

echo '== ssh verbose =='
ssh -vv gpu-laptop-remote
```

Ubuntu 本机：

```bash
systemctl is-active tailscaled
systemctl is-active ssh
sudo journalctl -u tailscaled --no-pager -n 80
sudo journalctl -u ssh --no-pager -n 80
tailscale status
sudo ss -lntp | grep ':22'
```

不要一失败就同时：

```text
重装 Tailscale
删除 known_hosts
重建 SSH 密钥
开放防火墙
修改路由器
```

每次只改变一层，改变后重新测试。

## 16. 离开寝室前的验收

在同一局域网中，先主动用异网别名测试：

```bash
ssh gpu-laptop-remote
```

然后确认：

```text
Ubuntu 不休眠
Tailscale 和 SSH 均开机启动
普通 SSH 密钥可用
MagicDNS 名称正确
Grants 允许自己的 Mac
tmux 会话可恢复
训练日志和 checkpoint 不依赖 Mac 连接
```

外出后第一次只做只读检查：

```bash
ssh gpu-laptop-remote '
  hostname &&
  uptime &&
  tmux ls 2>/dev/null || true &&
  nvidia-smi
'
```

确认链路稳定后再启动或修改正式任务。
