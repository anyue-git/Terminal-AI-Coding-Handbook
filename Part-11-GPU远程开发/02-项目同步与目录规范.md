# 02 项目同步与目录规范

> 最近核对：2026-07-29

Mac 与 Ubuntu 协作时，最容易制造混乱的状态是两边同时修改同一项目，并且都认为自己的版本最新。本章默认 **Mac 是源码主副本和 Git 复核端，Ubuntu 是运行副本、数据端和 GPU 训练端**。使用 VS Code Remote SSH 时可以反过来让 Ubuntu 成为主副本，但同一任务阶段只能有一个主要修改端。

```text
源码：Mac → Ubuntu
结果：Ubuntu → Mac
正式历史：Git
临时运输：rsync
```

## 1. 先把源码、环境、数据和结果分开

Mac 建议使用：

```text
~/Projects/my-project/      源码与 Git
~/ML-Runs/my-project/       拉回的日志、指标、图表和必要 checkpoint
```

Ubuntu 建议使用：

```text
~/projects/my-project/      源码运行副本
~/datasets/                 数据集
~/models/                   模型权重与缓存
~/runs/my-project/          每轮实验的配置、日志、指标和 checkpoint
```

数据、模型、运行结果和平台相关虚拟环境放在源码目录外，可以减少 Git、rsync、VS Code、语言服务器和 AI CLI 的误扫描。真实数据路径和模型路径由本机配置提供：

```bash
export DATA_DIR="$HOME/datasets/my-dataset"
export MODEL_DIR="$HOME/models/my-model"
```

仓库提交 `config.example.yaml`、`.env.example` 等模板，真实 `.env`、本地配置和下载凭据保持未跟踪。Mac 与 Ubuntu 分别创建 `.venv` 或 Conda 环境，具体原因见[Mac 与 Ubuntu 为什么必须分别创建环境](05-Mac与Ubuntu分别创建环境.md)。

## 2. Git 管版本，rsync 运送当前工作区

Git 负责分支、提交、审查和长期保留；rsync 负责快速复制当前文件，包括尚未提交的试验代码和实验结果。稳定变化通过 Git 传递：Mac 完成提交后，Ubuntu 使用 `git pull --ff-only` 获取；临时 GPU 试跑可以直接从 Mac 单向 rsync，验证后再形成提交。

```bash
cd ~/Projects/my-project

rsync -av --dry-run \
  --exclude-from='.rsyncignore' \
  ./ gpu-laptop:~/projects/my-project/

rsync -av \
  --exclude-from='.rsyncignore' \
  ./ gpu-laptop:~/projects/my-project/
```

项目根目录准备 `.rsyncignore`：

```text
.git/
.venv/
venv/
__pycache__/
*.pyc
.pytest_cache/
.mypy_cache/
.ruff_cache/
node_modules/
.env
.env.*
runs/
checkpoints/
data/
models/
*.log
.DS_Store
```

`.gitignore` 决定 Git 是否追踪，`.rsyncignore` 只有在命令显式引用时才影响传输。排除 `.git/` 可以保留 Ubuntu 自己的分支、索引和 Worktree 元数据；排除 `.venv/` 避免把 macOS 二进制环境复制到 Linux。

源路径末尾斜杠表示复制目录中的内容：

```bash
rsync -av source/ host:target/
```

省略斜杠通常会在目标中再建立 `source/`。正式同步前用 `--dry-run` 检查目录层级和文件清单。第一版脚本不加入 `--delete`；确实需要严格镜像时，先预演并逐条阅读所有删除项：

```bash
rsync -av --dry-run --delete \
  --exclude-from='.rsyncignore' \
  ./ gpu-laptop:~/projects/my-project/
```

`rsync` 的方向、斜杠和 include/exclude 基础见[scp、rsync 与端口转发](../Part-05-SSH/03-scp-rsync与端口转发.md)。

## 3. 用脚本固定参数，用双端检查保护现场

项目可以保存 `scripts/sync-to-gpu.sh`：

```bash
#!/usr/bin/env bash
set -euo pipefail

PROJECT_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
SOURCE_DIR="$PROJECT_ROOT/"
DESTINATION="gpu-laptop:~/projects/my-project/"
DRY_RUN=()

if [[ "${1:-}" == "--dry-run" ]]; then
  DRY_RUN=(--dry-run)
fi

printf 'source: %s\n' "$SOURCE_DIR"
printf 'destination: %s\n' "$DESTINATION"

rsync -av \
  "${DRY_RUN[@]}" \
  --exclude-from="$PROJECT_ROOT/.rsyncignore" \
  "$SOURCE_DIR" \
  "$DESTINATION"
```

```bash
chmod +x scripts/sync-to-gpu.sh
./scripts/sync-to-gpu.sh --dry-run
```

脚本能固定参数，无法判断 Ubuntu 是否已有尚未回收的修改。重要同步前分别查看两端：

```bash
cd ~/Projects/my-project
printf 'MAC\n'
hostname
pwd
git branch --show-current
git status --short
git rev-parse --short HEAD

ssh gpu-laptop '
  cd ~/projects/my-project &&
  printf "UBUNTU\n" &&
  hostname &&
  pwd &&
  git branch --show-current &&
  git status --short &&
  git rev-parse --short HEAD
'
```

Ubuntu 工作区有来源不明的源码修改时，先回收或放弃这些变化，再决定是否覆盖。双端状态清楚后执行正式同步：

```bash
./scripts/sync-to-gpu.sh
```

## 4. Ubuntu 的临时修复通过分支或补丁回收

远端修改已经成熟时，在 Ubuntu 建立独立分支、运行测试并提交，再由 Mac fetch 后阅读完整差异。Git 的暂存、提交、PR 和恢复方法见 Part 04，本章不再复制整套流程。

修改尚不适合提交时，可以在 Ubuntu 导出已跟踪文件相对 `HEAD` 的补丁：

```bash
cd ~/projects/my-project
git status --short
git diff --binary HEAD > ~/ubuntu-runtime.patch
git ls-files --others --exclude-standard \
  > ~/ubuntu-runtime-untracked.txt
```

Mac 拉回并在独立分支检查：

```bash
scp gpu-laptop:~/ubuntu-runtime.patch ~/Downloads/
scp gpu-laptop:~/ubuntu-runtime-untracked.txt ~/Downloads/

less ~/Downloads/ubuntu-runtime.patch
cat ~/Downloads/ubuntu-runtime-untracked.txt
git apply --check ~/Downloads/ubuntu-runtime.patch
git apply ~/Downloads/ubuntu-runtime.patch
```

`git diff HEAD` 不包含未跟踪文件正文，因此清单中的重要源码还要逐项回收；`.env`、数据和凭据不应进入补丁或下载目录。

## 5. 结果反向回传，并做一次完整练习

Ubuntu 的训练结果回到 Mac 时，先从轻量证据开始：

```bash
mkdir -p ~/ML-Runs/my-project

rsync -av --dry-run \
  --include '*/' \
  --include 'config.yaml' \
  --include 'command.txt' \
  --include 'environment.txt' \
  --include 'metrics.json' \
  --include 'metrics.jsonl' \
  --include '*.png' \
  --include '*.csv' \
  --include '*.sha256' \
  --exclude '*' \
  gpu-laptop:~/runs/my-project/ \
  ~/ML-Runs/my-project/
```

include/exclude 从上到下匹配，确认清单后去掉 `--dry-run`。大型 checkpoint 可以单独回传，并避开训练程序正在写入的文件。

第一次练习可以使用最小项目：

```bash
# Mac
mkdir -p ~/Projects/gpu-sync-demo/scripts
cd ~/Projects/gpu-sync-demo
printf 'print("hello gpu node")\n' > main.py
printf '.git/\n.venv/\n__pycache__/\n.env\nruns/\n' \
  > .rsyncignore
git init
git add main.py .rsyncignore
git commit -m "chore: create GPU sync demo"
```

把同步脚本的项目名改为 `gpu-sync-demo`，预演、同步并在 Ubuntu 运行：

```bash
./scripts/sync-to-gpu.sh --dry-run
./scripts/sync-to-gpu.sh

ssh gpu-laptop '
  cd ~/projects/gpu-sync-demo &&
  hostname &&
  pwd &&
  python3 main.py
'
```

让 Ubuntu 生成一个结果文件，再拉回 Mac：

```bash
ssh gpu-laptop '
  mkdir -p ~/runs/gpu-sync-demo/test-run &&
  printf "status=ok\n" > ~/runs/gpu-sync-demo/test-run/result.txt
'

mkdir -p ~/ML-Runs/gpu-sync-demo
rsync -av --dry-run \
  gpu-laptop:~/runs/gpu-sync-demo/ \
  ~/ML-Runs/gpu-sync-demo/
rsync -av \
  gpu-laptop:~/runs/gpu-sync-demo/ \
  ~/ML-Runs/gpu-sync-demo/
cat ~/ML-Runs/gpu-sync-demo/test-run/result.txt
```

这条练习建立了明确方向：Mac 源码到 Ubuntu，Ubuntu 运行产生结果，结果再回到 Mac。后续长任务沿用同一主副本原则，并把运行目录、日志和 checkpoint 交给对应章节管理。
