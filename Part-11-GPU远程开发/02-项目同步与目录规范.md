# 02 项目同步与目录规范

Mac 与 Ubuntu 协作时，最容易出问题的不是 SSH，而是两台机器都以为自己手里的代码才是最新版。

推荐先确定一个原则：

```text
Mac = 主要编辑端
Ubuntu = 主要运行端
```

也可以反过来把 Ubuntu 设为主副本，但不能两边同时都当主副本。

---

## 1. 推荐目录布局

Mac：

```text
~/Projects/my-project/      源码
~/ML-Runs/my-project/       拉回的实验结果
```

Ubuntu：

```text
~/projects/my-project/      源码
~/datasets/                 数据集
~/models/                   模型权重
~/runs/my-project/          实验输出
```

源码、数据、模型和实验结果分开，能避免：

- 数据集进入 Git；
- checkpoint 堆进源码目录；
- AI CLI 扫描几十 GB 无关文件；
- rsync 把缓存和虚拟环境来回传输。

---

## 2. Git 和 rsync 各负责什么

Git 适合：

- 源码；
- 文档；
- 配置模板；
- 小型脚本；
- 可审查历史；
- 多人协作。

rsync 适合：

- Mac 与 Ubuntu 间快速同步工作区；
- 数据集；
- 模型；
- 训练结果；
- 尚未提交但需要远程试跑的代码。

不要用 rsync 代替版本历史，也不要用普通 Git 搬运大型模型和训练结果。

---

## 3. 两种稳定工作模式

### 模式 A：Git 为主

Mac 修改并提交：

```bash
git status
git add 明确文件
git diff --cached
git commit -m "描述本次修改"
git push
```

Ubuntu 更新：

```bash
cd ~/projects/my-project
git status
git pull --ff-only
```

适合长期项目和多人协作。

### 模式 B：Mac 单向 rsync 到 Ubuntu

先预演：

```bash
rsync -av --dry-run \
  --exclude-from='.rsyncignore' \
  ~/Projects/my-project/ \
  gpu-laptop:~/projects/my-project/
```

确认后去掉 `--dry-run`。

适合个人局域网中的快速试验。它能同步未提交代码，但不会替你保存清晰历史。

推荐组合：

```text
Git
→ 负责正式版本

rsync
→ 负责快速试跑和大型文件
```

---

## 4. 源路径末尾的斜杠很重要

下面两条命令含义不同：

```bash
rsync -av source/ host:target/
```

表示同步 `source` 目录里的内容。

```bash
rsync -av source host:target/
```

通常会在目标中创建或更新一个名为 `source` 的目录。

正式执行前始终使用 `--dry-run`，并阅读实际文件列表。

---

## 5. 建立 `.rsyncignore`

示例：

```text
.git/
.venv/
venv/
__pycache__/
.pytest_cache/
.mypy_cache/
.ruff_cache/
node_modules/
.env
.env.*
runs/
checkpoints/
*.log
.DS_Store
```

`.gitignore` 和 `.rsyncignore` 作用不同：

- `.gitignore` 控制 Git；
- `.rsyncignore` 只有在 rsync 命令中显式引用才生效。

如果 Ubuntu 自己维护 Git 仓库，通常应排除 `.git/`，避免 Mac 的仓库元数据覆盖 Ubuntu 当前状态。

---

## 6. 不要默认使用 `--delete`

`--delete` 会删除目标端存在、但源端不存在的文件。

这对严格镜像有用，但也可能删除：

- Ubuntu 上独立生成的配置；
- 训练结果；
- checkpoint；
- 临时调试文件；
- 远端尚未同步回来的修改。

使用前至少：

```bash
rsync -av --dry-run --delete ...
```

确认删除列表，并保证目标端没有独立数据。新手同步脚本初版不要加入 `--delete`。

---

## 7. 一个带预演模式的同步脚本

项目中创建：

```text
scripts/sync-to-gpu.sh
```

内容：

```bash
#!/usr/bin/env bash
set -euo pipefail

SOURCE_DIR="$(cd "$(dirname "$0")/.." && pwd)/"
DESTINATION="gpu-laptop:~/projects/my-project/"
DRY_RUN=()

if [[ "${1:-}" == "--dry-run" ]]; then
  DRY_RUN=(--dry-run)
fi

rsync -av \
  "${DRY_RUN[@]}" \
  --exclude-from="$SOURCE_DIR.rsyncignore" \
  "$SOURCE_DIR" \
  "$DESTINATION"
```

赋予权限：

```bash
chmod +x scripts/sync-to-gpu.sh
```

先运行：

```bash
./scripts/sync-to-gpu.sh --dry-run
```

确认后：

```bash
./scripts/sync-to-gpu.sh
```

脚本减少重复输入，但不会自动替你判断路径是否合理。

## 8. 源码和结果保持单向

推荐：

```text
源码
Mac → Ubuntu

实验结果
Ubuntu → Mac
```

拉回结果先预演：

```bash
rsync -av --dry-run \
  gpu-laptop:~/runs/my-project/ \
  ~/ML-Runs/my-project/
```

只拉回指标和图表：

```bash
rsync -av --dry-run \
  --include '*/' \
  --include 'metrics.json' \
  --include 'metrics.jsonl' \
  --include 'config.yaml' \
  --include '*.png' \
  --include '*.csv' \
  --exclude '*' \
  gpu-laptop:~/runs/my-project/ \
  ~/ML-Runs/my-project/
```

复杂 include/exclude 规则必须预演。

---

## 9. Ubuntu 临时改了代码怎么办

不要直接反向 rsync 整个项目覆盖 Mac。

更稳妥的流程：

```text
Ubuntu 创建分支
→ 提交修改
→ 推送远程
→ Mac 拉取或 cherry-pick
```

至少也应先用 Git diff 导出补丁，而不是让两台机器互相覆盖。

---

## 10. 数据集和模型路径不要写死用户名

Ubuntu 可以使用：

```text
~/datasets/dataset-name/
~/models/model-name/
```

项目通过环境变量或本地配置引用：

```bash
export DATA_DIR="$HOME/datasets/dataset-name"
export MODEL_DIR="$HOME/models/model-name"
```

不要把真实用户名、API Key 或私人绝对路径写进公共配置。可以提交示例文件：

```text
config.example.yaml
.env.example
```

真实本地配置加入 `.gitignore`。

---

## 11. 训练前固定检查

Ubuntu 项目目录中：

```bash
hostname
pwd
git status
git rev-parse --short HEAD
python --version
python -c 'import sys; print(sys.executable)'
nvidia-smi
```

确认：

- 确实在 Ubuntu；
- 目录和分支正确；
- 代码版本正确；
- Python 环境正确；
- GPU 可见；
- 没有意外工作区修改。
