# 04 权限与安全边界总览

> 最近核对：2026-07-30

AI CLI 不只是聊天界面。它可能读取项目、修改文件、运行命令、访问网络、调用 MCP、执行 Hook、连接远程机器，甚至通过 Docker 或云工具影响项目外资源。

判断它是否安全，不能只问“这个工具靠谱吗”，而要拆成五层：

```text
任务边界
→ 你要求它做什么

审批策略
→ 哪些操作需要人工确认

Sandbox 或权限规则
→ 技术上允许访问哪里

操作系统与外部工具权限
→ 当前用户实际拥有什么能力

恢复能力
→ 出错后哪些内容能够撤销
```

任何一层过宽，都可能扩大影响。

## 1. Prompt 不是技术权限

在 Prompt 中写：

```text
不要读取 ~/.ssh
```

属于任务指令。它能帮助模型理解边界，但不能保证底层进程一定无法访问该目录。

真正的技术限制可能来自：

- 客户端 Sandbox；
- Allow/Deny 规则；
- 项目工作区挂载；
- 容器或虚拟机；
- 操作系统用户权限；
- 网络策略；
- MCP 或插件权限。

正确做法是：

```text
Prompt 明确边界
+
客户端限制能力
+
操作系统只提供必要权限
```

不要只依赖其中一层。

## 2. 审批和 Sandbox 不是同一件事

审批回答：

```text
这一步执行前要不要问人？
```

Sandbox 回答：

```text
即使获准，进程实际能访问哪里？
```

例如：

```text
自动批准运行 pytest
```

不代表 Agent 可以写系统目录；反过来，Sandbox 范围很大，也不代表每条命令都会自动执行。

Claude Code、Codex 和 Grok 的名称与配置方式不同，但都应分别理解“询问策略”和“活动边界”。具体设置见各自权限章节。

## 3. 从正确目录启动

启动前执行：

```bash
hostname
whoami
pwd
git status --short
```

尽量从项目根目录启动，不要在：

```text
~
Desktop
Downloads
包含多个项目的父目录
```

直接启动高权限 Agent。

读取本身也有风险。Agent 看到的 `.env`、商业文档、SSH 配置、浏览器数据或其他项目内容，可能进入上下文、日志或外部工具调用。

## 4. 读取范围与写入范围分开

一个任务可能需要读取多个模块，但只修改两个文件：

```text
允许读取：
- src/
- tests/
- pyproject.toml

只允许修改：
- src/parser.py
- tests/test_parser.py
```

完成后检查：

```bash
git status --short
git diff --name-status
git diff --stat
git diff
```

还要检查 Git 看不到的文件：

```bash
find . -type f -size +50M -print
```

避免 Agent 顺手生成大型缓存、模型或日志。

## 5. Shell 命令必须结合执行上下文判断

批准命令前确认：

```text
在哪台机器？
哪个用户？
哪个目录？
变量展开后路径是什么？
是否需要 sudo？
会修改文件、服务、网络还是数据？
是否有 dry run？
失败后怎样恢复？
```

下面操作通常不适合普通自动批准：

- `sudo`；
- 删除或覆盖大量文件；
- Git 历史重写和强制推送；
- SSH、防火墙、驱动和系统服务变更；
- 数据库迁移；
- Docker Volume 删除；
- 批量依赖升级；
- 对远程机器执行高影响命令；
- 生产环境操作。

## 6. 网络权限同时包含下载与上传

批准联网前确认：

- 目标域名；
- 请求是下载还是上传；
- 是否会发送源码、日志、Prompt 或凭据；
- 是否经过第三方代理或本地网关；
- 是否产生 API 费用；
- 是否连接内部或生产服务。

查询公开文档、下载锁文件中的依赖、向第三方上传整个仓库，风险完全不同。

使用 CC Switch、Cockpit Tools、企业 Gateway 或其他本地路由时，还要确认最终 Provider、Base URL、日志和请求链。详见 Part 10C。

## 7. 凭据可以被程序使用，不代表应被模型看到

常见敏感信息：

- API Key；
- OAuth Token、Refresh Token、Cookie；
- SSH 私钥；
- 数据库密码；
- 云平台凭据；
- 内部服务地址；
- 账号缓存。

任务中应写：

```text
程序从 MY_API_TOKEN 环境变量读取凭据。
不要读取、打印、记录或修改其真实值。
```

不要粘贴真实值到 Prompt、日志、Issue、PR 或截图。

只检查变量是否存在：

```bash
if [ -n "${MY_API_TOKEN:-}" ]; then
  echo 'MY_API_TOKEN is set'
else
  echo 'MY_API_TOKEN is not set'
fi
```

不要执行 `env` 后把完整结果交给 Agent。

密钥一旦泄露，删除文件不够，还要在对应平台撤销或轮换。

## 8. Git 是源码恢复工具，不是万能备份

Git 通常能管理：

- 已跟踪源码；
- 分支；
- 提交；
- diff。

Git 不一定能恢复：

- 未跟踪文件；
- 数据库；
- Docker Volume；
- 数据集和模型；
- 远程机器独立数据；
- 已上传外部服务的内容；
- 运行中的训练状态。

因此要分开：

```text
Git
→ 源码版本

备份和 checkpoint
→ 数据与运行状态

权限控制
→ 限制影响范围
```

## 9. Worktree 不是安全沙箱

Git Worktree 可以隔离工作目录和分支，但通常仍共享：

- 同一用户主目录；
- 环境变量；
- SSH 密钥；
- Docker daemon；
- 网络；
- 数据集和模型缓存；
- 部分 Git 仓库元数据。

它适合避免两个 Agent 同时改同一个工作区，不足以运行不可信代码。

## 10. 容器也不是自动安全

容器隔离会被以下配置明显削弱：

- `--privileged`；
- 挂载 Docker Socket；
- 挂载整个 `$HOME`；
- 挂载 `~/.ssh` 或云凭据；
- 使用 host network；
- 共享宿主机设备；
- 以 root 运行并写入宿主机 Bind Mount。

运行 Agent 生成的未知代码前，先检查挂载、网络、用户和设备权限。

## 11. 远程开发机比本地练习目录风险更高

大致风险层级：

```text
本地临时目录
< 本地真实项目
< 个人远程开发机
< 团队共享环境
< 生产环境
```

在 Ubuntu GPU 机器启动 Agent 前执行：

```bash
hostname
whoami
pwd
git status --short
nvidia-smi
```

默认禁止 Agent：

- 修改 SSH、防火墙和 Tailscale；
- 安装或删除驱动；
- 修改系统服务；
- 删除 datasets、models、runs；
- 停止不属于当前任务的 GPU 进程；
- 读取其他项目和凭据；
- 自动清理磁盘。

训练代码和系统管理应拆成不同任务，并使用不同权限。

## 12. MCP、Hooks、Plugins 和 Skills 扩大能力链

它们可能：

- 自动执行命令；
- 访问第三方服务；
- 读取更多目录；
- 改变 Agent 的默认行为；
- 将数据发送到外部系统。

安装或启用前确认：

- 来源和维护状态；
- 配置作用域；
- 读取与写入权限；
- 网络目标；
- 凭据来源；
- 日志位置；
- 是否自动执行；
- 如何禁用和卸载。

项目仓库中的配置也可能触发扩展。克隆陌生仓库后，不要未经检查就授予信任和高权限。

## 13. 自动批准只适合明确、可回滚的小动作

适合自动化的例子：

- 读取当前项目；
- 修改指定文件；
- 运行固定测试；
- 执行 Lint；
- 生成可人工审查的报告。

不适合默认自动批准：

- 网络上传；
- 安装未知依赖；
- `sudo`；
- 数据删除；
- 远程系统变更；
- Git push、merge 和历史重写；
- 生产部署；
- 账号和凭据操作。

自动批准减少的是点击次数，不是风险本身。

## 14. 高风险命令先要求变更卡片

让 Agent 先输出：

```text
主机：
用户：
目录：
完整命令：
读取内容：
修改内容：
网络目标：
需要权限：
可能中断：
备份或 dry run：
成功验证：
失败恢复：
```

无法清楚说明影响的命令，不应执行。

## 15. 独立复核也需要限制权限

复核者通常只需要：

- 原始需求；
- Git diff；
- 测试结果；
- 相关文件。

不需要写权限、生产凭据和系统管理能力。只读审查应尽量使用只读模式或隔离副本。

## 16. 一份通用安全任务头

```text
当前主机：
当前用户：
当前目录：
当前分支：

只允许读取：

只允许修改：

允许执行：

禁止：
- sudo；
- 访问项目外目录；
- 读取或打印凭据；
- 安装依赖；
- 访问未列出的网络；
- 删除数据；
- 修改系统服务；
- git add、commit、push、reset、clean 或 rebase。

需要扩大范围时停止，给出理由、完整命令、影响、验证和回滚方案。
```

## 17. 任务结束后的安全检查

```bash
git status --short
git diff --name-status
git diff --stat
git diff
```

同时检查：

- 新的大文件；
- 日志是否含密钥；
- `.env` 是否被跟踪；
- 后台进程；
- 容器和端口；
- 远程服务状态；
- API 用量和外部调用；
- 临时凭据是否需要撤销。

安全不是启动前点一次按钮，而是整个任务过程中持续确认影响范围。
