# 01 安装、认证与第一次启动

> 最近核对：2026-07-29
>
> Claude Code 更新频繁。安装方式、认证入口、权限模式和参数应同时以本机 `claude --help`、`claude doctor` 与当前官方文档为准。

Claude Code 是运行在终端中的编程 Agent。客户端负责读取项目、调用工具、编辑文件、运行命令和显示权限请求；模型后端负责理解 Prompt 和生成内容。安装客户端与选择模型供应商是两件不同的事，排错时必须分层判断。

本章完成四件事：选择一种安装方式、确认实际运行的二进制、完成正规认证、从一个练习项目以 Plan 模式开始第一次会话。

## 1. 先检查系统和当前环境

Claude Code 当前官方支持 macOS、Ubuntu、Debian、Alpine、Windows 和 WSL 等环境。Mac 与 Ubuntu 应分别安装，不要把一台机器的可执行文件和配置目录整体复制到另一台。

在准备安装的终端中执行：

```bash
hostname
uname -a
uname -m
printf '%s\n' "$SHELL"
git --version
```

还应确认当前机器、当前用户和安装目标。例如，通过 SSH 登录 Ubuntu 后安装，得到的是 Ubuntu 上的 Claude Code，不是 Mac 上的版本。

如果此前安装过，先检查：

```bash
type -a claude
command -v claude
claude --version 2>/dev/null || true
```

不要在不清楚现状时同时运行原生安装器、Homebrew、apt 和 npm。多条安装路线并存，会让 PATH、更新机制和卸载方式互相混淆。

## 2. 推荐路线：官方原生安装

Claude Code 当前官方将原生安装列为推荐方式。macOS、Linux 和 WSL 的官方命令形式是：

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

任何 `curl | bash` 都会直接执行网络返回的脚本。执行前至少确认：

- URL 是官方域名；
- 当前文档仍给出这条命令；
- 网络没有被不可信代理或镜像替换；
- 当前用户和安装目录正确；
- 没有把 API Key、Cookie 或密码拼进命令。

希望跟随延迟一段时间、跳过重大回归的 stable 渠道时，官方安装器支持：

```bash
curl -fsSL https://claude.ai/install.sh | bash -s stable
```

原生安装通常把启动器放在：

```text
~/.local/bin/claude
```

版本文件位于用户目录下的 Claude 安装区域。安装完成后如果出现 `command not found`，先检查 PATH：

```bash
ls -l ~/.local/bin/claude
printf '%s\n' "$PATH" | tr ':' '\n'
```

不要因为新终端暂时找不到命令就重复执行安装脚本。

## 3. Mac 可选路线：Homebrew Cask

Mac 上也可以使用 Homebrew：

```bash
brew install --cask claude-code
```

当前官方提供两个 Cask 渠道：

```text
claude-code
→ stable 渠道

claude-code@latest
→ 最新版本渠道
```

安装最新渠道：

```bash
brew install --cask claude-code@latest
```

不要同时安装两个渠道。检查：

```bash
brew list --cask | grep 'claude-code'
type -a claude
claude --version
```

Homebrew 安装默认不会由 Claude Code 自己自动更新，需要使用对应命令：

```bash
brew upgrade claude-code
```

或：

```bash
brew upgrade claude-code@latest
```

不要为了更新 Claude Code 而无差别运行整个 Homebrew 全量升级，尤其是在比赛、演示和重要项目期间。

## 4. Ubuntu 可选路线：官方 apt 仓库

Claude Code 当前也发布签名的 Linux 软件仓库。长期由系统包管理器维护时，可以按官方 Setup 页面配置 apt stable 或 latest 仓库。

这条路线会涉及：

```text
下载并核对 Anthropic 签名密钥
→ 添加官方 apt 仓库
→ apt update
→ apt install claude-code
```

仓库密钥指纹和仓库地址可能更新，应直接从官方文档复制并核对，不在本书中永久固定完整安装脚本。

安装后检查：

```bash
dpkg -l | grep claude-code
type -a claude
claude --version
```

通过 apt 安装的版本使用系统包管理器升级，不应再让另一个安装器覆盖同一路径。

## 5. npm 仍可用，但不再是默认首选

Claude Code 仍提供 npm 全局包：

```bash
npm install -g @anthropic-ai/claude-code
```

截至本次核对，新版 npm 包要求 Node.js 22 或更高版本。检查：

```bash
node --version
npm --version
npm prefix -g
```

不要使用：

```bash
sudo npm install -g @anthropic-ai/claude-code
```

这可能制造 root 所有的全局包和权限问题。需要升级 npm 安装时，官方建议明确安装 latest：

```bash
npm install -g @anthropic-ai/claude-code@latest
```

npm 包最终安装的也是平台对应的原生二进制。Node.js 主要参与安装过程，但版本和可选依赖仍会影响安装是否完整。

## 6. 安装后先确定实际调用的是哪一个版本

统一检查：

```bash
type -a claude
command -v claude
claude --version
claude doctor
claude --help
```

`claude doctor` 是只读诊断入口，可以检查安装健康、设置文件错误、更新状态和常见警告，不会直接进入项目会话。

如果 `type -a` 显示多个路径，例如：

```text
/Users/name/.local/bin/claude
/opt/homebrew/bin/claude
```

说明原生安装与 Homebrew 可能同时存在。Shell 从 PATH 前到后选择第一个命令。先决定保留哪种安装方式，再按各自卸载说明清理另一份，不要继续安装第三份来覆盖问题。

## 7. 认证与模型供应商要分开理解

Claude Code 客户端可以通过多种正规方式获得模型能力：

```text
Claude Pro / Max / Team / Enterprise 账户
Anthropic Console API
组织管理的认证方式
Amazon Bedrock
Google Cloud 的受支持平台
Microsoft Foundry
企业 LLM Gateway
兼容供应商接口
```

直接运行：

```bash
claude
```

在没有其他认证配置时，通常会引导浏览器登录。当前官方说明中，Claude Code 需要支持的付费 Claude 账户或 Console 账户；Claude.ai 免费计划不包含 Claude Code 使用权限。

如果当前环境设置了 `ANTHROPIC_API_KEY`，客户端可能改为提示批准该 Key，而不是打开浏览器。不要把 API Key 打印到终端、截图或聊天中。

只检查变量是否存在：

```bash
test -n "$ANTHROPIC_API_KEY" && echo 'ANTHROPIC_API_KEY is set'
test -n "$ANTHROPIC_AUTH_TOKEN" && echo 'ANTHROPIC_AUTH_TOKEN is set'
printf 'base_url=%s\n' "${ANTHROPIC_BASE_URL:-<not set>}"
```

这些变量可能来自 Shell、`settings.json`、企业启动器或第三方切换工具。详细优先级见 Part 10C。

## 8. 不要把网页会话信息改造成客户端认证

本手册不推荐：

- 导出浏览器 Cookie；
- 复制 Session Token 或 Refresh Token；
- 共享 Claude Code 认证缓存；
- 使用别人购买或导出的账号文件；
- 把网页登录状态导入第三方程序；
- 使用来源不明的“订阅转 API”；
- 将账号密码交给配置切换工具。

网页订阅、OAuth 登录、Console API 和第三方 API 是不同产品与计费链路。正规接入应使用供应商明确提供的登录、API Key、云身份或企业网关。

## 9. 更新机制取决于安装方式

原生安装默认支持后台检查和自动更新。查看当前版本和更新诊断：

```bash
claude --version
claude doctor
```

原生安装可手动更新：

```bash
claude update
```

当前官方渠道包括：

```text
latest
→ 较快获得新功能

stable
→ 通常延迟约一周，并跳过重大回归版本
```

渠道可以通过 `/config` 或用户设置控制。Homebrew、apt、dnf、apk 和 npm 应使用各自包管理器更新。

不要让两种更新机制同时控制同一个 `claude` 路径。

## 10. 建立安全的第一次练习项目

创建独立目录：

```bash
mkdir -p ~/terminal-practice/claude-first-project
cd ~/terminal-practice/claude-first-project
```

创建一个最小 Python 文件和测试：

```bash
cat > greeting.py <<'PY'
def greet(name: str) -> str:
    return f"Hello, {name}!"
PY

cat > test_greeting.py <<'PY'
import unittest

from greeting import greet


class GreetingTests(unittest.TestCase):
    def test_greet(self):
        self.assertEqual(greet("Claude"), "Hello, Claude!")


if __name__ == "__main__":
    unittest.main()
PY
```

运行基线测试：

```bash
python3 -m unittest -v
```

初始化 Git：

```bash
git init
git add greeting.py test_greeting.py
git commit -m "test: add greeting baseline"
```

如果 Git 尚未配置用户名和邮箱，应先按 Git 章节完成本机身份配置，不要让 Claude Code替你猜。

## 11. 第一次从 Plan 模式开始

确认目录和状态：

```bash
pwd
git status
git branch --show-current
```

启动：

```bash
claude --permission-mode plan
```

进入后先要求只读调查：

```text
当前阶段只读，不要修改文件、安装依赖、访问外部服务或执行 Git 写操作。

请检查当前目录、Git 状态、Python 文件和测试，并回答：
1. 项目当前行为是什么；
2. 测试怎样运行；
3. 如果要让 greet 去除名字两端空格，需要修改哪些文件；
4. 应先增加什么失败测试；
5. 哪些结论已经由文件证明，哪些仍是推测。
```

Plan 模式用于读取、分析和形成计划，不应直接修改源文件。即使当前版本允许某些经过分类器确认的只读命令运行，也要人工检查它实际读取和执行了什么。

## 12. 确认计划后再进入执行阶段

退出 Plan 模式或新开默认权限会话前，先人工确认：

- 修改范围是否只包含预期文件；
- 是否先补充失败测试；
- 是否需要安装依赖；
- 是否需要网络；
- 是否会操作 Git；
- 测试命令是否真实存在。

执行阶段可以使用普通交互模式：

```bash
claude
```

输入：

```text
只执行下面一个阶段：

先只修改 test_greeting.py，增加一个测试，要求 greet("  Alice  ") 返回 "Hello, Alice!"。
不要修改 greeting.py，不要安装依赖，不要执行 git add、commit 或 push。
运行 python3 -m unittest -v，确认新增测试因为预期原因失败，然后停止汇报。
```

这让第一次任务形成明确停止点，而不是一句“帮我改好”后自动跑到底。

## 13. 交互模式、带初始 Prompt 和 Print 模式

普通交互：

```bash
claude
```

带初始任务：

```bash
claude "解释当前项目结构，先不要修改文件"
```

一次性 Print 模式：

```bash
claude -p "只读总结当前目录中的 Python 文件"
```

结构化输出：

```bash
claude -p \
  "列出当前项目风险" \
  --output-format json
```

Print 模式适合脚本和只读分析，但自动化任务必须明确工具范围、权限模式、失败条件、输出格式和工作目录。不要把跳过权限提示的参数写进全局别名。

## 14. 会话继续与恢复

继续当前目录最近的会话：

```bash
claude --continue
```

简写：

```bash
claude -c
```

恢复指定会话或打开会话选择器：

```bash
claude --resume
```

按名称或 ID 恢复：

```bash
claude --resume auth-refactor
```

可以在启动时命名会话：

```bash
claude --name greeting-whitespace
```

恢复时创建新的分叉会话：

```bash
claude --resume greeting-whitespace --fork-session
```

会话保存的是对话上下文，不是 Git 快照。恢复后先输入：

```text
先不要继续修改。
重新检查 pwd、Git 分支、git status、git diff、项目规则、依赖和测试状态。
说明现实状态与旧会话上下文不一致的地方。
```

## 15. Mac 与 Ubuntu 分别安装和配置

两台机器可以共享：

- Git 仓库；
- 项目级 `CLAUDE.md`；
- `.claude/settings.json` 中适合团队共享的规则；
- 测试和依赖声明；
- Prompt 模板。

不要直接同步：

- Claude Code 可执行文件；
- 原生安装版本目录；
- 全局 npm 目录；
- 登录缓存；
- `~/.claude` 整体；
- 一台机器的 `.venv`；
- 含真实 API Key 的本地配置。

Mac 与 Ubuntu 可能使用不同供应商、模型、网络和凭据。每次都应知道当前请求最终发送到哪里。

## 16. 每次启动前和结束后的固定检查

启动前：

```bash
hostname
pwd
git status
git branch --show-current
type -a claude
claude --version
```

任务约束：

```text
只允许修改明确列出的文件。
不要执行 git add、commit、push、reset、clean、merge 或 rebase。
安装依赖、访问网络、删除文件或扩大目录范围前先说明。
完成后列出修改文件、执行命令、测试结果、未验证内容和风险。
```

结束后：

```bash
git status --short
git diff --name-status
git diff --stat
git diff
```

Claude Code 的任务总结只是陈述，Git 差异和测试输出才是证据。

## 17. 常见故障

命令找不到或版本不对：

```bash
type -a claude
command -v claude
printf '%s\n' "$PATH" | tr ':' '\n'
claude --version
claude doctor
```

登录后仍反复要求认证：

```bash
env | grep -E '^ANTHROPIC_(BASE_URL|MODEL)=' || true
test -n "$ANTHROPIC_API_KEY" && echo 'API key is set'
test -n "$ANTHROPIC_AUTH_TOKEN" && echo 'Auth token is set'
```

不要打印完整凭据。

项目识别错误：

```bash
pwd
git rev-parse --show-toplevel
git status
```

npm 安装出现 `EBADENGINE`：

```bash
node --version
npm --version
```

新版 npm 包需要 Node.js 22+。更简单的处理通常是改用推荐的原生安装，而不是用 sudo 强行安装。
