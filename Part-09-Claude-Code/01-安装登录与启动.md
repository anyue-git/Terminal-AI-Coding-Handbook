# 01 安装、认证与第一次启动

> 最近核对：2026-07-29
>
> Claude Code 更新频繁。安装方式、认证入口和参数以本机 `claude --help`、`claude doctor` 与当前官方文档为准。

Claude Code 的第一次配置可以拆成三个问题：终端实际运行哪一份客户端，当前使用哪种认证与模型后端，以及 Claude 从哪个项目目录开始工作。本章只处理这三件事；完整练习见[AI CLI 快速上手](../00-快速开始/02-AI-CLI快速上手.md)。

## 1. 在每台机器上选择一条安装路线

Mac 与 Ubuntu 分别安装，不复制另一台机器的可执行文件、全局包目录或整个配置目录。安装前先看当前系统与已有命令：

```bash
hostname
uname -a
uname -m
printf '%s\n' "$SHELL"
git --version

type -a claude 2>/dev/null
command -v claude 2>/dev/null
claude --version 2>/dev/null || true
```

通过 SSH 登录 Ubuntu 后执行安装，得到的是 Ubuntu 上的客户端，不会同时安装到 Mac。已经存在 `claude` 时，先确认来源，不要叠加多套安装器。

当前官方推荐 macOS、Linux 和 WSL 使用原生安装器：

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

希望使用延迟重大更新的 stable 渠道：

```bash
curl -fsSL https://claude.ai/install.sh | bash -s stable
```

远程脚本会直接执行下载内容，运行前确认地址仍来自官方文档，并确认当前用户与安装目录。原生启动器通常位于 `~/.local/bin/claude`；安装后找不到命令时检查：

```bash
ls -l ~/.local/bin/claude
printf '%s\n' "$PATH" | tr ':' '\n'
```

Mac 也可以选择 Homebrew Cask，stable 与 latest 二选一：

```bash
brew install --cask claude-code
# 或
brew install --cask claude-code@latest
```

Ubuntu 可以按官方 Setup 页面配置签名 apt 仓库。仓库地址和密钥可能变化，本书不复制整段长期脚本。

npm 全局包仍可使用，但不再是默认首选；截至核对日期需要 Node.js 22 或更高版本：

```bash
node --version
npm --version
npm prefix -g
npm install -g @anthropic-ai/claude-code
```

全局目录权限异常时应修正 Node/npm 安装与 prefix，不使用 `sudo npm install -g` 绕过权限。

## 2. 确认实际二进制与更新来源

安装后统一运行：

```bash
type -a claude
command -v claude
claude --version
claude doctor
claude --help
```

`type -a` 同时显示 `~/.local/bin/claude`、Homebrew 或 npm 路径时，Shell 只会按 PATH 顺序执行其中一份。先决定保留哪种安装，再按相应卸载方法清理其他来源。

更新方式也要与安装方式对应。原生安装使用 `claude update` 及其 latest/stable 渠道；Homebrew、apt、dnf、apk 和 npm 由各自包管理器升级。两个更新器同时管理同一命令时，版本和路径问题会反复出现。

## 3. 区分账户认证、API 与模型后端

直接运行：

```bash
claude
```

在没有其他配置时，客户端通常引导浏览器登录。正规路线包括受支持的 Claude 账户、Anthropic Console API、组织管理认证、Amazon Bedrock、Google Cloud、Microsoft Foundry、企业 Gateway 和兼容供应商接口。这些路线对应不同的凭据、计费和数据处理主体。

排查认证与路由时，只查看变量是否存在以及非敏感元数据：

```bash
test -n "${ANTHROPIC_API_KEY:-}" && echo 'ANTHROPIC_API_KEY is set'
test -n "${ANTHROPIC_AUTH_TOKEN:-}" && echo 'ANTHROPIC_AUTH_TOKEN is set'
printf 'base_url=%s\n' "${ANTHROPIC_BASE_URL:-<not set>}"
```

不要输出 Key 正文。变量还可能来自用户 Settings、项目 Settings、组织管理、启动器或供应商切换工具。进入会话后使用 `/status` 查看最终认证和模型后端。

浏览器 Cookie、Session Token、Refresh Token 和他人账号缓存不属于正常认证接口。第三方后端的接入与恢复见[接入 DeepSeek 与第三方供应商](05-接入DeepSeek与第三方供应商.md)。

## 4. 从明确的项目目录第一次启动

先创建或选择一个可丢弃的 Git 练习项目，再从项目根目录启动：

```bash
cd ~/terminal-practice/claude-first-project
pwd
git rev-parse --show-toplevel
git status
claude --permission-mode plan
```

Plan 模式适合第一次调查。进入后运行：

```text
/status
/permissions
/context
```

确认客户端看到的目录、认证、模型、权限模式和项目规则。第一条请求可以很简单：

```text
只读检查当前项目，说明入口、测试命令和可能的最小修改范围，不修改文件。
```

首次练习不需要在本章重新创建一整套示例代码；可直接按照[AI CLI 快速上手](../00-快速开始/02-AI-CLI快速上手.md)完成调查、最小修改和 diff 复核。

Mac 与 Ubuntu 可以共享 Git 仓库、项目级 `CLAUDE.md`、不含秘密的 `.claude/settings.json` 和测试命令，但两台机器分别安装和登录。客户端二进制、全局 npm 目录、登录缓存、整个 `~/.claude`、`.venv` 和真实 Key 不应直接同步。

## 5. 常见安装与启动故障

命令找不到或版本不符合预期：

```bash
type -a claude
command -v claude
printf '%s\n' "$PATH" | tr ':' '\n'
claude --version
claude doctor
```

登录后反复要求认证时，查看 `/status`，再检查 Base URL、认证变量和 Settings 来源。npm 出现 `EBADENGINE` 时先核对 Node 版本；通常改用推荐的原生安装比使用 sudo 强装更清楚。

项目识别错误时检查：

```bash
pwd
git rev-parse --show-toplevel
git status
```

安装问题、认证问题和项目目录问题应分开处理。客户端能够启动以后，再进入权限、会话和大任务章节，不必在第一章同时配置所有高级功能。
