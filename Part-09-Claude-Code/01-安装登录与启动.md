# 01 安装、接入与启动

> 最近核对：2026-07-28
>
> Claude Code 更新较快。安装命令、认证入口和参数应同时参考本机 `claude --help` 与当前官方文档。

Claude Code 是运行在终端里的编程 Agent。它负责读取项目、调用工具、修改文件和显示权限请求；真正处理 Prompt 的模型后端，则可以来自 Anthropic 官方账户、Anthropic API、企业云平台、LLM Gateway，或者 DeepSeek 等兼容供应商。

所以第一次使用时要分成两件事：

1. 安装 Claude Code 客户端；
2. 选择认证方式和模型供应商。

安装的是方向盘，接入的是发动机。把两件事混在一起，排错时很容易不知道究竟是哪一层出了问题。

---

## 1. 先确认当前机器和基础环境

本手册主要覆盖 macOS 与 Ubuntu。先检查：

```bash
uname -m
git --version
echo "$SHELL"
```

准备使用 npm 安装时，再检查：

```bash
node --version
npm --version
```

当前官方文档仍要求 Node.js 18 或更高版本。安装前也要确认网络和所在地区满足所选供应商的服务条件。

---

## 2. 选择一种安装方式，不要多条路线一起堆

### npm 安装

当前常见方式是：

```bash
npm install -g @anthropic-ai/claude-code
```

不要因为 npm 出现权限错误就直接加 `sudo`。优先处理 Node.js 来源、用户级 npm 目录，或者改用官方提供的其他安装方式。

### 官方原生安装路线

Anthropic 也提供原生安装和迁移方式。具体命令和平台状态可能变化，应从官方 Setup 页面获取，不要长期复制论坛里的远程安装脚本。

已有安装可以先查看：

```bash
claude doctor
claude install --help
claude migrate-installer --help
```

同一台机器不要在不清楚现状时反复使用 npm、原生安装器和旧脚本。多装几份通常不会让 Claude 更聪明，只会让 PATH 更有故事。

---

## 3. 安装后先确认实际运行的是哪一个文件

```bash
type -a claude
claude --version
claude doctor
claude --help
```

如果 `type -a` 显示多个路径，可能同时存在：

- npm 全局版本；
- 原生或本地安装版本；
- 旧路径残留；
- 不同 Node.js 环境下的版本。

不要继续安装来“覆盖”冲突。先确认当前 Shell 最终调用的是哪个 `claude`。

---

## 4. 选择认证与模型后端

### Anthropic 官方账户或 API

Claude Code 官方支持通过 Claude App 订阅、Anthropic Console API 计费，以及组织配置的认证方式接入 Anthropic 模型。

适合：

- 需要 Claude 模型和最新 Claude Code 功能的完整兼容；
- 能够正常使用 Anthropic 服务；
- 不想维护模型映射或第三方端点。

### Amazon Bedrock 或 Google Vertex AI

企业环境可以通过受支持的云平台接入，由组织统一管理身份、费用和审计。

### DeepSeek 官方 Anthropic 兼容接口

不少读者并不使用 Anthropic 官方订阅。DeepSeek 官方提供了 Claude Code 接入文档和 Anthropic 兼容端点，可以保留 `claude` 客户端，同时把模型后端换成 DeepSeek。

这条路线使用的是 DeepSeek API Key，不是浏览器 Cookie，也不是把网页订阅“转换”为 API。

详细配置见：

- [接入 DeepSeek 与第三方供应商](05-接入DeepSeek与第三方供应商.md)

### 企业网关或其他第三方供应商

Claude Code 也可以连接团队部署的 LLM Gateway。CC Switch 一类工具可以帮助管理多个供应商配置，但它本身不是模型厂商，也不会替中转商的安全性和真实性背书。

无论使用哪种后端，都要确认：

- 请求最终发送给谁；
- 谁负责计费；
- 是否保存源码和 Prompt；
- 日志保留多久；
- API Key 存在哪里；
- 工具调用和模型映射是否完整兼容。

---

## 5. 不要用网页会话信息代替正规认证

本手册不推荐：

- 复制浏览器 Cookie；
- 导出 Session Token；
- 共享 Claude Code 认证缓存；
- 使用别人的 API Key；
- 把账号密码交给切换工具；
- 使用来源不明的“订阅转 API”；
- 将网页登录状态导入第三方程序。

正规路线应使用供应商明确提供的 OAuth、API Key、企业身份或正式网关。

---

## 6. 从项目根目录启动

```bash
cd ~/Projects/my-project
pwd
git status
git branch --show-current
claude
```

Claude Code 会把启动目录作为主要工作上下文。从家目录、下载目录或多个仓库的父目录启动，可能导致它读取无关文件、漏掉项目规则，或者在错误位置创建内容。

如果 `git status` 已经显示未提交修改，先弄清这些修改属于谁、属于哪个任务。

---

## 7. 第一次任务只做项目调查

进入 Claude Code 后先输入：

```text
当前阶段只读，不要修改文件、安装依赖、访问外部服务或执行 Git 写操作。

请检查当前目录、Git 状态、README、CLAUDE.md、依赖声明和测试配置，并回答：
1. 项目入口在哪里；
2. 主要模块如何组织；
3. 怎样运行和测试；
4. 当前任务可能涉及哪些文件；
5. 哪些目录不应修改；
6. 当前有哪些未提交改动；
7. 哪些结论仍是推测。

重要结论给出文件路径。
```

如果它找错入口或无法说明证据，不要直接进入修改阶段。

---

## 8. 交互模式和一次性运行

普通交互模式：

```bash
claude
```

带初始任务启动：

```bash
claude "解释项目架构，先不要修改文件"
```

一次性打印模式：

```bash
claude -p "只读总结当前项目结构"
```

需要结构化输出时，当前版本可查看：

```bash
claude -p "列出当前风险" --output-format json
```

非交互模式更适合已经限定好目录、工具、网络、最大轮数和失败条件的任务。不要把跳过权限提示的危险参数写成日常别名。

---

## 9. 继续旧会话前先重新核对现实

继续当前目录最近的会话：

```bash
claude --continue
```

简写：

```bash
claude -c
```

恢复指定会话：

```bash
claude --resume SESSION_ID
```

会话保存的是对话上下文，不是项目快照。恢复后先输入：

```text
先不要继续修改。
重新检查当前目录、Git 分支、未提交改动、项目规则、依赖文件和测试状态。
说明现实状态与旧会话上下文可能不一致的地方。
```

---

## 10. Mac 和 Ubuntu 应分别安装、分别配置

Mac 与 Ubuntu 可以共享 Git 仓库、项目级 `CLAUDE.md`、测试和依赖声明，但不要直接同步：

- Claude Code 可执行文件；
- 全局 npm 目录；
- 认证缓存；
- 平台相关二进制；
- 整个 `~/.claude` 配置目录；
- 一台机器的虚拟环境。

如果两台机器使用不同供应商或 API Key，应分别配置，并明确知道每台机器把请求发送到哪里。

---

## 11. 每次启动前和结束后检查什么

启动前：

```bash
hostname
pwd
git status
type -a claude
claude --version
```

任务中明确：

```text
只允许修改列出的文件。
不要执行 git add、commit 或 push。
安装依赖、访问网络、删除文件或扩大目录范围前先说明。
完成后列出修改文件、测试结果、未验证内容和风险。
```

结束后：

```bash
git status --short
git diff --name-status
git diff --stat
git diff
```

---

## 12. 常见故障

### 找不到命令或版本不对

```bash
type -a claude
echo "$PATH"
claude --version
claude doctor
```

### 仍然要求 Anthropic 登录

如果你本来准备使用 DeepSeek 或网关，检查当前 Shell 是否加载了正确的 Base URL 和认证变量，以及配置切换工具是否真的启用了 Claude Code 配置。不要打印完整 API Key。

### 项目识别错误

```bash
pwd
git rev-parse --show-toplevel
git status
```

### npm 权限错误

先检查 Node.js 来源、npm 全局目录和文件所有权，不要直接使用管理员权限重装。
