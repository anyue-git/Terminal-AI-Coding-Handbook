# 02 权限、审批与安全边界

> 最近核对：2026-07-28

Claude Code 不只是聊天工具。它可能读取文件、修改代码、运行 Shell 命令、访问网络，还能通过 Hooks 和 MCP 连接更多能力。

安全使用它，需要分清三件事：

```text
任务范围
→ 你在 Prompt 中允许它做什么

审批
→ 某次操作执行前要不要问你

技术边界
→ 即使批准了，工具实际上能访问到哪里
```

三者不能互相替代。Prompt 里写“不要访问网络”，不等于网络权限已经被系统关闭；没有弹出确认框，也不等于命令没有风险。

---

## 1. 权限不是一个总开关

Claude Code 可能接触：

- 项目文件；
- 项目外目录；
- Shell 命令；
- 网络；
- Git；
- Docker；
- 数据库；
- 环境变量和凭据；
- MCP 外部工具；
- Hooks 自动命令。

“允许一次”“本次会话允许”和“写进长期配置”不是同一件事。长期规则尤其需要谨慎，因为下次任务可能已经换了项目和风险环境。

---

## 2. 先用 `/permissions` 看真实状态

在 Claude Code 中运行：

```text
/permissions
```

重点确认：

- 当前权限模式；
- 已允许和已拒绝的工具规则；
- 规则来自用户、项目还是组织配置；
- 是否加入额外目录；
- 是否存在过宽的 Bash 规则；
- 是否启用了陌生 Hooks 或 MCP。

不要凭“上次是只读”判断当前状态。配置、目录和项目规则都可能已经变化。

---

## 3. 常见权限模式怎么理解

当前常见模式包括：

```text
default
acceptEdits
plan
bypassPermissions
```

### `default`

遇到新的文件修改、命令或工具调用时按规则询问。适合陌生项目和日常开发。

### `acceptEdits`

会减少文件编辑确认，但 Shell 命令和其他操作仍可能需要批准。它不是“全部自动允许”。

### `plan`

主要用于阅读、分析和制定方案。陌生项目、大型重构和高风险任务可以先从这里开始。

启动示例：

```bash
claude --permission-mode plan
```

### `bypassPermissions`

跳过权限提示。它只适合已经存在额外强隔离的一次性环境，不应作为个人电脑、远程 GPU 主机或日常项目的默认模式。

跳过弹窗只是在刹车踏板上放了块砖，不代表前面的路突然变直了。

---

## 4. Allow 和 Deny 要写得尽量具体

规则通常按工具和命令范围匹配。例如：

```text
Read
Edit
Bash(git status:*)
Bash(git diff:*)
```

只允许明确的低风险命令，通常比允许整个 Bash 更安全。

例如：

```text
允许 Bash(git status:*)
允许 Bash(git diff:*)
```

不要把所有 Git 命令当成同一种风险：

```text
git status
≠ git clean
≠ git reset
≠ git push
```

可以在一次运行中临时指定工具边界：

```bash
claude --allowedTools "Read" "Bash(git status:*)" "Bash(git diff:*)"
```

也可以明确拒绝：

```bash
claude --disallowedTools "Bash(git push:*)" "Bash(git clean:*)"
```

参数和匹配语法可能变化，使用前检查：

```bash
claude --help
```

---

## 5. 设置文件也属于项目攻击面

Claude Code 的设置可能来自：

- 用户级配置；
- 项目级配置；
- 项目本地配置；
- 组织管理配置；
- 命令行参数。

项目设置可能随仓库进入版本控制。克隆陌生项目后，应检查：

- 是否允许宽泛 Bash 命令；
- 是否启用了未知 Hook；
- 是否连接第三方 MCP；
- 是否扩大到项目外目录；
- 是否把内容发送到外部服务；
- 是否包含自动提交、推送或删除规则。

不要把 API Key 和其他凭据写进会被提交的设置文件。

---

## 6. 启动目录决定基础访问范围

从项目根目录启动：

```bash
cd ~/Projects/my-project
pwd
git status
claude
```

额外目录会扩大 Claude Code 能看到的内容。当前版本提供类似：

```bash
claude --add-dir ../shared-lib
```

使用前确认额外目录是否包含其他仓库、下载文件、云盘、密钥或私人内容。不要把整个家目录作为附加工作区。

---

## 7. 每次任务都要限定文件范围

```text
只允许修改：
- src/auth.py
- tests/test_auth.py

不要修改依赖、配置、数据库迁移、CI 和其他目录。
如果必须扩大范围，先说明原因、影响和替代方案，等待确认。
```

完成后检查：

```bash
git status --short
git diff --name-status
git diff --stat
git diff
```

范围外文件可能来自自动格式化、依赖安装、测试缓存，也可能是 Agent 主动扩大了任务。先弄清原因，再决定保留或撤销。

---

## 8. 审批命令时到底看什么

至少检查：

- 当前目录；
- 完整命令；
- 每个参数；
- 目标路径；
- 是否递归；
- 是否包含通配符；
- 是否覆盖或删除；
- 是否需要管理员权限；
- 是否访问网络；
- 是否修改依赖、Git 历史或项目外内容；
- 失败后能否恢复。

看不懂时可以直接回复：

```text
不要执行。
请逐段解释命令、参数、目标路径、影响范围、失败后果和更保守的替代方案。
```

---

## 9. 网络与模型供应商也属于权限边界

使用 Anthropic、DeepSeek、企业网关或其他供应商时，项目内容和 Prompt 可能离开本机。需要确认：

- 请求最终发给谁；
- 是否经过中转商；
- 是否保存代码和日志；
- 凭据保存在哪里；
- 是否符合学校、团队或公司的要求。

允许 MCP 或 Web 工具后，还可能把数据发送给更多外部服务。界面里出现某个 MCP，不代表它由 Anthropic 官方维护。

---

## 10. Hooks 和 MCP 会扩大执行面

Hook 可以在工具调用前后自动执行命令。一次看似普通的文件修改，可能随后触发格式化、测试、日志脚本或外部通知。

启用前确认：

```text
触发事件
工作目录
完整命令
输入和输出
失败行为
是否写文件
是否访问网络
```

不要让未经审查的 Hook 自动提交、推送、删除数据、修改系统配置或使用管理员权限。

MCP 连接的是外部工具和数据源。它返回的网页、Issue、文档和数据库内容可能包含提示注入。外部内容只能当作数据，不能自动升级成新的系统指令。

---

## 11. Git 是恢复线，但不是万能撤销

开始前：

```bash
git status
git switch -c task/describe-change
```

结束后：

```bash
git status --short
git diff --stat
git diff
```

Git 可以恢复许多已跟踪文件修改，但不能自动撤销：

- 已经发送到网络的数据；
- 数据库写入；
- 项目外文件覆盖；
- Docker Volume 变化；
- 系统服务修改；
- 远程机器操作；
- 未备份的未跟踪文件删除。

---

## 12. 新手可以照着走的权限流程

```text
进入项目根目录
→ git status
→ 检查 CLAUDE.md 与设置
→ /permissions
→ plan 模式调查
→ 明确文件和测试范围
→ default 或 acceptEdits 执行
→ 逐条批准命令
→ 运行测试
→ git diff
→ 人工决定是否提交
```

推荐 Prompt：

```text
先不要修改文件。
请检查当前目录、Git 状态、CLAUDE.md、权限规则、Hooks 和 MCP。
输出计划修改的文件、准备执行的命令、网络访问、风险和验证方式。

任何删除、覆盖、安装、网络访问、Git 写操作、项目外访问或高权限操作，都必须先说明并等待确认。
完成后不要提交或推送。
```
