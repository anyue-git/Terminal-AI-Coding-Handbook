# 02 权限、审批、Sandbox 与安全边界

> 最近核对：2026-07-29

Claude Code 的权限系统由几部分组成：Permission Mode 决定默认怎样处理工具调用，Allow/Ask/Deny 规则针对具体工具和命令，Sandbox 约束 Bash 及其子进程能访问的资源，Hooks 则能在工具执行前后增加项目闸门。它们共同影响当前会话，但职责并不相同。

通用的 Shell、网络、凭据、Docker 和远程主机风险见[权限与安全边界总览](../Part-12-AI开发工作流/04-权限与安全边界总览.md)。本章重点是怎样读懂 Claude Code 自己的实际权限状态。

## 1. 先查看当前会话，而不是沿用上次印象

从项目根目录启动 Claude Code：

```bash
cd PROJECT_ROOT
pwd
git status
claude
```

进入后运行 `/permissions`。这里应能看到当前模式、Allow/Ask/Deny 的来源、附加目录，以及已经加载的 Hooks、MCP、Plugins、Connector 和子 Agent。启动参数、用户设置、项目设置、组织策略和工作目录都会影响最终结果，因此上一次会话使用 Plan，不代表这一次仍然只读。

## 2. Permission Mode 决定默认处理方式

命令行可以指定：

```bash
claude --permission-mode MODE
```

当前常见模式如下：

- `manual`：界面中也称 default；未被规则预先处理的调用会询问用户，适合日常开发。
- `acceptEdits`：自动接受工作目录或附加目录中的文件编辑，Shell、网络和其他能力仍受规则控制。
- `plan`：用于探索和方案设计；当前版本可能允许部分被分类为只读的命令，不能只凭模式名称判断每条调用。
- `auto`：由后台安全判断自动批准与请求一致的调用，减少重复询问，但无法理解所有业务数据和远程副作用。
- `dontAsk`：不显示普通审批，未被提前允许的工具直接拒绝，适合白名单明确的自动化。
- `bypassPermissions`：跳过大多数提示，只适合外层已经隔离、数据可丢弃且没有真实凭据的一次性环境。

启动示例：

```bash
claude --permission-mode manual
claude --permission-mode acceptEdits
claude --permission-mode plan
claude --permission-mode auto
claude --permission-mode dontAsk
claude --permission-mode bypassPermissions
```

`--dangerously-skip-permissions` 不适合作为日常别名或团队脚本默认值。若任务只是调查，直接使用 Plan；进入修改阶段后再按实际文件和命令设置规则，比把所有项目长期放进高权限模式更容易理解。

## 3. Allow、Ask、Deny 针对具体工具

Claude Code 按 `Deny → Ask → Allow` 的类别顺序判断规则。宽泛 Deny 不会被更具体的 Allow 覆盖，例如已经拒绝 `Bash(aws *)` 时，再允许 `Bash(aws s3 ls)` 不能形成例外；需要例外应缩小拒绝范围。

规则既可以匹配工具，也可以包含 specifier：

```text
Bash
Read
Edit
WebFetch

Bash(git status)
Bash(git diff *)
Bash(python3 -m unittest *)
Read(./docs/**)
WebFetch(domain:docs.python.org)
Agent(Explore)
```

一个本机项目配置可以写在 `.claude/settings.local.json`：

```bash
mkdir -p .claude
cat > .claude/settings.local.json <<'JSON'
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": [
      "Bash(git status)",
      "Bash(git diff *)",
      "Bash(python3 -m unittest *)"
    ],
    "ask": [
      "Bash(git add *)",
      "Bash(git commit *)",
      "WebFetch(domain:*)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)",
      "Bash(git push *)",
      "Bash(git clean *)"
    ]
  }
}
JSON

python3 -m json.tool .claude/settings.local.json
claude doctor
```

用户级设置位于 `~/.claude/settings.json`，项目共享设置位于 `.claude/settings.json`，本机项目设置位于 `.claude/settings.local.json`。共享文件会随仓库进入其他人的环境，因此项目被信任前，应先读清其中的权限、Hooks、Plugins 和 MCP，而不是因为仓库来源熟悉就直接接受全部配置。

规则语法可能随版本调整。修改后重新进入 `/permissions`，确认实际匹配结果，而不要只检查 JSON 是否能解析。

## 4. Sandbox 与 `--add-dir` 改变实际访问范围

`Deny: Read(./.env)` 只约束 Claude Code 的 Read 工具，不保证任意 Python、Node 或 Shell 子进程无法打开同一文件。权限规则决定客户端是否发起工具调用；Sandbox 决定 Bash 及其子进程获准后能够访问哪些资源。内置工具、MCP 和 Connector 是否受同一 Sandbox 覆盖，需要按当前平台和官方说明核对。

附加目录会扩大会话边界：

```bash
claude --add-dir ../shared-lib
realpath ../shared-lib
find ../shared-lib -type f | sed -n '1,40p'
```

适合添加的是当前任务确实需要的一个库或文档目录，而不是整个 HOME、Downloads、云盘根目录或多个仓库的共同父目录。加入目录后，再用 `/permissions` 检查最终状态。

## 5. Hooks 可以增加项目闸门

PreToolUse Hook 能在工具执行前检查命令并阻止操作。下面的练习脚本拦截包含 `git push` 的 Bash 调用：

```bash
mkdir -p .claude/hooks
cat > .claude/hooks/block_git_push.py <<'PY'
#!/usr/bin/env python3
import json
import sys

try:
    payload = json.load(sys.stdin)
except json.JSONDecodeError as exc:
    print(f"invalid hook input: {exc}", file=sys.stderr)
    sys.exit(2)

if payload.get("tool_name") != "Bash":
    sys.exit(0)

command = payload.get("tool_input", {}).get("command", "")
if "git push" in command:
    print("Blocked: git push must be performed manually after diff review.", file=sys.stderr)
    sys.exit(2)

sys.exit(0)
PY
chmod +x .claude/hooks/block_git_push.py
```

在项目设置中注册：

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/block_git_push.py\""
          }
        ]
      }
    ]
  }
}
```

多数 Hook 事件中，退出码 `0` 表示继续，`2` 表示阻止并把 stderr 反馈给 Claude；其他非零值通常被视为非阻断错误。具体事件语义仍以当前文档为准。简单字符串匹配可能被复杂 Shell 写法绕过，因此这个例子适合展示机制，不是完整命令解析器。

Hook 本身也是项目代码。启用后应在练习分支测试一条允许命令和一条拒绝命令，确认目标命令是否真的执行，再决定是否共享到仓库。

## 6. 一次实际配置顺序

第一次为项目建立 Claude Code 权限时，可以依次完成：用 `/permissions` 记录当前状态；选择适合任务的 Permission Mode；只为确定的低风险命令添加 Allow；把需要人判断的操作留在 Ask；为明确禁止的文件和命令添加 Deny；需要时再启用 Sandbox、附加目录或 Hook。每改变一层，都新开会话验证最终行为。

权限章节只说明 Claude Code 如何配置。具体任务仍应通过真实文件、测试和 Git diff 验收；高影响命令的通用判断方法见[权限与安全边界总览](../Part-12-AI开发工作流/04-权限与安全边界总览.md)。
